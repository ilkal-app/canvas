# @canvas/schema

## Purpose

The board schema: the eleven object types of the document model with their Zod validators and inferred TypeScript types, the reference rules between objects (connector detach, cascading delete, dangling references), migrations between schema versions, and portable JSON export/import. Pure TypeScript with no DOM, no GPU, no React and no Yjs, so every other package and service can depend on it. `@canvas/document` validates every command against these schemas before it becomes a transaction; the MCP server can hand the same schemas to agents as JSON Schema (`z.toJSONSchema`), field descriptions included.

## Public API

- `TEMPLATES`, `TEMPLATE_CATEGORIES`, `Template`, `TemplateCategory`, `TemplateCategoryId`: The board templates' metadata, in the dialog's order: each one's kebab-case id, name, category, the mode of the boards it makes, the switch flags it `requires` (always `templates`); the 12 owner-approved whiteboard templates. The five categories with their display names.
- `templatesFor(features, list?)`, `searchTemplates(list, query)`, `templatesIn(list, category)`, `templateById(id, list?)`: The templates a person may use (every required flag on); those whose name or category name holds every word of a query, ignoring case and accents; those of a category (`all` for every one); one by id. Pure; `list` defaults to `TEMPLATES`.
- `LEARNING_TEMPLATE`, `seedableTemplateById(id)`: The learning board's template, "Learn the basics", outside `TEMPLATES` and gated by no flag, opened only from the home page's Get started checklist; and the lookup the relay seeds by, which finds it and every one of `TEMPLATES`.
- `templateDocument(id)`: A template's portable board document, for the relay's seed; the documents live apart from the metadata (`templates/documents/`), so the app, which never calls it, does not bundle them.
- `BOARD_MODES`, `BoardMode`: The six board modes, in order; the flags that gate them live in the private `@canvas/plans`.
- `componentObjectSchema`, `ComponentObject`, `instanceObjectSchema`, `InstanceObject`: Board-local definition containers and stored references with per-child overrides; a main may store a live `autoLayout`, an instance `isWidthFixed`/`isHeightFixed` (it keeps its own size on that axis though its main hugs), and a text's or sticky's override record a `measuredSize` with the font fingerprint it was measured with.
- `overridePathSchema`, `overrideRecordSchema`, `instanceOverridesSchema`, `OverrideRecord`, `InstanceOverrides`: Strict content/colour/text-style/image/visibility override records; `runs` only beside `text` and under the stored-text run rules; nested instance segments address source children, never stored virtual ids.
- `overrideFieldsSchema`, `instanceOverrideFieldsSchema`, `overrideRunsIssues`: An override record's fields without the `runs`/`text` pairing rule, and that rule as messages, so commands refuse a bad pairing as `invalid-override`.
- `textStyleOverrideSchema`, `TextStyleOverride`: An override record's `textStyle`: a strict partial text style, at least one field, laid over every run of the child's resolved text.
- `MAX_INSTANCES`, `MAX_INSTANCE_DEPTH`: 10,000 stored references per board and five expansion levels.
- `INSTANCE_SCALE_MIN`, `INSTANCE_SCALE_MAX`, `INSTANCE_SCALE_VERSION`: An instance's content `scale` bounds, 0.05 to 20, and the schema version that introduced it.
- `scaledObject(object, scale)`: An object drawn `scale` times larger about its parent's origin: position, size, points, stroke widths and dashes, radii, font sizes and absolute spacing, shadows, auto-layout gap and padding, and a nested instance's own scale, its override records kept in main units; the virtual copies of a scaled instance's content.
- `resolveInstanceChild`, `ResolvedInstanceChild`, `ShownInstanceChild`, `HiddenInstanceChild`: One leaf child's virtual copy in an instance, equal to its `resolveInstance` entry, for patching a scene after an edit; undefined (resolve the whole instance) under an auto-layout container.
- `autoLayoutTree(reader, container, records?)`, `LayoutReader`: The `layOutStack` tree of an auto-layout frame or main: box children in stacking order, nested auto-layout containers as sub-stacks; with an instance's records, a hidden child leaves the flow and an overridden text takes its `measuredSize`.
- `laidInstanceSize(reader, instance, main)`: The size an instance of an auto-layout main lays out to with its effective overrides, on the axes the main hugs and the instance has not fixed; on an axis its main's variants size, its variant's size; a scaled instance lays out in main units and draws the laid size `scale` times larger.
- `unscaledInstance(instance)`: An instance with its box divided by its content `scale`, in its main's units, as its content is laid out.
- `hasGeometry(record)`: Whether an override record moves or sizes its target or patches its layout (`x`, `y`, `width`, `height`, `autoLayout`), so a single-child read cannot place what it changes.
- `withRecordGeometry(board, main, content, records, children?)`, `DrawnMain`: A main and its content as override records draw them: the root record sizes the main and patches its layout, content without a record follows its constraints into that box, and each record moves and sizes its child.
- `variantSizedAxes(main)`, `VariantSizedAxes`: The axes some preset's root record of a main sizes, where an unfixed instance takes its variant's size and a resize fixes the axis.
- `definitionContent`: Ordinary definition descendants, without expanding nested instance references or including comments.
- `instanceReferenceProblems`, `InstanceReferenceIssue`, `InstanceReferenceProblem`: Missing/wrong mains, cycles and excessive depth with source chains for deterministic repair.
- `resolveInstance`, `ResolvedInstance`, `virtualObjectId`: Pure transient inherited content and geometry; virtual ids never enter the document or presence. Accepts an optional reusable `ChildIndex` for repeated resolution, and the overrides to resolve with (its effective ones by default).
- `instanceOverrideFields`: Lists each source type's supported override fields; `textStyle` and `runs` wherever `text` is.
- `variantAxisSchema`, `variantAxesSchema`, `variantNameSchema`, `variantSelectionSchema`, `VariantAxis`, `VariantSelection`, `MAX_VARIANT_AXES`, `MAX_VARIANT_VALUES`, `MAX_VARIANT_NAME`: A main's variant axes (the first value of each the default) and an instance's selection, with their limits.
- `presetKey`, `parsePresetKey`, `PresetKeyParts`, `selectedValues`: A preset's `axis=value` key both ways, and the value in force on each axis (a selection the axis no longer lists falls back to its default).
- `effectiveOverrides`, `effectiveOverridesOf`: An instance's selected presets composed in axis order with its own records on top, the records every resolver uses; a measured size a later layer's text made stale is dropped.
- `isMeasuredSizeCurrent`: Whether a record's measured size was measured with the bundled fonts in use ('s follower re-measures otherwise).
- `mergeOverrideRecords`: Lays one override record over another, field by field (`textStyle` and `variant` key by key, an outer `text` dropping inner `runs`).
- `effectiveSlotMain`: The main a nested instance (a slot) expands: its record's swapped-in `mainId` while that is a live main that makes no cycle and stays within depth, else its stored one.
- `slotSwapIssue`, `SlotSwapIssue`: Why a main cannot be swapped into a slot under given ancestor mains (missing, not a main, retired, cycle, depth), the rule `effectiveSlotMain` and the swap commands share.
- `namedSwapTargets`: The mains an instance's own records, or any variant preset of a main, name as swap targets, for strict write-time cycle checks.
- `slotExpansion`: A nested instance as its enclosing instance expands it: its record applied, its effective main, and the records that reach below it.
- `mainClosure`, `DefinitionReader`: Every id resolving instances of some mains may read: containers' descendants, stored mains and every main a record or preset names as a swap target, transitively; the closure the engine, the snapshot and the app share.
- `variantPresetIssues`: Why a main's preset keys don't fit its axes.
- `applyInstanceOverride`: A child with one override record's content fields applied (text, text style, runs, fill, stroke colour, note colour, image, a nested instance's `variant`), without mutating either; visibility is the resolver's. The app previews a main's preset with it.
- `editableOverrideFields`: `instanceOverrideFields` without the fields a writer derives (`measuredSize`) or that their own controls set (a nested `variant`, or `mainId`): what the inspector and the board projection offer as rows.
- `mapInsideObject`, `mapPoint`, `mapVector`, `AffineMap`: Pure affine geometry used by group resizing and constraint resolution.
- `planGroupResize`, `BoxSize`, `GroupResize`, `GroupResizePlan`, `ObjectTreeReader`: Shared proportional group geometry, kept here so renderer and document constraints agree.

- `CONSTRAINT_MODES`, `constraintsSchema`, `ConstraintMode`, `Constraints`, `DEFAULT_CONSTRAINTS`, `effectiveConstraints`: optional child pin/stretch constraints, defaulting to start/start without rewriting older objects.
- `autoLayoutSchema`, `AutoLayout`, `AUTO_LAYOUT_DIRECTIONS`, `AUTO_LAYOUT_ALIGNS`, `AUTO_LAYOUT_JUSTIFIES`, `AUTO_LAYOUT_SIZINGS`: a frame's or main's optional live auto-layout: direction, gap (negative overlaps the children), per-side padding, cross-axis align, main-axis justify, and hug or fixed per axis.
- `DEFAULT_AUTO_LAYOUT`: the auto-layout a container takes when one is added: a row hugging both axes, no gap or padding, at the start.
- `layoutChildSchema`, `LayoutChild`: how an object sits in an auto-layout container, `{ fill }`; only box objects (text, sticky, image, video, shape, frame, component, instance) store it, in their `size` group.
- `layOutStack(root)`, `stackLayoutOf(autoLayout)`, `StackLayout`, `StackNode`, `StackPlacement`, `StackDirection`, `StackAlign`, `StackJustify`, `StackPadding`: the pure stack layout (moved from `@canvas/mcp`,/): rows or columns, gap (negative overlaps, the content never below 0, ignored when spread with space-between in a container of its own size), padding, align, justify, fill, hug, hidden children left out; and the stack layout of a stored auto-layout.
- `constrainChildren`: pure constraint layout of a sized container's descendants, preserving styles and image fitting; accepts an optional reusable `ChildIndex`.
- `AffineMap`, `mapPoint`, `mapVector`, `mapInsideObject`: pure affine geometry used by the existing group resize and constrained child layout.
- `planGroupResize`, `ObjectTreeReader`, `BoxSize`, `GroupResize`, `GroupResizePlan`: shared proportional group geometry; the document package keeps its existing exports.

Every `…Schema` is a Zod schema; the type of the same name without the suffix is inferred from it (`z.output`). Objects are strict: unknown keys fail validation.

**Ids and versions**

- `SCHEMA_VERSION`: The schema version this build reads and writes.
- `AUTO_LAYOUT_SCHEMA_VERSION`: The schema version that introduced live auto-layout.
- `OBJECT_NAME_VERSION`: The schema version that introduced a layer `name` on every object.
- `VARIANTS_SCHEMA_VERSION`: The schema version that introduced component variants.
- `SWAP_SCHEMA_VERSION`: The schema version that introduced instance swap.
- `isSupportedSchemaVersion(version)`: Whether a document written with `version` can be loaded (1 up to `SCHEMA_VERSION`).
- `objectIdSchema`, `ObjectId`: Opaque object id, 1–64 of `[A-Za-z0-9_-]`, branded.
- `pageIdSchema`, `PageId`, `isPageIdText(value)`: Opaque page id, the object id pattern, branded; whether a value is a string that pattern takes.
- `assetIdSchema`, `AssetId`: Opaque id of an asset in object storage, branded.
- `principalIdSchema`, `PrincipalId`: Who created an object: `user:<id>`, `agent:<id>` or `system`, branded.
- `createSeededIdGenerator(seed)`: Deterministic object id generator for tests and fixtures (no entropy, no crypto).

**Field types**

- `rgbaSchema`, `Rgba`: Colour `[r, g, b, a]`, each channel in [0, 1].
- `BOARD_BOUND`: The board's bound: 2^30 (1,073,741,824) world units, on where objects are on the board.
- `angleSchema`: An angle in radians within ±`BOARD_BOUND`: the limit a new object's rotation has on every way in.
- `finiteCoordinate(v)`: A computed coordinate made storable: a finite value stays, past the bound too; an infinity becomes the largest finite number, NaN 0.
- `pointSchema`, `Point`: A point `{ x, y }` in world units, finite (what an object stores).
- `unitPointSchema`, `UnitPoint`: A point in the unit square, as fractions of a box.
- `strokeSchema`, `Stroke`, `MAX_STROKE_WIDTH`: Stroke colour and width in world px, `0 < width <= 64`.
- `strokeStyleFields`, `StrokeStyle`: The stroke style of a path, line or connector, siblings of `stroke` in its style group, each optional (absent draws as before): `strokeDash`, `strokeJoin`, `strokeMiterLimit`, `strokeCap`.
- `strokeDashSchema`, `strokeDashPatternSchema`, `StrokeDash`, `MAX_STROKE_DASH_ENTRIES`, `MAX_STROKE_DASH_LENGTH`, `MAX_STROKE_DASH_OFFSET`: A dash pattern `{ pattern, offset? }`: 1 to 8 lengths in [0, 4096] world px, not all 0 (an odd count repeats, as SVG), and an offset within ±32768; `null` is solid.
- `strokeJoinSchema`, `StrokeJoin`, `STROKE_JOINS`, `strokeMiterLimitSchema`, `DEFAULT_STROKE_MITER_LIMIT`, `MAX_STROKE_MITER_LIMIT`: A join (`miter`, `round`, `bevel`) and the miter limit, 1 to 100, default 4.
- `strokeCapSchema`, `StrokeCap`, `STROKE_CAPS`: How open ends and dashes end (`butt`, `round`, `square`); on a line or connector, only at an end with no decoration.
- `strokeStyleReason(style)`: The door's judgement of a style group's stroke style as a peer wrote it: the first refused field (`strokeDash.pattern.2`, `strokeJoin`). `drawableValuesReason('style', …)` applies it.
- `strokeAlignSchema`, `StrokeAlign`, `STROKE_ALIGNS`, `DEFAULT_STROKE_ALIGN`, `strokeAlignFieldSchema`, `frameStrokeFieldSchema`, `strokeOutsideFraction(align)`, `strokeOutsetOf(stroke, align)`: Where a shape's or frame's outline lies about its edge: `'inside'` (absent, the default), `'center'` or `'outside'`; the shape and frame field; a frame's outline (`null` or absent: none; its colour may be `ink`); the fraction of the width outside the edge (0, 0.5, 1; anything else reads as inside) and how far, world px, an outline reaches outside it.
- `frameCornerRadiusSchema`, `FrameCornerRadius`, `CornerRadii`, `frameCornerRadii(value)`: A frame's corner rounding: one radius or four, `[topLeft, topRight, bottomRight, bottomLeft]` (Figma's order), each at least 0 (absent on a frame: sharp); a stored value as four radii (absent or refused: sharp), not capped (the engine caps each at half the shorter side).
- `opacitySchema`, `layerShape`, `LAYER_OPACITY_TYPES`, `layerOpacityOf(value)`: An opacity from 0 to 1 (an image's required field); the optional layer `opacity` field text, stickies, shapes, lines, connectors, paths, groups, frames, mains and instances spread into their schema (absent is opaque; comments and videos take none), the types that store it, and a stored value as the opacity to draw (absent or refused: 1).
- `visibilityShape`, `LAYER_VISIBILITY_TYPES`, `isStoredHidden(object)`, `withoutStoredHidden(object)`: The optional layer `isHidden` field every type but a comment spreads into its schema (absent is shown; hidden, a layer and its subtree is not drawn, not hit and takes no space in an auto-layout, and an instance record overrides it either way), the types that store it, whether a stored object is hidden (only a stored `true`), and an object without the field.
- `shadowSchema`, `Shadow`, `shadowFieldSchema`, `DEFAULT_SHADOW`, `MAX_SHADOW_OFFSET`, `MAX_SHADOW_BLUR`, `MAX_SHADOW_SPREAD`: A drop shadow: `{ x, y, blur, spread, color }` in world px (offset ±1000, blur 0–500 as Figma's radius, spread ±500), colour a tuple, never `ink`; the shape and frame field (`null` or absent: none, or a list of layers) and the inspector's default (0, 4, blur 4, black 25%).
- `shadowLayersSchema`, `ShadowValue`, `MAX_SHADOW_LAYERS`, `shadowLayersOf(shadow)`: A list of 1 to 8 drop shadows drawn in order, the first lowest; a shadow field read as its layers (none, one, or the list).
- `INK`, `inkableColorSchema`, `InkableColor`: The theme-aware colour token `'ink'` and a colour that may be it or a token reference: a stroke's or text style's colour.
- `colorSchema`, `Color`: A colour that may name a board token but never `'ink'`: a sticky's colour, an override's `fill`, `strokeColor` and `color`.
- `tokenRefSchema`, `TokenRef`, `isTokenRef(value)`, `tokenIdSchema`, `TokenId`: A board colour token reference, exactly `{ token: id }` with no `type` key, and its id: a built-in name or a custom id.
- `BUILTIN_TOKENS`, `BuiltinTokenId`, `BUILTIN_TOKEN_DEFAULTS`, `TokenValues`, `isBuiltinToken(id)`: The six built-in tokens (`ink`, `text`, `muted`, `surface`, `border`, `accent`) and their light and dark defaults (ink = `INK_COLORS`, the others the Vellum and Graphite theme tokens).
- `tokenEntrySchema`, `TokenEntry`, `TokenTable`, `tokenNameSchema`, `MAX_CUSTOM_TOKENS`, `MAX_TOKEN_NAME_LENGTH`, `tokenValuesOf(id, table?)`: A board's token table entry (custom or edited built-in), the table by id, names of 1 to 40 characters, 64 custom tokens, and a token's values on a board.
- `ColorMode`, `COLOR_MODES`, `colorModeSchema`: A colour mode, `'light'` or `'dark'`, and a frame's, main's or instance's optional `colorMode`.
- `resolveColor(value, mode, table?)`: A stored colour in one mode: a tuple as is, `'ink'` or a token the board's value (table, else built-in default), an unknown token the ink value; never throws.
- `INK_COLORS`, `InkTheme`, `resolveInk(color, theme, inkColors?)`, `isInk(color)`: What ink draws as per theme (the `ink/primary` tokens: Vellum `#1E1F1C` light, Graphite `#ECEBE5` dark), and resolving a colour for one viewer with the built-in token defaults.
- `isSameColor(first, second)`: Whether two stored colours are the same: both `ink`, references to one token, or equal channels.
- `paintSchema`, `Paint`, `gradientSchema`, `Gradient`, `ColorOrGradient`: A fill: a solid `Rgba` tuple, a token reference, a linear or radial gradient object, or an image paint (a path's fill refuses it); `ColorOrGradient` is a drawn paint that is not an image.
- `imagePaintSchema`, `ImagePaint`, `imageFitSchema`, `ImageFit`, `isImagePaint(paint)`: An image laid into a shape's or frame's box: `{ type: 'image', assetId, naturalSize, fit: fill | fit | crop | tile, crop }`, and its discriminant.
- `ResolvedPaint`, `resolvePaint(paint, mode, table?)`: A paint as drawn (a tuple, a gradient or an image), and a stored paint with its token resolved.
- `linearGradientSchema`, `LinearGradient`, `radialGradientSchema`, `RadialGradient`: A gradient by angle in radians in (−π, π], or by centre in the unit box and radius in (0, 2].
- `gradientStopSchema`, `GradientStop`, `gradientStopsSchema`, `MIN_GRADIENT_STOPS`, `MAX_GRADIENT_STOPS`, `MAX_RADIAL_RADIUS`: 2 to 8 stops, offsets in [0, 1] and non-decreasing; the radius limit.
- `paintColorAt(paint, u, v)`, `gradientPositionAt(gradient, u, v)`: A paint's straight-alpha colour at a unit-box point, interpolated in premultiplied sRGB; where the point lies along a gradient.
- `paintBoxOf(object)`, `paintUnitPoint(box, point)`, `UnitBoxPoint`, `PaintedObject`, `pathBounds(path)`: The box a paint is evaluated in (a shape's or frame's box, a path's network bounds) and a local point's unit-box coordinates; an axis of zero extent maps to 0.5.
- `paintAverageColor(paint)`, `isGradient(paint)`, `isPaintVisible(paint)`, `isPaintOpaque(paint)`: The average colour (level of detail; `null` for an image paint); whether a paint is a gradient (`type` linear or radial), paints anything (a token or an image paint does), or is opaque everywhere (a token is not until resolved, an image paint never is).
- `effectiveColorMode(object, board, options?)`, `ColorModeBoard`, `ColorModeOptions`, `ColorModeFallback`: The mode an object draws tokens in: the nearest frame, main or instance with a `colorMode` (virtual content walks through its instance; an instance without one takes its main's), else the `fallbackMode` hook, else the `viewerTheme` (an option, or the third argument alone).
- `frameFillColorMode(object, board, options)`, `frameFillFallback(options)`, `frameFillModeOf(fills, options)`, `FrameFillMode`, `FrameFillModeOptions`, `backdropFillOf(object)`, `FRAME_FILL_DARK_LUMINANCE`, `FRAME_FILL_MIN_ALPHA`: The frame-fill rule, the `fallbackMode` the app and the snapshot service use: the nearest ancestor frame whose fill is at least half opaque decides, `dark` when its WCAG luminance is below about 0.186 (where both inks contrast equally), judged top-down (a token fill in the mode the frames above give, the `ink` token in the viewer's `inkColors` unless the board edited it, a gradient by its span-weighted mean, a translucent fill composited over the deciding fill above it, an image fill skipped); as a hook for one viewer and token table; over a list of ancestor fills, with the tokens and theme it read; a frame's fill (none for other objects).
- `containerTextMode(object, fillMode, options)`, `containerFillOf(object)`: The container-text rule: a sticky's or filled shape's theme-default text (`ink`, tokens) draws dark on a light fill and light on a dark one, by the frame-fill threshold, whatever the theme or an ancestor's `colorMode`; the fill a container shows behind its own text.
- `drawnColorModes(object, board, options)`, `DrawnColorModes`: The modes an object draws in for one viewer: its fill's (`effectiveColorMode` with the frame-fill fallback) and its own text's (the container-text rule), which a vector export, the clipboard and the caret read.
- `fontFamilyUsesOf(object)`, `FontFamilyUse`, `boardFontFamilies(board)`, `BoardFontFamily`: Where an object names font families (runs, labels, instance overrides, a main's variant presets) and every family a board names with the objects and text styles naming it.
- `colorTokenUsesOf(object)`, `ColorTokenUse`, `hasColorToken(board, id)`, `unknownColorTokenIssues(board, object)`: Where an object names tokens, whether a board has one, and the `unknown-color-token` notices of an object.
- `styleIdSchema`, `StyleId`, `styleNameSchema`, `MAX_STYLE_NAME_LENGTH`, `styleNameKey(name)`, `effectStyleIdFieldSchema`: A named style's id (the object id pattern), its name (1 to 40 characters, no space at either end, `/` groups; compared trimmed and case-blind) and a shape's or frame's `effectStyleId` field.
- `textStyleValueSchema`, `TextStyleValue`, `TEXT_STYLE_VALUE_FIELDS`, `effectStyleValueSchema`, `EffectStyleValue`: A text style's value (a run's typography without its colour) and an effect style's (`{ shadows }`, 1 to 8 layers).
- `textStyleEntrySchema`, `TextStyleEntry`, `TextStyleTable`, `effectStyleEntrySchema`, `EffectStyleEntry`, `EffectStyleTable`, `MAX_TEXT_STYLES`, `MAX_EFFECT_STYLES`: A board's named style tables: `{ id, name, value, createdBy, createdAt }` by id, at most 64 of each kind.
- `textStyleUsesOf(object)`, `effectStyleUseOf(object)`, `StyleUse`, `unknownStyleIssues(board, object)`: Where an object names a style (each run's `textStyleId`, a shape's or frame's `effectStyleId`), and the `unknown-text-style` and `unknown-effect-style` notices of an object.
- `lineCapSchema`, `LineCap`, `LINE_CAPS`: End decoration of a line or connector.
- `textStyleSchema`, `TextStyle`: Font family, size (world px), colour, weight (100–900), italic, and optional `letterSpacing` and `lineHeight` and `fontVariations` and `lang`.
- `fontVariationsSchema`, `FontVariations`, `MAX_FONT_VARIATION_AXES`, `isSameFontVariations`: A run's variable-font axis coordinates by four-character tag, at most 16 axes; absent and empty are the font's defaults.
- `fontVariationAxesSchema`, `FontVariationAxes`, `mergeFontVariations(current, axes)`: A change to some axes of a run's coordinates (a value per tag, `null` removes it) and its merge into a run's own, the other axes kept.
- `languageTagSchema`: A BCP 47 language tag, at most 35 characters.
- `fontFeaturesSchema`, `FontFeatures`, `MAX_FONT_FEATURES`, `isSameFontFeatures`: A run's OpenType features by four-character tag (`0` off, `1` on, above `1` an alternate), at most 32; absent and empty are the shaper's defaults.
- `postScriptNameSchema`, `PostScriptName`: A face's PostScript name, 1 to 63 printable ASCII characters without `[ ] () { } < > / %` (OpenType name ID 6), naming a run's face beyond weight and slant.
- `withPostScriptName`: A style with its face name set, or removed for `undefined`.
- `restyledFace`: The face name a style keeps after a restyle: a patch's own name wins, a move to another family without one drops the old face, else it is kept.
- `letterSpacingSchema`, `LetterSpacing`, `LETTER_SPACING_LIMITS`, `lineHeightSchema`, `LineHeight`, `MAX_LINE_HEIGHT`, `PerUnit`, `ValueRange`: A run's letter-spacing (`{ value, unit: 'px' | 'percent' }`, percent of the font size, trimmed at line ends) and line-height (`'auto'` or `{ value, unit }`; a line is as tall as its tallest run), with their ranges.
- `MIN_FONT_SIZE`, `MAX_FONT_SIZE`: The font size range, 4 to 400 world px.
- `styleRunSchema`, `StyleRun`: A run of `length` UTF-16 code units in one style.
- `isSameTextStyle(first, second)`: Field-by-field style equality; a letter-spacing of 0 and a line-height of `'auto'` equal none.
- `textContentSchema`, `TextContent`: Text plus the runs covering it, under the run invariant, and optionally each paragraph's list style.
- `paragraphStyleSchema`, `ParagraphStyle`, `MAX_LIST_LEVEL`, `paragraphCount`, `isSameParagraphStyle`: A paragraph's list style (bullet or numbered, level 0 to 3, or plain), the deepest level, a text's paragraph count and style equality.
- `findRunIssues(text, runs)`: The ways runs break the run invariant, as messages.
- `findRunsSplittingCharacters(text, runs)`: The indexes of runs that start inside a surrogate pair.
- `isCharacterBoundary(text, index)`: Whether a UTF-16 position is not inside a surrogate pair.

**Drawable ranges**

The ranges a renderer draws numbers within: one statement, read by the engine's reader of stored objects (`ownUndrawableReason`, `undrawableReasonOf` in `@canvas/engine`) and by the relay's door check of incoming values (`UpdateStampCheck` in `@canvas/document`), so the two never disagree. Each `…Reason` returns why a number is out of its range, or `undefined`. Pure.

- `DRAWABLE_EXTENT`: How far from the origin a drawn object's geometry may lie on the board: 2^31 world units per axis (twice `BOARD_BOUND`).
- `MAX_DRAWABLE_SIZE`: The widest width, height, corner radius or natural size a drawn object holds: 2^32.
- `FLOAT32_MAX`: The largest finite float32 (about 3.4e38): past it a GPU buffer holds a number as infinite.
- `UndrawableReason`: `not-finite`, `negative-size`, `past-extent`, `out-of-range` or `undrawable-parent`.
- `coordinateReason(v)`: A coordinate (a placement, a line end, a vertex, a handle) finite; its place on the board is judged with its parents (`DRAWABLE_EXTENT`), not from the value alone.
- `scalarReason(v)`, `pointReason(p)`: A number with no narrower range (a rotation, a weight, a free end), or a point's two: finite and within ±`FLOAT32_MAX`.
- `sizeReason(v)`, `naturalSizeReason(v)`, `fontSizeReason(v)`: A size in [0, `MAX_DRAWABLE_SIZE`]; a natural size a whole number from 1 to `MAX_DRAWABLE_SIZE`; a font size from 4 to 400.
- `unitReason(v)`, `cropExtentReason(v)`, `cropReason(crop)`: A fraction in [0, 1]; a crop's width or height in (0, 1]; a crop with both, and its right and bottom edges within the image (`cropSchema`'s slack).
- `colorReason(c)`, `strokeReason(s)`, `sidesReason(n)`, `capReason(c)`: Colour channels in [0, 1]; a stroke's colour and width from 0 to 64; sides a whole number from 3 to 64; a cap of `LINE_CAPS`.
- `FONT_WEIGHTS`, `FontWeight`, `fontWeightSchema`, `isFontWeight(value)`: The nine weights a run may ask for, 100 to 900 in steps of 100; a family draws one it lacks with its nearest face.
- `fontWeightReason(w)`: A run's weight one of `FONT_WEIGHTS`.
- `letterSpacingReason(s)`, `lineHeightReason(h)`: A run's letter-spacing and line-height within `LETTER_SPACING_LIMITS` and `MAX_LINE_HEIGHT`.
- `textRunsReason(content)`: At least one run, each with a drawable style, whole lengths covering the text.
- `instanceScaleReason(v)`: An instance's content scale finite and from `INSTANCE_SCALE_MIN` to `INSTANCE_SCALE_MAX`.
- `drawableValuesReason(kind, value, stored?)`, `DrawableValueKind`, `DrawableValueFinding`, `DrawableValueReason`, `StoredValueReader`, `StoredValue`: The door check of one stored value (a placement's `pageId` too: absent, `null` or an id, else `not-an-id`) as a peer sent it: a placement, a size, a style group (an image's crop and natural size, a fill, background or stroke, a frame's `showName`: absent or a boolean, else `not-a-boolean`, a stroke style, and an `opacity` in [0, 1]), a line end or pair, a vertex or a segment's handles, or a freehand stroke's flat points or pressures (`stroke-points`, `stroke-pressures`); the first field out of range, a judged field that is not a number (`not-a-number`), or a value or group that is not a record (`not-a-record`). Given the value the board holds there (`stored`, read once, only when a field would be refused), a field written as it is held is not judged.
- `paintReason(value)`, `strokeValueReason(value)`, `PaintValueFinding`, `PaintValueReason`: The door's judgement of a fill or background and of a stroke as a peer wrote them: the first refused field (`stops.3.offset`, `color`). `drawableValuesReason('style', …)` applies them to a style group.
- `strokeAlignValueReason(value)`: The door's judgement of a shape's or frame's stroke alignment as a peer wrote it: absent or one of `STROKE_ALIGNS`, else `out-of-range`; `drawableValuesReason('style', …)` applies it, and judges a frame's `stroke` as any stroke (`strokeValueReason`).
- `shadowValueReason(value)`: The door's judgement of a shape's or frame's drop shadow as a peer wrote it: absent, null, or a strict `{ x, y, blur, spread, color }` within its ranges, colour a tuple; `drawableValuesReason('style', …)` applies it too.
- `isSameValue(first, second)`: The door's equality rule: equal primitives (NaN equal to NaN), or arrays and records of the same values under the same keys. A field written as the board holds it is not judged at the door, and the command layer judges only the fields a write changes by the same test.

## Design notes

- **Drawable ranges.** `drawable/` states once the ranges a renderer draws numbers within, so the engine's reader (part 2) and the relay's door check (part 1) read the same predicate. A coordinate is held to finite only, by both: it is an offset in its parent's or its object's frame, and the board's bound is on where objects land, not on what they store (above). The engine sees a whole object with its parents and judges its place against ±`DRAWABLE_EXTENT`; the relay sees one value at a time and cannot. Bounding stored coordinates at the door would refuse what commands honestly store: a child of a frame turned 45° at one corner of the board, placed at the opposite corner, stores 2√2 × 2^30, and a child moved inside the bound out of a parent a peer left far stores about the parent's distance (`placement-bound.test.ts` in `@canvas/document`). An empty group moved by 1e308 stored 1e308 until bounded every placement a command writes (the sync fuzz's hostile-coordinates run found it); the door still takes such a raw value. Every other number the door judges is held to the reader's own range: sizes to [0, 2^32], a rotation to float32, a crop to the unit square and within the image, a natural size to the whole numbers 1 to 2^32. The whole image behind a crop is not judged at the door: it needs the box, stored apart from the crop. A field the board already holds as written is not judged (`stored-value-match.ts`, fix round 1): lets a value past its limit stay, and a command that rewrites a group whole (a move rewrites `placement`) carries it; judging only what a write changes keeps the door from refusing that honest rewrite, and a rewrite of what is already there never makes the board worse.
- **Frames of reference.** An object's `x`, `y`, `rotation` place it in its parent's frame (the board for `parentId: null`, else a group or frame). Its own frame is the parent's translated by (`x`, `y`) and then rotated by `rotation` radians about that point (clockwise on a y-down screen). Points stored inside an object (line points, path vertices, free connector ends) are in the object's own frame. There is no scale.
- **The board bound.** `BOARD_BOUND` = B = 2^30 = 1,073,741,824 world units. Why this number: float64 arithmetic on it is exact (a sum of a few coordinates is an integer below 2^53, and a coordinate at the bound keeps 22 fraction bits, so a quarter of a world unit survives), and everything a renderer forms from it is finite in float32 (its largest value is about 3.4e38): a corner at zoom 64 is 2^36, the squared distance between two opposite corners is 2^63. `fields/board-bound.test.ts` shows both at the bound. Without a bound `1e308` is a finite `x`, but `x + width` and the length between two far ends overflow to `Infinity` and poison bounds, the spatial index and the GPU buffers; NaN and the infinities already fail `z.number()`. **The bound is on where objects are on the board**: every object a command changes or carries keeps each extent of its axis-aligned box on the board (`geometryBoxOf` through `boardTransformOf`) within max(B, what it was), so an extent inside may go anywhere inside and one past it may stay or come in; the command layer judges it (`@canvas/document`, `worldBoundViolations`). **What an object stores is not bounded**, only finite: a member of a group of two frames at -B and +B stores 2B and lies inside the bound, so the object schemas hold no bound. Values that are not positions have limits of their own, the same on every way in (`findValueLimitIssues`: a rotation, a corner radius, a natural size, the whole image behind a crop, a comment pin's offset; `angleSchema` for a new object's rotation). `importBoard` refuses a document with an object whose box on the board, resolved through the parents that come with it, is past the bound, a value past its limit, or a number that is not finite (a `1e400` literal), each an `out-of-bound` issue; the same values load from a Yjs document (see `@canvas/document`). Values derived from stored data are stored as computed: `finiteCoordinate` clamps only what is not finite (a detached connector end or comment pin is worked out where the object was, past the bound when the object was).
- **Z-order** is the `z` fractional-index key, compared by UTF-16 code units (`src/z-order/`). The rule is's, from `@canvas/document` (whose README has the scheme, David Greenspan's fractional indexing, and the growth bound behind the 512-character cap): base-62 characters, a head letter stating the integer part's length, a fraction not ending in `0`, not the smallest integer alone. The object schema validates every `z` by it (`zKeySchema`), so `importBoard` rejects an invalid key with `invalid-z-key` and the document store refuses a local write that sets one. Remote updates are not validated, so a peer that skips validation can still leave an invalid key on a board; the store therefore checks `z` only when a write changes it, and a write that keeps a stored invalid key (a move, a detach, an undo's repair) goes through. Siblings stack by `z`, ties by id (`compareSiblings`). Both live here, not in the document package, because the engine may import only this package and must draw in the document's order; generating keys stays in `@canvas/document`. Tightening `z` changed no stored shape, so there is no migration: every key the command layer writes already met the rule.
- **Keep sibling order incrementally; do not re-sort.** `compareSiblings` is cheap per call, but sorting 50k siblings with it takes 27 ms (the document's `sortedSiblings` bench), more than two frame budgets. A consumer that needs a parent's children in order keeps them sorted and applies each change set's few created, moved and deleted children by binary search with `compareSiblings` (O(log n) each), as the document's `topChildOf` keeps each parent's top child from change sets. The engine's z-order segments rebuild the paint order only when a change set touches a `z`, a parent or the set of objects (`ZOrderMirror`), and since they keep each parent's children sorted that way (`SiblingLists`), so a reorder walks sorted lists instead of re-sorting (1.2 ms against 7.8 ms for one of 50k root siblings, engine README).
- **Text** is the prototype's `text` + `runs` model (`webgl-whiteboard/src/text/runs.ts`): run lengths are UTF-16 code units, sum to the text length, adjacent runs differ, only empty text has its single zero-length run, and every run boundary falls between characters.
- **Run boundaries fall between code points, not grapheme clusters.** A run may not start inside a surrogate pair: Yjs `Y.Text` stores each formatted stretch as its own string and encodes a lone surrogate as U+FFFD, so such a run would leave the writer with the character and every peer with two replacement characters, never converging. `findRunIssues` reports it, and the Zod refinement of text, sticky and label runs puts it on the run's own path (`['runs', index]`) with `params.boardIssueCode` `'run-splits-character'`, which `importBoard` reports it under instead of `invalid-object`. The unit is the code point, which is what Yjs indexes count as whole characters, and not the grapheme cluster (an emoji ZWJ sequence such as U+1F469 U+200D U+1F4BB, a flag, a letter with combining marks). Restyling part of a grapheme looks odd but is harmless: every peer stores the same code points and converges. Checking grapheme boundaries would need `Intl.Segmenter`, which costs a segmentation pass over every text on every validation (a 50k-object board validates on load and every command validates what it writes), and whose answers depend on the runtime's Unicode tables, so two peers, or a peer and the relay, could disagree on whether the same board is valid. If graphemes became the unit (for example to keep a caret or a restyle from splitting a ZWJ sequence), the rule would move to the editing layer that places boundaries, with segmentation pinned to one Unicode version; the stored format, `length` in UTF-16 code units, would not change, and a schema check, if still wanted, would be a new `SCHEMA_VERSION` with a migration that moves existing boundaries out of clusters.
- **Asset records are not board content.** `AssetRecord` lives in the assets service's Postgres and travels over its HTTP API; the document stores only an image's `assetId` and `naturalSize`. It is here so the service and the client's texture manager validate one shape. Its level URLs are signed and short-lived, so a client refetches the record (`GET /assets/:id`) rather than caching them. `naturalSize`, `blurhash` and `averageColor` are null until the service has read the image, which is why they are nullable.
- **Paths** are the prototype's vector network (`webgl-whiteboard/src/vector/model.ts`): vertices with a `mirror` mode, segments that own their handle offsets.
- **Rules are pure functions over a `Board` value** and never mutate their inputs. They leave `updatedAt` alone (no clock); `@canvas/document` stamps it and applies a `cascadeDelete` result as one transaction, so one undo restores everything.
- **Stored field names** follow the prototype (`locked`, `autoWidth`, `clip`, `loop`, `muted`, `italic`), not the `is…` predicate style of code identifiers, since they are a data format shared with agents and files.
- **Migrations** operate on plain JSON of any version. To change the stored shape: increment `SCHEMA_VERSION`, add the step that produces it to `MIGRATIONS`, and test it on a fixture of the previous version; a test fails if a version has no step. Version 3: a version 2 board is one page, so its step adds `pages: [{ id: 'page-1', name: 'Page 1', order: 'a0' }]` and `pageId: 'page-1'` to every root object (`null` to every child). Version 5: an override record may hold `textStyle` and `runs`; a version 4 reader's strict record would refuse them, so portable JSON names the version, and the step is the identity. Version 6: a frame may store `showName`; the step is the identity, since a frame without it keeps the default (`isFrameNameShown`: hidden inside a frame or component, shown otherwise), and no stored frame is rewritten. Version 8: a text style's weight may be any of the nine CSS weights; the step is the identity. Version 9: a fill or background may be an image paint; the step is the identity. Versions 10 (auto-layout), 12 (variants) and 13 (instance swap) add optional fields with identity steps. Version 11: a colour may name a board token `{ token }`, a frame, main or instance may set `colorMode`, and a portable board may carry `tokens`; the step is the identity. The stroke style version (`STROKE_STYLE_VERSION`): a path, line or connector may store `strokeDash`, `strokeJoin`, `strokeMiterLimit` and `strokeCap` beside its stroke (not inside it: `strokeSchema` keeps its shape; `@canvas/document` gates the new style fields with stored layout 12); the step is the identity, since an object without them draws as before. The drop shadow version (`DROP_SHADOW_VERSION`): a shape or frame may store `shadow`; the step is the identity, since absent means no shadow. The stroke alignment version (`STROKE_ALIGN_VERSION`): a shape or frame may store `strokeAlign`, and a frame a `stroke` (`@canvas/document` gates them with stored layout 13); the step is the identity, since absent means an outline inside the edge and a frame without a stroke draws none. The preset geometry version (`PRESET_GEOMETRY_SCHEMA_VERSION`): an override record may carry a child's `x`, `y`, `width` and `height` (a group or path `x` and `y` only), an auto-layout container's `autoLayout` patch, and at the main's own id a variant's size (`@canvas/document` gates them with stored layout 14); the step is the identity, since a record without them changes no geometry. The object name version (`OBJECT_NAME_VERSION`): any object may store a layer `name` (`@canvas/document` gates it with stored layout 15); the step is the identity, since an object without one is unnamed. The named styles version (`NAMED_STYLES_VERSION`): a portable board may carry `textStyles` and `effectStyles`, a run may name a text style (`textStyleId`), a shape or frame an effect style (`effectStyleId`), and a shadow may be a list of layers (`@canvas/document` gates them with stored layout 16); the step is the identity, since an older value names no style and has one shadow at most. The frame radius version (`FRAME_RADIUS_VERSION`): a frame may store `cornerRadius`, one radius or four (`@canvas/document` gates it with stored layout 17); the step is the identity, since absent means sharp corners. The negative gap version (`NEGATIVE_GAP_VERSION` in `version/schema-version.ts`): an auto-layout's `gap` may be negative, overlapping its children (`@canvas/document` gates it with stored layout 18); the step is the identity, since every earlier gap is zero or more. The instance scale version (`INSTANCE_SCALE_VERSION`): an instance may store a content `scale`, 0.05 to 20 (`@canvas/document` gates it with stored layout 19); the step is the identity, since an instance without one draws its content at its main's size.
- **Pages.** A board has ordered pages; a root object names its page in `pageId`, an object in a group or frame has `pageId: null` and is on its root ancestor's page, so every object is on exactly one page and a frame carries its subtree. `pageId` is optional: an object without it (stored or built before pages) is on the default page. `validateBoard` reports a root object on a page the board lacks (`missing-page`), a child naming a page (`invalid-page`), a connector end or comment anchor on another page (`cross-page`), and more than `MAX_PAGES` live pages as a notice (`page-count`, `severity: 'notice'`): the limit is one on creation, which concurrent adds can pass, and `importBoard` keeps such a board.
- Every schema key carries both a TSDoc comment (for TypeScript and TypeDoc) and a `.describe()` string (for the JSON Schema agents read); keep the two in step.

### Atomic relay envelopes

`AtomicHeader`, `AtomicFrame`, `encodeAtomicFrame`, `decodeAtomicFrame` and `isAtomicFrame`
define the version-one binary transport shared by relay and client. The CAB family prefix
reserves unsupported versions for explicit refusal rather than legacy fallback. Strict JSON
metadata is limited to 4 KiB; raw parts use `MAX_ATOMIC_PART_BYTES` so the complete frame fits
within 8 MiB. Cursor/epoch fields are canonical decimal strings. Client batch headers contain
no authority identity; only the authenticated server supplies principal/session/epoch.

**Atomic relay framing**

`atomicHeaderSchema` and `AtomicHeader` describe strict version-one capability, staging, commit,
receipt and refusal metadata. `encodeAtomicFrame`/`decodeAtomicFrame` copy bounded payload bytes;
`isAtomicFrame` routes every reserved CAB prefix, including unsupported versions, to refusal
instead of legacy decoding. `MAX_ATOMIC_PART_BYTES` leaves framing headroom under the relay frame
limit. A `part-staged` message confirms buffered bytes only; a durable `receipt` follows canonical
publication. Epochs and commit cursors are decimal strings on the wire.

- **SVG import.** `svg/` turns untrusted SVG markup into `path` and `shape` objects in a group's frame, for the MCP server's `create_objects` and later the app's paste. It reads the markup as data with its own small XML reader (no DOM, no DTD, no entity but the predefined five, nothing fetched or run) and caps everything it walks (`SVG_IMPORT_LIMITS`). Path data takes the full grammar (arcs become quarter-turn cubics); transforms and the `viewBox` are applied exactly, since a cubic stays a cubic under an affine map. A shape is used only where it draws the element exactly: it keeps the element's box and centres its outline on the edge (`strokeAlign: 'center'`; before, the box grew by half the stroke for an inside outline), and only opaque, uniform, mitred strokes qualify. Each subpath becomes its own chain or loop of fresh vertices, since the engine fills only loops of three or more vertices; an open subpath with a fill becomes a closed fill object under the open stroke. SVG gradients map onto the board's: a linear one stays linear in the object's unit box through any transform, so its angle and moved stops are exact; a radial one is exact when the box sees it round. A stroke's `stroke-dasharray` and `stroke-dashoffset` (scaled as its width), `stroke-linejoin` and `stroke-miterlimit` (where the outline turns a corner) and `stroke-linecap` (where a subpath is open) become the path's `strokeDash`, `strokeJoin`, `strokeMiterLimit` and `strokeCap` (`svg-stroke-style.ts`), each left out where it equals the board's default (solid, round), so a round-stroked icon imports as before; a dashed stroke, or a sharp rectangle not mitred, is a path, not a shape. What the board cannot draw (filters, masks, clipping, text, images, patterns, a dash list it cannot hold, `miter-clip` and `arcs` joins drawn as miters, nonzero overlaps drawn even-odd) is drawn without it or approximated, and reported with a count.
