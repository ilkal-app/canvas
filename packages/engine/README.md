# @canvas/engine

`ImageLoadDeferredError` lets an asset source report a server capacity wait. `LevelLoader` releases the fetch slot and waits without spending its ordinary failure retry budget; cancellation and destruction still cancel the wait.

## Purpose

The renderer: retained scene graph, the `GpuBackend` interface with WebGPU and WebGL2 implementations, the engine host that runs it in a worker (or on the main thread), text/shape/path/image rendering, the R-tree spatial index, hit testing and layout.

## Public API

- `InstanceExpansion`, `InstanceStatus`, `DefinitionSource`, `isVirtualObjectId`: transient component-instance expansion (an instance that sets no `colorMode` is shown with its main's, and a main's mode change re-resolves its instances; an instance shows its main's variant presets for the values it selects, and an axis change or its own switch re-resolves it, while a preset edit patches only the children whose preset records changed, in place even in an auto-layout main when it only repaints (`fill`, `strokeColor`, `color`), and re-resolves every instance when a changed record moves or sizes a child, patches a layout or sizes the variant at the main's own id; a slot shows the main its records or presets swap in, and an edit to, or the retirement, deletion or restoration of, any main a definition can swap in re-resolves the instances that can reach it) before renderer enqueue, with whole-board definition invalidation, retired-main filtering and real selection owners.

The text pass reuses local full-glyph quads within a frame for the same immutable layout,
origin, scale, prior tiers and atlas revision. `SharedGlyphQuads` replays atlas lookups and
missing-glyph requests in their original order, preserving LRU eviction order and request
backoff. It retains no geometry across frame boundaries; world transforms remain per-object.

A retained `ScenePass` may supply `preparePatch` when its slot count is unchanged. It must prove that full preparation would change only the shared float slice in the first `recordCount` records, preserving all other floats and page assignments. Returning `undefined` uses full preparation. `InstanceBuffer.writePartialMany` validates the shared slice once and updates a retained slot prefix without clearing the rest of each record; overlapping source views and NaN payloads preserve typed-array copy semantics. The text pass uses this path when its ordered glyph quads are unchanged and every patched glyph is present, updating their world transform while retaining glyph data and atlas pages.

- `MIN_ZOOM`, `MAX_ZOOM`: The camera zoom range a person navigates, 0.02× to 64×.
- `clampZoom(zoom)`: Limits a requested zoom factor to that range.
- `Camera`, `WorldBounds`, `CameraClipTransform`: A camera value (world top-left, zoom, viewport in CSS px, dpr), a world rectangle, the world-to-clip map.
- `worldToScreen(camera, point)`, `screenToWorld(camera, point)`: World units ↔ CSS pixels from the viewport's top-left corner; pure, inverse of each other.
- `visibleWorldBounds(camera)`, `cameraClipTransform(camera)`, `isSameCamera(a, b)`: The world rectangle on screen; the map the camera uniform holds; camera equality.
- `isWebGpuSupported(host)`: Whether a navigator exposes WebGPU (else the WebGL2 backend is used).
- `planCapture`, `captureSizeOf`, `fitsCapture`, `DEFAULT_CAPTURE_LIMITS`, `CaptureRect`, `CaptureLimits`, `CaptureTile`, `CapturePlan`: An export's plan: the image's size for a board area at a scale, within limits (16384 px a side, 128 MP), and the tiles of at most 4096 px it is drawn in, each with the camera that draws exactly its window. Pure.
- `captureScene(plan, renderTile)`, `RenderCaptureTile`: Draws an export tile by tile, one at a time, through the caller's `renderTile`, and stitches the tiles into one RGBA image.
- `createGpuBackend(canvas, options)`: Creates the backend for a canvas: WebGPU when available, else WebGL2; `prefer` and `sampleCount` options.
- `CreateGpuBackendOptions`: `prefer` (`webgpu` default) and `sampleCount` (4 default).
- `GpuBackend`, `GpuDeviceLoss`, `GpuDeviceLostListener`, `GpuDrawStateCounts`: The interface every renderer is written against: resources, pipelines, passes, submit, readback, timings, the optional `whenSubmittedWorkDone()` (WebGPU `onSubmittedWorkDone`, a polled WebGL2 fence); `onDeviceLost(listener)` reports a lost device or context once (WebGPU `device.lost`, WebGL2 `webglcontextlost`, with `restored` settling when a new backend can be made). `drawStateCounts` (optional, `GpuDrawStateCounts`): render passes begun and pipelines and bind groups actually bound, cumulative; the `submit` stage reports each frame's difference as `FrameStats.renderPasses`, `pipelineSwitches` and `bindGroupChanges`.
- `GpuCapabilities`, `GpuBackendName`, `GpuSampleCount`: What the running backend can do: max texture size, timestamps, sample count, adapter name, software flag.
- `GpuBuffer`, `GpuBufferDescriptor`, `GpuBufferUsage`: Vertex and uniform buffers, written by byte range.
- `GpuTexture`, `GpuTextureDescriptor`, `GpuTextureFormat`, `GpuTextureRegion`, `GpuTextureDataLayout`: 2D `rgba8unorm` / `r8unorm` sampled textures and load-only `rgba32float` placement tables, written whole or by sub-region.
- `GpuSampler`, `GpuSamplerDescriptor`, `GpuFilterMode`, `GpuAddressMode`: Sampling state: nearest or linear, clamp or repeat.
- `GpuShaderSource`: One pass's shaders: WGSL plus its generated GLSL ES 3.0.
- `CURVE_STENCIL_SHADER`: The stencil pass of a non-zero fill with curved edges: triangles in device pixels with Loop–Blinn coordinates, discarding past each quadratic; the golden harness's `nonzero-curves` scene.
- `GLYPH_STENCIL_SHADER`, `GLYPH_STENCIL_MOVE_SHADER`: The vector glyph tier's stencil pass: a text run's glyph triangles in its object's frame, placed by its record and the scene camera, discarding past each quadratic and writing no colour; and its retained-move variant.
- `PARITY_TRIANGLE_SHADER`: The backend parity scene's shaders, for the golden-scene harness (`tooling/golden`).
- `GpuVertexBufferLayout`, `GpuVertexAttribute`, `GpuVertexFormat`, `GpuVertexStepMode`: Per-vertex and per-instance record layouts; offsets and strides are derived.
- `GpuRenderPipeline`, `GpuRenderPipelineDescriptor`, `GpuBindingLayoutEntry`: Pipelines: shaders, vertex layout and group-0 bindings.
- `GpuBlendMode`, `GpuColorWrite`, `GpuStencilState`, `GpuCompareFunction`, `GpuStencilOperation`: Fixed-function state: premultiplied blending, colour writes, even-odd stencil.
- `GpuBindGroup`, `GpuBindGroupDescriptor`, `GpuBindGroupEntry`: Resources bound together for draws.
- `GpuRenderPass`, `GpuRenderPassDescriptor`, `GpuViewport`, `GpuColor`: A pass on the canvas, or on a render target (`target`): clear, viewport, instanced draws with an instance range.
- `GpuRenderTarget`, `GpuRenderTargetDescriptor`: An offscreen colour target from `GpuBackend.createRenderTarget({ width, height })`: passes with `target` draw into it with the canvas's pipelines and resolve into its `rgba8unorm` `texture` (rows bottom-up on WebGL2).
- `createLayerCompositePipeline(backend)`: The `layer-composite` pipeline: a render target's texture blended premultiplied source-over at an opacity (`layer-composite.wgsl`; uniform at binding 0, texture 1, sampler 2).
- `drawLayerComposite(backend, target, rect, opacity)`: Draws a render target into the canvas at a device rectangle of its own size, at an opacity, in its own pass; flips rows on WebGL2.
- `GpuPassTiming`: A labelled pass's GPU time in ms.
- `GpuCanvas`: `HTMLCanvasElement` or a worker's `OffscreenCanvas`.

### Scene graph and frame (`src/scene/`)

- `SceneRenderer`, `SceneRendererOptions`, `FrameInput`, `InkColors`: The frame driver: scene, per-pass GPU resources, camera uniform and the `Frame`; `setStickyAuthors(authors)` (only the labels that change are queued), `enqueue(changes)` (through its `DrawableGate`), `renderFrame({ timeMs, camera })`, `hasPendingWork()` (meshes still being built, or churn the budget carried to a later frame), `setTheme(theme, inkColors?)` (the viewer's theme: `'ink'` draws `inkColors[theme]`, default the schema's `INK_COLORS`; rewrites only the ink objects' records, one dirty-range pass, no text layout, path mesh or document read; returns the records changed; `SceneRendererOptions.theme` and `inkColors` set the start; objects in no explicit colour mode follow it for tokens too), `setColorTokens(table)` (the board's colour token values: rewrites only the records naming a token whose light or dark value changed; `SceneRendererOptions.colorTokens` sets the start), `SceneRendererOptions.colorModeFallback` (a schema `ColorModeFallback` hook, or the built-in `'frame-fill-luminance'` by name; asked for an object's mode when no ancestor-or-self frame, main or instance sets one, before the viewer's theme; absent: none), `takeUndrawable()` (the objects the gate found undrawable since the last call, each once per change: an `UndrawableReport`, at most 1,000 listed), `retainedPlacementOf(id)` (a retained-move member's placement as drawn; for tests and diagnostics).
- `Frame`, `StagePosition`: The frame loop as ordered named stages; `insertStage(before | after, anchor, stage)` and `wrapStage(name, wrap)` are the extension point. `addPendingWork(isPending)` registers a stage's work for later frames, which `hasPendingWork()` (and so `SceneRenderer.hasPendingWork`) reports.
- `FrameStage`, `FrameContext`, `FrameStats`, `FrameTimerHook`, `NO_FRAME_TIMERS`: A stage `{ name, run(context) }`; what a stage sees (time, camera, viewport, backend, timers, scene, buffers, passes, draw list, stats).
- `DrawListEntry`: One step of the frame's draw order, `{ passName, page?, ranges }`; `cull` fills the list (a paged pass one entry per page), `draw` walks it in order.
- `BUILT_IN_STAGE_NAMES`, `COLLECT_CHANGES_STAGE`, `UPLOAD_DIRTY_RANGES_STAGE`, `createCullStage(culler)`, `createDrawStage(timingLabel?, background?)`, `SUBMIT_STAGE`: The built-in stages: `collectChanges`, `levelOfDetail` (below), `uploadDirtyRanges`, `cull`, `zOrderSegments` (below), `layers` (renders the frame's offscreen layers, below), `draw` (which paints its `background`, if any, under every object), `submit`.
- `ChurnBudget`, `DEFAULT_CHURN_BUDGET`: How much churn one frame takes on (`SceneRendererOptions.churnBudget`): `entriesPerFrame`, the visible-set entries and exits the default culler admits per frame, and `lodChangesPerFrame`, the level-of-detail form changes; the rest waits for later frames, new entries nearest the viewport's centre first (`FrameStats.carriedAdmissions` counts what waits). Opt-in (`churnBudget: {}` for these defaults, 6,000 and 3,000; also `EngineHostOptions.churnBudget`); off by default, since on the m1 it raises the 50k-mobile p95 by a third.
- `DrawStageBackground`: What the `draw` stage paints first, under every object: `prepare(context)` before the pass opens (writes), `draw(renderPass, context)` right after the clear (`SceneRendererOptions.background`).
- `GridBackground`, `GridBackgroundOptions`, `GRID_DOT_COLOR`, `GRID_DOT_RADIUS_PX`, `GRID_UNIFORM_BYTE_LENGTH`, `dotGridUniformOf(camera, color, radiusPx)`: The dot grid: a draw-stage background of one full-canvas quad whose shader lights dots in device pixels; `setVisible`; a 48-byte uniform written only when the camera changes; hidden, it writes and draws nothing.
- `gridSpacingAt(zoom)`, `GRID_MIN_SPACING_PX`, `GRID_MAX_SPACING_PX`: The grid's spacing, world units: the power of two keeping dots 16–32 CSS px apart, so it doubles zooming out and halves zooming in; snapping to the grid uses it too.
- `gridOpacityAt(zoom)`, `GRID_FADE_FULL_ZOOM`, `GRID_FADE_HIDDEN_ZOOM`: The grid's opacity at a zoom: 1 at and above 25%, a smoothstep down to 0 at 12.5% (one spacing doubling), 0 below; there the grid writes and draws nothing. Snapping is unaffected.
- `ZOrderSegments`, `Z_ORDER_SEGMENTS_STAGE_NAME`, `ZOrderSegmentCounts`, `ZOrderSegmentsOptions`, `ZOrderTables`, `SegmentSpatialIndex`, `MAX_CHECKED_MOVES`, `PAINT_ORDER_BATCH`, `DEFAULT_SLOT_COMPACTION`, `SlotCompactionOptions`: The stage after `cull` that rewrites the draw list into z-order segments; `install(frame)`; `counts` of cached-table rebuilds (`orderEdits`: orders edited in place); `tables()`, its tables indexed by rank as they stand (`ZOrderTables`, for tests and diagnostics); `segmentCount` of the last plan; `spatial`, the index whose boxes let occluders over nothing share segments, checked against each frame's moved objects (up to `MAX_CHECKED_MOVES`). `SceneRenderer` installs one, with its culler's index, unless `isZOrdered: false`. Slot order (`SlotCompactor`): a change set creating at least `PAINT_ORDER_BATCH` (64) objects reaches the scene with `created` in paint order, so their slots follow it; and on still frames (no change set, the same camera, no retained move) a pass whose last plan drew more than `ratio` ranges per entry, and at least one extra range per `recordsPerExtraRange` of its records (a few objects inserted mid-order are cheaper drawn as a few more ranges than the whole pass moved after each), is re-slotted in paint order, `recordsPerFrame` records a frame (`ZOrderSegmentsOptions.compaction`, `SlotCompactionOptions`, `DEFAULT_SLOT_COMPACTION`: 4, 64 and 4,096; `false` never re-slots), with `hasPendingCompaction()` keeping frames coming and `counts.slotCompactions` the records moved.
- `planSegments(input)`, `planSegmentDraws(input)`, `SegmentPlan`, `SegmentPlanInput`, `PlannedPass`, `SlotOwners`, `BoundsOfRank`, `PassPageSpans`: The pure planner: the passes with their slot owners (and the ranks their level of detail hides) by paint rank, occluder flags, the visible ranges, the camera scale and object boxes in; the segment-major draw list out (with its segment count, whether it merged by boxes, and the page spans a move is checked against).
- `paintOrderOf(objects)`, `StackedObject`: The board's paint order, bottom first: parents before children, siblings by `z` then id.
- `compareStacking(a, b)`, `StackingKey`: Siblings by `z` (UTF-16 code units), ties by id: the schema's `compareSiblings`, the rule `@canvas/document` sorts by too.
- `SceneHierarchy`: The parent tree of a scene's objects as last applied (`Scene.hierarchy`): `parentOf`, `childrenOf`, `has`; the scene refreshes descendants by it and connector routing finds what a moved group or frame carries.
- `Scene`, `SceneOptions`: The retained scene: mirrors the document into per-pass instance records; `apply(changeSet)` rewrites only changed objects and their descendants; `rewriteRecords(passName, targets)` rewrites one pass's records whose drawing changed; `pagesOf`, `pageRevisionOf` for paged passes; `slotRevisionOf` identifies unchanged per-object slot ownership; `slotOwnershipRevision` tracks any ownership change across the scene, independently of record content. `clipTable`: the clipping frames its records' clip indices name, each worked out once per `apply` and kept in step as frames move, stop clipping or go. `levelOfDetail`: each drawn object's level-of-detail form per pass with a rule (`LevelOfDetail`). `ink`, `setInk(color)`, `setTheme(theme, inkColors?)`, `setTokens(table)`: colour resolution, each returning the records rewritten; `SceneOptions` takes `ColorTargetsOptions` (`theme`, `inkColors`, `ink`, `colorTokens`, `colorModeFallback`). `layerOpacity`: the layers drawn in the multiply form. `compactSlots(passName, ids, isFresh?)` re-slots one pass's records of the listed objects in that order, through the ordinary record path, into the lowest free slots or, with `isFresh`, past every slot handed out, and bumps `compactionRevision`, which slot caches fed only by change sets rebuild on.
- `SceneHandles`: A scene's dense object handles (`Scene.handles`): `handleOf(id)` (a small integer an object keeps for the scene's life once it has held slots, through deletion and recreation), `passIndexOf(name)`, and each pass's slots and slot revision by handle (`slotsOf(handle, passIndex)`, `revisionOf(handle, passIndex)`), so the camera path reads typed tables instead of maps keyed by id.
- `SceneLayerOpacity`: What `Scene.layerOpacity` does: `changeFallbacks(added, removed)` draws layers in the multiply form or composites them again, rewriting only the trailing transparency of their records and their descendants'; `multiplierOf(id)` is what an object's records multiply by, for a layer the opacity of its ancestors drawn in the multiply form.
- `SceneSource`, `SceneChangeSet`: What the scene reads: `get(id)` over schema objects, plus `created`/`updated`/`deleted` ids (the DocumentStore adapts to it).
- `SceneChangeQueue`: Coalesces the change sets that arrive between frames into one.
- `ScenePass`, `ScenePipelineSpec`, `SceneObject`: A render pass: name, record layout, pipeline spec (optional `pageBindings`: per-page textures, samplers, uniforms; optional `pageShaderVariants`: shaders for a page whose records name only its first `pageSlots` resources; optional `isDeferred`: the pipeline is built on the pass's first record, not at engine start), `recordCount(object)`, optional `isOccluder(object)`, optional `levelOfDetail` (its rule and the size it measures), `prepare(record, target: { object, transform, palette? }, recordIndex)` (`palette`: the `ColorPalette` the object's `'ink'` and tokens resolve in; `textPalette`: the one its text resolves in when a sticky's or filled shape's own fill gives another mode), and optionally `createDrawer(setup)` (a custom-draw pass), `pageOf(target, recordIndex)`, `pageEntries(page)` and `pageSlotsOf(page)` (paging), `install(frame)`, `forget(id)`, `reportMemory(ledger)`, `destroy()`.
- `ScenePassDrawer`, `ScenePassDrawerSetup`, `EntryDrawContext`, `DrawerMemory`: A custom-draw pass's per-renderer drawer: `install(frame)`, `drawEntry(context, entry)` for each of its draw-list entries, `hasPendingWork()`, `memory()`, `destroy()`.
- `ScenePassFactory`, `ScenePassEntry`, `ScenePassEnvironment`, `resolveScenePasses(entries, environment)`: A pass with state or GPU resources of its own, built per renderer from the backend and the host's hooks (`requestFrame`, `now`, the text resources, the memory ledger, the device budget, image support); a renderer's list mixes pass values and factories.
- `createStandardScenePasses({ jobs, onFault?, meshByteBudget?, layerByteBudget? })`, `StandardScenePassesOptions`: The passes both engine hosts draw with, in this order: `FRAME_SHADOW_PASS`, `SOLID_RECT_PASS`, `RECT_GRADIENT_PASS`, `RECT_IMAGE_PASS`, `ROUNDED_RECT_PASS` and `ROUNDED_RECT_GRADIENT_PASS`, `FRAME_STROKE_PASS`, the layer composite pass (below; its layers under the device budget's `layers` share, C2c), `SDF_SHAPE_PASS`, `SDF_SHAPE_GRADIENT_PASS`, `SDF_SHAPE_IMAGE_PASS`, `LINK_PREVIEW_PASS` and `LINK_ICON_PASS`, `IMAGE_PASS` (a factory, built per renderer around the texture manager it shares with the image-fill passes), `IMAGE_BORDER_PASS` (an image's border over it), a path pass and its gradient variant (`createGradientPathPass`) meshing through the given job pool under the device budget's `meshes` share, then `TEXT_PASS`, then `FRAME_TITLE_PASS`.
- `splitRangesByPage(ranges, pageBySlot)`, `PageRanges`: Splits a paged pass's instance ranges into one list per page, pages ascending; the `cull` stage and the z-order segments use it.
- `SOLID_RECT_PASS`: Flat-colour quads for frame backgrounds, all occluders. Every shape, filled rectangles included, is the SDF shape pass's.
- `FRAME_SHADOW_PASS`, `FRAME_SHADOW_PASS_NAME`: A frame's drop shadow, one soft record of the shape pass's layout and shader, registered first so it lands under the frame's own background; flagged to the z-order segments; never cut by the frame's own clip.
- `LAYER_COMPOSITE_PASS`, `LAYER_COMPOSITE_PASS_NAME`, `isLayerForm(object)`, `LayerDraw`, `LAYERS_STAGE_NAME`: Layer opacity in layer form: the pass with one record per translucent container or multi-part leaf, composited once from its offscreen layer; which objects take that form; one layer a frame draws; the stage that renders the layers before `draw`. C2c bounds them: at most 16 per frame, none under 64 device pixels, within the `layers` share, the rest drawn in the multiply form (design notes); a `LayerDraw` that fell back for the budget is `isInline`, its window drawn in place of its composite.
- `FRAME_STROKE_PASS`, `FRAME_STROKE_PASS_NAME`, `isStrokedFrame(object)`, `writeFrameStrokeRecord(record, frame, transform, ink?)`: A frame's outline, one stroke-only frame SDF record (`FRAME_SHAPE_INSTANCE_LAYOUT`) drawn with the shape shader (the frame's box, rounded as the frame is, its outline inside, centred or outside the edge), drawn after the frame's descendants (`ScenePass.isDrawnAfterDescendants`: a closing paint rank after its subtree) so it lands over the frame's background and its whole subtree, as in Figma, and under later siblings; flagged to the z-order segments; never cut by the frame's own clip; whether a frame has an outline that paints.
- `IMAGE_BORDER_PASS`, `IMAGE_BORDER_PASS_NAME`, `isBorderedImage(object)`, `writeImageBorderRecord(record, image, transform, palette?)`: An image's border, one stroke-only frame SDF record of its box with sharp corners, the border wholly inside the edge (`'ink'` and tokens resolved by the palette), drawn right after `IMAGE_PASS` and flagged an occluder so it lies over its own image; no record for an image whose border does not paint.
- `RECT_GRADIENT_PASS`, `RECT_GRADIENT_PASS_NAME`: The gradient variant of the solid-rect pass, a factory: frame backgrounds that are a gradient the schema accepts, the solid-rect record plus its paint-table record (`rect-gradient` shader); the average colour under the gradient level-of-detail threshold.
- `RECT_IMAGE_PASS`, `RECT_IMAGE_PASS_NAME`: The image variant of the solid-rect pass, a factory: frame backgrounds that are an image paint the schema accepts, drawn as a box, rounded as the frame is, by `sdf-shape-image` from the renderer's shared texture manager, laid in by the paint's fit; the image's average colour until a level is resident and under `IMAGE_LOD_RULE`.
- `InstanceBuffer`, `InstanceBufferOptions`: A pass's persistent CPU instance buffer: fixed stride, grow by doubling, free list, coalesced `dirtyRanges`. `reuseLowestFirst()` hands free slots out lowest first, `allocateFresh()` allocates past every slot handed out, and `trimHighWater()` lowers `recordCount` past free slots at the top (slot compaction); `changedSlots` lists the exact slots written since `clearDirty`.
- `InstanceLayout`, `resolveInstanceLayout(attributes)`: A record layout of `float32…` attributes and its stride; `clipFloat` and `opacityFloat`, for a scene layout, name its clip index float and its trailing layer transparency float.
- `resolveSceneInstanceLayout(attributes)`, `CLIP_INDEX_LOCATION`: A scene pass's record layout: its own attributes, then a `float32` clip index at `@location(14)` and a trailing `float32` layer transparency at `@location(12)`, both written by the scene after the pass prepares the record (the slot of the record's nearest clipping ancestor, never its own object, 0 unclipped; 1 minus the object's cumulative layer opacity, 0 opaque).
- `ROUNDED_RECT_PASS`, `ROUNDED_RECT_GRADIENT_PASS`: The solid and gradient backgrounds of frames with a rounded corner, each one frame SDF record (the shape record, then the four capped corner radii at `@location(15)`) drawn by `sdf-shape` and `sdf-shape-gradient` (the gradient one a factory with its paint table record); a sharp frame's background stays the solid-rect or rect-gradient pass's flat quad.
- `isInsideFrameShape(frame, point, outward?)`: Whether a point in a frame's own frame lies in its box grown by `outward`, a rounded frame's empty corners left out as the shader draws them: `hitPoint`'s frame pick and the tools' colour under a point.
- `ClipTable`, `CLIP_TEXELS_PER_SLOT`, `CLIP_FLOATS_PER_SLOT`: The scene's clip table (`Scene.clipTable`), four rgba32float texels per clipping frame some drawn object is clipped by: world origin and axis; size, its clipping ancestor's slot and a rounded flag; the map into that ancestor's frame (float64 on the CPU); its four capped corner radii. Slot 0 is unclipped; free-list slots, doubling growth, dirty texels only.
- `ClipTableTexture`, `CLIP_TABLE_BINDING`: The clip table's GPU copy, a load-only texture every scene pass binds at `@binding(5)`; replaced when the table grows, else only dirty texels are written.
- `ByteRange`, `coalesceDirtyRecords(records, stride, maxGap)`: A `[start, end)` byte range; dirty records merged into upload ranges.
- `ScenePassResources`: A pass's GPU side: pipeline (a deferred pass's built by the first `upload` that finds a record; `hasPipeline` says whether it exists), camera bind group (with the clip table at binding 5, rebuilt when its texture is replaced), geometry and the GPU instance buffer it uploads dirty ranges to; given no `ClipTableTexture` (an overlay drawn outside a scene), it keeps one unclipped slot of its own.
- `CameraUniform`, `CAMERA_UNIFORM_BYTE_LENGTH`, `cameraUniformValues(camera)`: The 32-byte camera uniform (the clip map, then one device pixel in world units, then one CSS pixel in world units, `cameraUniformValues`), written only when they change.
- `SceneCuller`, `InstanceRange`, `CullRangeChange`, `AllVisibleCuller`: The `cull` stage's strategy (default: `SpatialCuller`, below) and a culler that culls nothing.
- `WorldTransform`, `worldTransformOf(object, source)`: An object's own frame to the world, ancestors composed.

### Connectors (`src/connectors/`)

- `connectorPathOf(from, to, route)`, `ConnectorPath`, `elbowConnectorRoute(from, to, middle?)`, `curvedConnectorCubic(from, to)`, `ELBOW_STUB`, `CURVE_HANDLE_FRACTION`: A connector's centre line from its placed ends (`placeConnectorEnds` in `@canvas/schema`): straight; elbow (axis-aligned, leaving each attached end square to its side for `ELBOW_STUB` world units, one bend where the axes cross or two through the middle, its movable piece at `elbowMiddle`); curved (one cubic whose handles reach `CURVE_HANDLE_FRACTION` of the span along each end's normal). Pure.
- `connectorLabelPoint(path)`: Where a connector's label is centred: halfway along its centre line by length. Pure.
- `resolveConnectorShape(connector, source)`, `ConnectorTargetSource`, `ConnectorShape`: The shape a connector draws on the document as it is now: ends placed on their targets' world boxes, routed, label point. Pure.
- `resolveConnectorEnds(connector, source)`: A connector's ends placed on the document as it is now, in its frame, as `resolveConnectorShape` routes from them; its route handles are measured from them. Pure.
- `connectorLabelSize`, `ConnectorLabelSize`, `LABEL_GAP_PADDING`, `LineGap`: a connector label's laid-out size, which its line breaks around with that padding a side and a press drags along it. Pure.
- `CONNECTOR_LEVEL_OF_DETAIL`, `CONNECTOR_LOD_RULE`, `CONNECTOR_HIDDEN_STROKE_PX`: The connector pass's level of detail: a connector whose stroke is under half a device pixel wide is hidden (not meshed, drawn or segmented), shown again from 0.6 px.
- `FRAME_TITLE_LOD_RULE`, `FRAME_TITLE_HIDDEN_WIDTH_PX`: The frame title pass's level of detail: a frame's name is hidden while the frame is under 40 device px wide on screen, shown again from 48.
- `createPathPass({ draws: 'connectors' })`, `PathPassContent`, `CONNECTOR_MESH_BYTE_BUDGET`: Connectors draw in a path pass of their own (`connector`, after the path pass in `createStandardScenePasses`, its mesh cache capped at 8 MiB), so they take their own level of detail.
- `connectorShapeOf(connector)`: The shape a connector value was placed with by the renderer's routing (each re-route hands the scene a new value), or its free ends' shape for a value that did not come through it.
- `ConnectorPlacements`: Connectors' placed values: `place(connector, source)` returns a copy carrying the shape it draws on the document now (kept while nothing it is placed from changed), `lastPlaced`, `forget`, `size`. The renderer's routing and the page's hit-test index each keep one, so hit testing and the index bound and pick a connector where it is drawn.

### Level of detail (`src/lod/`)

- `LodForm`, `LodLevel`, `LodRule`: A form an object draws in (`full`, `greek`, `average-color`, `chord`, `hidden`); a rule's cheap forms, richest first, each with the on-screen size under which it is taken.
- `lodFormOf(rule, screenSizePx, previous?)`, `lodLevelOf`, `lodFormAt`, `bandSideOf`, `lodEdgesOf`: Pure: the form for a size with hysteresis (cheaper at once under a threshold, back only at the threshold × (1 + the rule's `hysteresis`, 20% by default)); the same as a level number; which side of a threshold's 20% band a size is on (the no-thrash rule); the sizes on screen where an answer may change.
- `LOD_HYSTERESIS`, `TEXT_GREEK_LINE_PX`, `TEXT_HIDDEN_LINE_PX`, `IMAGE_AVERAGE_COLOR_EDGE_PX`, `PATH_CHORD_BOUNDS_PX`, `TEXT_LOD_RULE`, `IMAGE_LOD_RULE`, `PATH_LOD_RULE`, `SHAPE_FLAT_EDGE_PX`, `SHAPE_LOD_RULE`: The thresholds (`lod-thresholds.ts`): text greek under 4 device px a line and hidden under 2.5; images their average colour under 8 px on the longer edge; paths chords under 6 px; a 20% band each.

### Drawable geometry (`src/drawable/`)

- `DRAWABLE_EXTENT`, `MAX_DRAWABLE_SIZE`, `MAX_REPORTED_UNDRAWABLE`: Re-exported from `@canvas/schema` (part 1: the relay's door check reads the same ranges): how far from the origin a drawn object's geometry may lie, 2^31 world units on each axis (twice the board's bound of ±2^30, so an honest object at the edge, with its stroke and label overflow, is never refused); the widest size it may hold (2^32); the most undrawable objects one frame report lists (1,000).
- `undrawableReasonOf(object, source)`, `isDrawableIn(object, source)`, `UndrawableReason`: The one rule every reader of stored geometry follows: an object is drawable when everything the engine writes from it to a float32 GPU buffer is finite there and nothing it loops over runs past an honest count: every number finite; colours, opacity and crop in [0, 1] (a crop's size in (0, 1], the crop within the image); `sides` an integer from 3 to 64; a stroke at most 64 wide; font sizes in the schema's 4-400 and natural sizes whole numbers from 1; the whole image behind a crop (the drawn box over the crop's size) within 2^32; at least one style run; run lengths whole and covering the text; the shape kind and line caps ones the schema lists; widths, heights and corner radii in [0, 2^32]; any other number within float32's range; its geometry on the board within ±`DRAWABLE_EXTENT`; and every frame or group around it drawable too. Otherwise its reason (`not-finite`, `negative-size`, `past-extent`, `out-of-range`, `undrawable-parent`). The ranges are the schema's (`coordinateReason`, `sizeReason`, … in `@canvas/schema`), never a copy. Pure, no curve flattened.
- `ownUndrawableReason(object)`: The same rule on the object's own fields alone (no parent, no place).
- `DrawableGate`, `UndrawableObject`, `UndrawableReport`: The door a change set passes before the scene or a hit-test index reads it: an undrawable object is absent (`get` returns `undefined`), objects whose drawability changed with an ancestor are listed as updated, `takeReport()` gives each undrawable object once per change (the first 1,000 and the count), `isDrawable(id)` (O(1)), `undrawableCount`. The `SceneRenderer` owns one; the app's hit-test index another. O(changed objects) per change set: a changed frame or group whose descendants did not change keeps a hull of its subtree in its own frame, so moving or turning it re-judges it alone (a select-all drag's preview frames); judging an object that holds no children allocates nothing.

The gate has a private conservative proof for accepted worker-owned retained moves. After a
full successful root/hierarchy check, unchanged session geometry and current positions deep
inside the drawable extent can skip repeated validation. Ordinary changes, different session
bases, shared buffers, main-thread hosts and coordinates outside that interior retain the exact
validation path. This changes no drawable value or refusal reason and never mutates snapshots.

The worker-pool burst micro-benchmark (`tooling/bench/src/workers/layout-burst.bench.ts`) sends 500 unique text-layout requests in one tick through the production pool, protocol and layout handler on real Node workers. `chooseWorkerCount` sizes the pool from available CPUs, capped at four. Startup/font loading are outside samples; every sample drains and checks all 500 replies before the next begins. Three recorded-duration clocks report first-result latency, last-result latency, and synchronous posting/receive-handler work. The last excludes native deserialization before the JavaScript receive callback, and nested posts are counted once. These are Node transport/CPU measurements, not browser frame or GPU timings; the printed reciprocal rates are not end-to-end throughput.

On 2026-09-30, Node 22.23.2 with four workers, three independent runs of the standard three repeats recorded median first-result latency **0.333 ms**, last-result latency **15.496 ms**, and synchronous transport work **7.467 ms** per burst (median across runs). The corresponding median p95s were **0.924 ms**, **53.404 ms**, and **10.697 ms**. These cases are automatically discovered by `bench:ci`'s micro suite and use its unchanged 10% threshold, 0.001 ms floor and measured noise allowance. A new case bootstraps until three history runs exist. In an ephemeral three-run calibration, `BENCH_LAYOUT_EXTRA_CLONE=1` adds one extra request serialization before each normal post; the unchanged comparator rejected last-result median **28.229 ms** and transport p95 **29.871 ms**. No stored history or reference was changed.

### Images and the texture manager (`src/images/`)

- `IMAGE_PASS`, `IMAGE_PASS_NAME`, `IMAGE_STAGE_NAME`, `IMAGE_LEVEL_OF_DETAIL`: The image pass (a `ScenePassFactory` in `createStandardScenePasses`, after the solid-rect pass): one record per image, or one per visible tile of an image large enough to be tiled, on the page of the level or tile it samples; its `images` stage (after `collectChanges`) updates the texture manager, rewrites the records whose level changed and counts `FrameStats.blankImages`, `placeholderImages` and `visibleImages`. Flagged to the z-order segments at any opacity above 0; keeps paint order across pages. An image whose fitted longer edge is under 8 device px draws its average colour (`IMAGE_LEVEL_OF_DETAIL`), on its level's page, counted as drawn, not blank.
- `ImageLoadDeferredError`: An adapter capacity wait, with a bounded `retryAfterMs`; loader retries it without spending ordinary failure attempts.
- `TextureManager`, `TextureManagerOptions`, `TextureManagerStats`, `ImageFrameInput`, `ImageFrameResult`: The client texture manager: per frame, each visible image's level from its on-screen size × DPR with hysteresis, the smallest level always resident, prefetch along the pan, loads by priority through the pool, uploads under the `textures` budget with larger-first LRU eviction, atlases for small levels and tiles, visible tiles only for large images, lower levels after an allocation failure; a pan at an unchanged zoom plans nothing. `track`, `forget`, `update`, `bindingOf`, `shownKeys`, `residentKeys`, `isIdle`; `stats` counts uploads, evictions, blank frames, allocation failures and loads nothing could decode (`decoderMissingFailures`).
- `pendingImageAssetInfo(mimeType)`: The description an adapter gives an asset it cannot describe yet (the board not linked to it, the image not read): no size, no levels, a placeholder, replaced through `subscribe`.
- `AssetSource`, `ImageAssetInfo`, `ImageAssetTiles`, `AssetTileKey`, `ImageAssetListener`: The engine's only view of image assets: `describe`, `fetchLevel`, `fetchTile`, `fetchOriginal` (each fetch with an `AbortSignal`), `subscribe` for levels the server adds, and two optional reports for an adapter that paces its follow-ups: `setVisibleAssets` (the assets the images on screen wait for, and those the images near the view or ahead of the pan wait for, whenever either set changes) and `revive` (an object using a pending asset changed). Its TSDoc lists what the adapter owes the engine: board and token on every URL, signed URLs refreshed inside the fetch past their 900 s, pending descriptions rather than early rejections, one multiplexed event stream closed on `ready` or `failed`, AVIF or WebP by decoder capability, never a logged URL. `ImageAssetInfo` is `Pick<AssetRecord, …>` of `@canvas/schema`, so the app's adapter passes records through (an AVIF level may be listed with its WebP fallback; the adapter fetches the format the job workers can decode); `naturalSize`, `averageColor` and `blurhash` are null until the service has read the image (a placeholder, and no decoding of the original, until then). ### Memory budget (`src/memory/`)

- `budgetForDevice({ deviceMemoryGb, maxTextureSize, isMobile })`, `DeviceMemoryBudget`, `DeviceDescription`, `DeviceClass`: Bytes per memory category by device class: 512 MiB desktop, 128 MiB mobile, at most an eighth of `navigator.deviceMemory`, 256 MiB for a GPU whose textures stop at 4096 px; textures 34 64ths, glyph atlases and path meshes an eighth each (on a phone or tablet 10 and 6 64ths, so the text atlas holds a 2048-texel page), offscreen layers (render targets) 6 64ths. The texture manager keeps under `textures`; the glyph atlas and path meshes read `atlases` and `meshes`.
- `DESKTOP_BUDGET_BYTES`, `MOBILE_BUDGET_BYTES`: 512 MiB and 128 MiB.
- `AtlasLoan`, `AtlasLoanOptions`, `ATLAS_LOAN_MARGIN_SHARE`: The textures' loan of unused memory to the scene text atlas, one per budget: the texture manager reports what it holds, wants and may hold, and caps itself less what the atlas borrows; the atlas grows by `lendableBytes` (what the textures neither hold nor want, less an eighth) and gives memory back at once (`reclaim`) when images want it.
- `EvictionMemory`, `REGENERATION_WINDOW_MS`: What a cache evicted in the last 8 s (one zoom sweep) and the entries it made again inside that window: the glyph atlas (`regeneratedGlyphCount`) and the path mesh cache count regenerations with it, which a zoom sweep must not cause.

## Depends on

`@canvas/schema` (object types, for the scene; `StyleRun`, `TextStyle` and `TEXT_ALIGNS`, for text). Dev dependencies: `naga-wasm` (WGSL → GLSL at build time) and `@webgpu/types`.

**Bundled fonts** (`assets/fonts/`): Liberation Sans 2.x, regular, bold, italic and bold italic, under the SIL Open Font License 1.1 (`assets/fonts/LICENSE`). It is the open face metric-compatible with Arial, and so with the prototype's default Helvetica. The files are copied unmodified from `pdfjs-dist` 5.4.296 (`standard_fonts/`); SHA-256: regular `f8ace1f8…221f`, bold `361c61b8…dddc`, italic `832b4406…f512`, bold italic `a224075a…281d`. Tests and golden scenes read them; the app will serve its own fonts.

**msdfgen** is not a dependency of the engine: `src/text/msdf/msdfgen-module.ts` types its Embind API structurally, and whoever runs `msdf` jobs with MSDF supplies a loader. The app's job worker and the golden harness use `@zappar/msdf-generator` 1.2.4 (msdfgen, stb_truetype and Skia PathOps compiled to WebAssembly; licences under [Third-party notices](#third-party-notices)), pinned exactly because the engine relies on its Embind names (`Font`, `VectorUnsignedChar`, `getGlyphShape`, `generateMSDFWithOverlapFix`), which the package ships in `dist/msdfgen_wasm.js` but does not export; the golden text scenes fail if they drift.

`naga-wasm` provenance, recorded because it is young: version 30.1.0, pinned exactly, bundling naga 30.0.1 (wgpu's shader translator) compiled to WebAssembly; first published 2026-09-17; a single maintainer (kekkon-nexus); published from GitHub Actions with npm provenance; declares `engines: node >=24.12` but runs on this repo's Node 22 (it needs only WebAssembly and `fs`). Its output is committed, so a changed release shows up as a reviewable diff. The fallback is the `naga` CLI from cargo, with the same script.

## Frame pipeline (the extension point)

A frame is `SceneRenderer.renderFrame({ timeMs, camera })`: it builds a `FrameContext` and runs `SceneRenderer.frame`, an ordered list of named `FrameStage`s (`{ name, run(context) }`, synchronous, on the thread that owns the backend). The built-in stages, in order:

| Stage               | What it does                                                                                                                                                                                                                                                        |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `collectChanges`    | Drains the `SceneChangeQueue` (change sets pushed with `enqueue` since the last frame, coalesced) and applies it to the `Scene`.                                                                                                                                    |
| `levelOfDetail`     | Brings each visible object's level-of-detail form up to date for the camera (`LevelOfDetail`): the objects that entered the culler's visible set, and on a zoom only the object sizes the zoom took across a threshold or band edge; counts transitions and thrash. |
| `uploadDirtyRanges` | Writes the camera uniform if the camera's clip map changed, then each pass's dirty instance ranges (or the whole used range once after the buffer grew).                                                                                                            |
| `cull`              | Asks the `SceneCuller` which instance ranges each pass draws and fills `context.drawList`: one `{ passName, ranges }` entry per pass with visible records, in pass order.                                                                                           |
| `zOrderSegments`    | `ZOrderSegments`: rewrites `context.drawList` segment-major, a new segment at each visible opaque occluder, passes in registered order within a segment (see "Z-order segments" under Design notes). Absent with `isZOrdered: false`.                               |
| `draw`              | Begins one render pass (clearing to `clearColor`) and walks `context.drawList` in order: per entry, binds that pass's pipeline and buffers and issues one instanced draw per range.                                                                                 |
| `submit`            | `backend.submit()`.                                                                                                                                                                                                                                                 |

Later work adds or wraps stages; it does not edit the loop:

- **Add** a stage with `frame.insertStage('before' | 'after', anchorName, stage)`. The draw list decides draw order, not the pass list: `zOrderSegments` rewrites `context.drawList` in place segment-major after `cull`, so a stage that wants the final order inserts after `zOrderSegments` (one inserted after `cull` runs before it, and its list is re-planned); an overlay pass inserts before `submit`.
- **Transient overlay** stages may use `frame.insertTransientOverlay(stage)` after `draw` only when they change overlay pixels and never document geometry, camera, resources or queues. Selection/pointer pixels are not persisted document content. `captureContentStructure()` compares exact stage objects and callbacks, excluding these explicit overlays; ordinary insertions or wrappers invalidate it. Built-in preview resource reads also reject unknown passes/backgrounds and incomplete paths, text or images. The host combines these contributors with its exact scene/camera barrier and a live post-callback state check before issuing a certificate.
- **Wrap** a stage with `frame.wrapStage(name, (inner) => ({ name, run: (context) => { …; inner.run(context); … } }))`; the wrapper keeps the name and position, and a wrapper that never calls `inner` replaces the stage. Stages share live references (scene, buffers, backend), so they cannot be moved to another thread one at a time: the engine host (`src/host/`) builds the whole `SceneRenderer` inside the worker (`EngineRuntime`), with a worker-side `SceneSource` (`SceneSourceMirror`) fed by the plain-data change sets it receives.
- **Time** stages through `FrameTimerHook` (`SceneRendererOptions.timers`): the frame calls `stageStarted(name)` and `stageEnded(name)` around every stage, even one that throws. The scene reads no clock (Global Constraint 3); the stage timers (`StageTimers`, below) implement the hook with an injected one and are installed with `installStageTimers(renderer.frame, timers)`, which wraps the stages so they can be removed again at run time. `timeMs` in the context is the caller's frame time. GPU time per pass comes from `SceneRendererOptions.timingLabel` and `collectPassTimings`.
- **Draw differently** with a custom-draw pass (`ScenePass.createDrawer`): for passes that are not one instanced quad per record, such as the path pass's stencil-then-cover fills. The renderer creates the pass's drawer with its instance buffer and the camera uniform, calls `drawer.install(frame)` after `zOrderSegments` is in place (the path drawer wraps `collectChanges` to track paths and inserts `preparePathMeshes` before `draw`, where writes are still allowed), and the `draw` stage hands the drawer each of the pass's draw-list entries (`drawEntry(context, entry)`) instead of drawing its ranges. Records, culling and z-order segments are the scene's as for any pass. `SceneRenderer.hasPendingWork()` tells a frame loop that a drawer has work a later frame would show.
- **Share** per-frame data through the context: `drawList` is written by `cull`, may be rewritten by stages after it, and is read by `draw`; `stats` counts changed objects, buffer writes, uploaded bytes and draw calls.

**Registering a pass.** A pass is a `ScenePass` value listed in `SceneRendererOptions.passes` (default `[SOLID_RECT_PASS, RECT_GRADIENT_PASS, RECT_IMAGE_PASS, ROUNDED_RECT_PASS, ROUNDED_RECT_GRADIENT_PASS, SDF_SHAPE_PASS, SDF_SHAPE_GRADIENT_PASS, SDF_SHAPE_IMAGE_PASS, LINK_PREVIEW_PASS, LINK_ICON_PASS]`; the hosts use `createStandardScenePasses`); passes draw in list order within each z-order segment, and a pass flags with `isOccluder` the objects it paints that must land over later-pass content below them, whatever their alpha (each flag can start a segment). It declares its instance record layout (`resolveInstanceLayout`, `float32…` attributes from `@location(1)` on), its `ScenePipelineSpec` (a generated shader from `src/gpu/shaders/`, per-vertex geometry at slot 0, blending), how many records an object needs (`recordCount`, 0 for objects it does not draw) and how to fill one (`prepare`, pure, called only when the object or an ancestor changes). Every scene pass binds the camera uniform at `@group(0) @binding(0)` as `struct { scale: vec2f, offset: vec2f }` with `clip = world * scale + offset`, followed by `pixel: f32`, one device pixel in world units (32 bytes; a pass may declare only the first 16). The text and SDF shape renderers became scene passes this way.

**Paged passes** (draw calls are bounded by passes times atlas pages times opaque segments). A pass that samples an atlas or textures declares the bindings each page adds after the camera (`ScenePipelineSpec.pageBindings`: its texture, sampler and page uniform), names the page every record samples (`pageOf(target, recordIndex)`, asked right after `prepare` and kept per slot by the scene: `Scene.pagesOf`) and hands over each page's resources (`pageEntries(page)`). The `cull` stage then splits the pass's visible ranges into one draw list entry per page (`splitRangesByPage`, `DrawListEntry.page`), the z-order segments split each segment's entry the same way, and the draw binds the page's bind group (camera plus page entries, built once per page and rebuilt only when the pass names other resources for it), so draw calls stay at most segments × passes × pages. A pass whose shader picks a texture per record (the scene text's page switch) may also declare `pageShaderVariants` and answer `pageSlotsOf(page)`: the draw then binds the first variant covering the page's slots, with a bind group per page and pipeline (the switch costs fragment time with every texture it can reach, whichever the records pick). A page change with no document change (a glyph that landed on another atlas page) bumps the pass's page revision (`Scene.pageRevisionOf`), which re-plans the segments. **Passes with state** (a layout cache, an atlas, a texture manager) are listed as a `ScenePassFactory` and built per renderer with a `ScenePassEnvironment` (the backend, `requestFrame` for work that lands between frames, `now` for work budgets, `text`: the fonts and job pool the text pass lays out and rasterises with, `ledger`, `budget` and `images`: the memory ledger, the device budget and the image pass's catalogue); such a pass adds its own stages (`install(frame)`), rewrites records whose drawing changed without a document change (`Scene.rewriteRecords(passName, targets)`: same record count, only changed records marked dirty), forgets objects the scene drops (`forget(id)`) and frees its resources with the renderer (`destroy()`). `createStandardScenePasses` builds the list hosts render, since passes cannot cross to the worker; each rendering task inserts its pass at its place in that order. A custom-draw pass (`createDrawer`) and a paged pass are separate extensions: a drawer draws its entries itself, a paged pass draws instanced quads per page.

## Frame statistics (stage timers, memory ledger, benchmark export)

The engine records CPU time per stage, GPU time per pass and GPU bytes per category, enforces a byte budget per device, and feeds the same counters to the developer overlay and the benchmark suite.

**Measuring a renderer.** The host creates `new StageTimers({ clock: () => performance.now() })` (the engine core reads no clock itself), gives the draw stage a `timingLabel` (`SceneRendererOptions.timingLabel`) if it wants GPU time, and calls `installStageTimers(renderer.frame, timers)`.

**On an engine host** the runtime does this itself, through a `FrameStatsRecorder`: `host.startFrameStats(capacity)` installs `StageTimers` on the host's frame (clock: the rendering thread's `performance.now()`, `FrameScheduler.now`) the first time and clears the history every time, `host.readFrameStats()` resolves with `createBenchmarkSample` of it, and `host.stopFrameStats()` uninstalls the timers; from a worker the summary comes back as an `engine-frame-stats` message. The benchmark harness (`tooling/bench`) reads it this way, through the app's engine harness. The host's scene pass has the timing label `scene`, so with timestamp queries `passes.scene` is its GPU time (without statistics started the backend keeps at most four frames of uncollected timings on WebGPU, 128 passes on WebGL2, then stops timing).

**Install the timers after every stage has been inserted** (segments, overlay passes): a stage inserted later runs untimed, and one inserted before the first or after the last stage falls outside the frame's CPU time. Installing twice on the same frame throws, changing nothing.

Each wrapped stage reports `stageStarted`/`stageEnded`; the first also calls `beginFrame(context)` and the last `endFrame(context)`, which records:

- CPU ms per stage (two clock reads per stage) and per frame (first stage start to last stage end);
- the frame's counters from `context.stats` (draw calls, uploaded bytes, buffer writes, changed objects) and the records the draw list covers (`visibleRecords`: the records of the objects the R-tree culler found in the padded viewport, one per object and pass for today's passes);
- GPU memory per category, after reporting the scene's own buffers (`reportSceneMemory`);
- when `capabilities.hasTimestampQuery`, a `collectPassTimings()` call right after `submit`, so it returns exactly this frame's labelled passes; the promise resolves frames later and `recordPassTimings(frameIndex, …)` writes the GPU ms into that frame's sample if it is still in the history. When a frame does not directly follow the last one the timers ended (they were just installed, or re-installed after the renderer kept rendering untimed, or the previous frame was abandoned), the backend also holds passes of frames nobody collected (up to 4 frames on WebGPU, 128 passes on WebGL2): that frame's collection drains the backlog and is discarded, so toggling the timers never shows a GPU spike. Without timestamp queries the backend is never asked and GPU times stay NaN (absent from the export). While installed on a backend with timestamp queries, the timers must be its only `collectPassTimings` caller: another caller would take some frames' timings. Pass the timers to `installStageTimers` only, not also as `SceneRendererOptions.timers`, or each stage reports twice.

A frame whose stage throws leaves no sample. `installation.uninstall()` restores the original stage objects, so turning measurement off leaves no wrapper, hook or clock read behind (tested: the stages are identical and a frame reads the clock zero times). It throws, changing nothing, if another wrapper was added on top of a timed stage afterwards; uninstall wrappers in reverse order.

**Cost.** Samples are slots of a ring (`FrameHistory`, 240 frames, one spare slot so the frame being written never overwrites a kept one), blanked and rewritten in place; per-stage and per-pass arrays grow only when a new stage or pass label first appears. A steady frame therefore allocates nothing on the CPU path (with timestamp queries, the backend's promise is one allocation per frame). Measured (`pnpm bench`, Apple M1 Max, a quiet run): a 10-stage frame of empty stages takes about 0.1 µs untimed and 0.8 µs with the timers installed (p99 0.9 µs), so they cost well under a microsecond against a 20 µs budget. `createBenchmarkSample` over 240 frames × 10 stages takes about 0.15 ms (p99 0.3 ms), so the overlay calls it at 4 Hz and never per frame.

**Memory ledger.** Every owner of GPU memory reports its current size with `ledger.set(category, owner, bytes)` when it allocates, grows or shrinks, and `ledger.delete(category, owner)` when it frees; the ledger keeps a running total per category, so the per-frame snapshot is five number copies. Categories and who reports them:

| Category          | Reported by                                                                                                                                                                                                                                                                                                                                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `instanceBuffers` | Now: each scene pass's GPU instance buffer, by pass name (`reportSceneMemory`, from the stage timers).                                                                                                                                                                                                                                                                                                       |
| `uniforms`        | Now: the camera uniform (`camera`, 32 bytes).                                                                                                                                                                                                                                                                                                                                                                |
| `atlases`         | Now: the glyph atlas pages: each text pass reports its own atlas through `ScenePass.reportMemory` (`reportSceneMemory`, from the stage timers), the scene's text as `glyph-atlas` and the frame titles as `frame-title-atlas` (`reportGlyphAtlasMemory(atlas, ledger, owner)`); a standalone `TextRenderer` reports after `prepare`.                                                                         |
| `textures`        | Now: image textures, by the texture manager, which also enforces the `textures` budget of `budgetForDevice`: `image levels` (levels with a texture of their own) and `image atlas` (the pages of small levels and tiles). Video textures when they land.                                                                                                                                                     |
| `meshes`          | Now: the path pass's cached meshes, owner `path`, reported by `reportSceneMemory` from the pass's drawer (`ScenePassDrawer.memory`).                                                                                                                                                                                                                                                                         |
| `layers`          | The layer composite pass's (`LayerCompositor`): each pooled tile target's `width × height × 4` resolved bytes, 32-byte uniforms and, while a target lives, the backend's shared scratch as it allocates it: the live targets' widest width by their tallest height, at 24 bytes a texel on WebGPU and 32 on WebGL2 with 4× MSAA (`layerScratchBytesPerTexel`, C2c). `LayerTargets` charges a target by name. |

The scene's clip table texture is counted under `textures` too, owner `clip-table`, by `reportSceneMemory`. Pass geometry (each pass's small per-vertex buffer) is not counted. The ledger is `StageTimers.ledger`; pass one in (`new StageTimers({ clock, ledger })`) to share it with the owners.

**Benchmark export: the contract with the benchmark harness.** `createBenchmarkSample(timers.history)` summarises the frames the history holds into plain JSON-serialisable data; the harness records one per scripted scenario and compares each number with the reference run (a 10% gate). Changing this shape changes that contract:

```ts
interface BenchmarkSample {
  frames: number; // frames the percentiles cover: the newest min(runFrames, capacity); 0 before the first frame, when every number is 0
  runFrames: number; // frames since the history was created or cleared; frames < runFrames means the percentiles are truncated
  stages: Record<string, { p50: number; p95: number }>; // CPU ms per stage name, frames it ran in
  passes: Record<string, { p50: number; p95: number }>; // GPU ms per timing label, resolved frames only; {} without timestamps
  passFrames: Record<string, number>; // frames whose GPU time resolved, per timing label
  frameWorkMs: { p50: number; p90: number; p95: number; max: number }; // per frame: CPU ms plus the resolved GPU ms of its passes
  memory: Record<
    'instanceBuffers' | 'atlases' | 'textures' | 'meshes' | 'uniforms' | 'layers',
    { bytes: number; peakBytes: number } // GPU bytes at the newest frame, and the most at any frame's end of the whole run
  >;
  p50: FrameCounters; // median of each per-frame counter
  p90: FrameCounters; // 90th percentile of each per-frame counter (the text suite judges p90 and the median)
  p95: FrameCounters; // 95th percentile of each per-frame counter (the maximum when frames < 20)
  max: FrameCounters; // maximum of each per-frame counter over the whole run, however long
  recentFrames: RecentFrame[]; // the newest RECENT_FRAME_COUNT (60) frames one by one, oldest first: stage ms and counters (the frame debug view); not judged
  atlasHitRate?: number; // 1 − Σ atlasMisses / Σ atlasLookups over the frames held; absent without a lookup
}
interface FrameCounters {
  cpuMs: number; // first stage start to last stage end
  drawCalls: number;
  uploadedBytes: number;
  bufferWrites: number;
  changedObjects: number;
  visibleRecords: number;
  blankImages: number; // visible images of assets ready once, drawn without a texture: always 0
  placeholderImages: number; // visible images on their placeholder: nothing of the asset ever loaded
  visibleImages: number; // visible image objects
  segments: number; // z-order segments the draw list formed
  lodTransitions: number; // objects whose level-of-detail form changed
  lodThrashes: number; // of them, objects past two changes of form per threshold crossing: always 0
  atlasRegenerations: number; // glyphs generated again within 8 s of their eviction: always 0
  atlasLookups: number; // glyph lookups made laying text into records, replays of a shared layout included
  atlasMisses: number; // of those, glyphs not at the tier wanted, so requested
  meshRegenerations: number; // path meshes built again within 8 s of their eviction: always 0
  vectorTextRuns: number; // text runs drawn from their outlines, above 512 device px per em
  layersDrawn: number; // layers composited through offscreen targets: at most 16
  layersFallbackSmall: number; // layers in the multiply form for being under 64 device pixels
  layersFallbackLimit: number; // layers in the multiply form past the limit of 16
  layersFallbackBudget: number; // layers in the multiply form to stay inside the layers budget
  layerBytes: number; // what the layers hold: targets, uniforms and the shared scratch
}
```

How the harness uses it: create the timers with `capacity` at least the scenario's frame count (a 10-second drag at 60 Hz is about 600 frames; the default 240 keeps 4 seconds) so the percentiles cover the whole scenario, call `timers.history.clear()` before the scenario (it resets `runFrames`, `max` and the peaks), and read the result after it. `max.cpuMs` is what "no frame over 33 ms during the drag" checks and `memory.*.peakBytes` what "never exceeds the budget" checks; both cover the whole run whatever the capacity. Read GPU times only through the history or this export, never by calling `collectPassTimings` yourself: the installed timers own it.

Percentiles are nearest-rank (an observed frame, not an interpolation); with fewer than 20 frames the p95 is the maximum. The developer overlay in `@canvas/app` shows the same value, read at 4 Hz.

## Shaders

`parity-triangle.wgsl` is the backend parity scene's pass; `layer-composite.wgsl` composites a render target at an opacity; `dot-grid.wgsl` is the dot grid (`GridBackground`, `src/scene/grid-background.ts`); `sdf-shape.wgsl` is the SDF shape pass (`src/shapes/`); `msdf-text.wgsl` is the text pass (`src/text/renderer/`); `path.wgsl` is the path pass (`src/paths/`). The gradient variants `sdf-shape-gradient`, `path-gradient` and `rect-gradient` have no `.wgsl` of their own: `scripts/gradient-shader.ts` derives each at build time from its solid source (`sdf-shape.wgsl`, `path.wgsl`, `solid-rect.wgsl`), adding the paint table at `@group(0) @binding(1)`, the paint-table record as instance attribute 8 and `paintAt` (the WGSL statement of `paintColorAt`, premultiplied), and changing only the fill colour's source, so the SDF, coverage and placement can never drift from the solid shader; their retained-move variants come from `move-shader.ts` as the solid ones'. Frame clipping: the six scene shaders (`solid-rect`, `sdf-shape`, `image`, `path`, `scene-text`, `frame-title`) read their record's clip index at `@location(14)`, call `clipVertex(world, clipIndex, camera.pixel)` and multiply their premultiplied output by `clipCoverage(...)`; `scripts/clip-shader.ts` includes the clip table at `@group(0) @binding(5)` and both functions before their vertex input at build time (so the gradient and move variants clip alike), and fails the build if a scene shader drops either call. Coverage is `clamp(0.5 − d / pixel, 0, 1)` of the largest box distance over at most 8 clipping frames (the first two from interpolated frame-local points, the rest mapped up the table); it is multiplied, never `discard`ed, so the path pass's stencil operations still run where a fill is clipped. On WebGL2 the table is sampled in both stages (`_group_0_binding_5_vs` and `_fs`, both on texture unit 5). WGSL is the single source (`src/gpu/shaders/<name>.wgsl`, entry points `vertexMain` and `fragmentMain`). `pnpm --filter @canvas/engine shaders` (run by `build`) transpiles each one with naga, compiled to WebAssembly (`naga-wasm`, so no Rust toolchain), and writes next to it `<name>.vert.glsl` and `<name>.frag.glsl` (GLSL ES 3.0, committed for review) and `<name>.generated.ts`, which exports the `GpuShaderSource`. Generated files carry a header, are excluded from ESLint and Prettier, and are marked `linguist-generated`. Commit them with the `.wgsl` change: `pnpm --filter @canvas/engine shaders:check` regenerates in memory and fails on any stale output, and it runs as part of the engine's `lint` (so `pnpm check` catches a stale commit) and as a unit test (`scripts/shader-build.test.ts`); `pnpm test:golden` builds the engine, which regenerates them.

## Design notes

- **Layer visibility**. A layer stored `isHidden` and everything inside it never reaches the scene: `InstanceExpansion` leaves it out as it leaves out a retired main (`ShownObjects`), and re-evaluates the subtree when the flag flips. An instance draws a main's hidden child only where a record says `isHidden: false` (`resolveInstance`), without the main's flag.
- **Layer opacity, multiply form**. A layer's `opacity` multiplies into everything it holds: `SceneOpacity` gives each object its own opacity times every ancestor's (groups, frames, mains and instances, worked out once per `Scene.apply`; an instance that sets none shows its main's, handed down by the expansion as a main's colour mode is, `withMainOpacity`), and every scene record carries 1 minus it as its trailing float (`InstanceLayout.opacityFloat`, `@location(12)`), which every scene shader multiplies into its coverage with the clip's (`clipCoverage(local, frame, alpha)`, `scripts/clip-shader.ts`). An image's record multiplies its own opacity already, so its transparency is its ancestors' alone. A frame's name never fades (at opacity 0 it is hidden with its frame: C2b). Absent opacity writes 0 and multiplies by exactly 1, so an opaque board draws exactly as before. A faded path layer leaves the opaque route for the stencilled one (`isOpaquePathLayer`), so its overlapping triangles do not blend twice. Opacity 0 draws nothing and stays hittable. This is exact for one record; overlapping parts of a container or a multi-part leaf would each blend over the other, so with the layer composite pass those draw in layer form (C2b, next).
- **Layer opacity, layer form** (`src/scene/layers/`, `src/scene/segments/layer-planning.ts`). With the standard passes, an object whose own opacity is below 1 and that is a group, frame, main or instance, or a multi-part leaf (a shape with a label or a drop shadow, a sticky, a path with a fill and a stroke, a labelled connector), is in layer form (`isLayerForm`): its parts draw opaque into an offscreen target and composite once at its opacity, so overlaps never double up. Every other translucent object keeps the multiply form, exact for one part. **Records.** `SceneOpacity` is relative to the nearest layer: a record's multiplier stops at its nearest layer-form ancestor, and a layer-form object's own opacity is left to its composite, so nothing multiplies across a layer's boundary. **Planning.** The layer composite pass gives each layer-form object one record holding its opacity, drawn after its descendants (a closing paint rank) and flagged as an occluder. When a board has layers or objects at opacity 0, the z-order segments plan in layers (`planLayeredDraws`): each visible record goes to the innermost layer whose ranks (its own to its closing one) hold it, objects at opacity 0 and everything under them go nowhere, frame names included (they stay in the spatial index, so they hit), and passes drawn outside layers (`ScenePass.isOutsideLayers`: frame names, which never fade at partial opacity) stay on the canvas. Each layer, innermost first, is planned as a rank window of its own, with its visible children's composites in place of their content; the canvas is planned last with the outermost composites, each composite's rank taking its layer's box. The draw list holds the windows' entries first, tagged with their layer (`DrawListEntry.layer`), then the canvas's, and `FrameContext.layers` lists the layers drawn (`LayerDraw`). A layered plan re-plans whenever coverage or the fallbacks change, and when objects move under a plan merged by boxes; a kept plan re-measures its layers. Since C2c it re-plans incrementally (`LayeredPlanCache`): the windows' layout (`structureOf`) is kept while the tables and fallbacks stand; their visible records (`LayeredCoverage`) are kept too, the culler's coverage change routed to the windows it touches revision by revision, and on a change of fallbacks the slots of the ranks that change window are moved (`reownSlots`); a layer window is planned again only when its records, its children's composites (slots and bounds), its ranks, or a member's box or level-of-detail form changed; the canvas keeps its plan when only objects that break none of its merges moved (`isCanvasPlanKept`: as `checkMovedObjects`, with layer members as their composite and the composites' bounds counted), and is patched by its own interval cache (`SegmentWindows`, fed the canvas's share of each change, composites added and removed included) when only its records changed. A test checks that draw order and records equal a fresh renderer's after moves inside and across layers, coverage changes and form flips (`layered-incremental.test.ts`). A board with nothing translucent has no layer record and takes exactly the old path: the same ranks, plans, passes and uploads. **The `layers` stage**, last before `draw`, has the pass's drawer (`LayerCompositor`) work out each layer's rectangle (its members' boxes under the camera, rounded outward plus a pixel, cut to the canvas or its parent's rectangle: `layerDeviceRect`), its targets (C2c: pooled, below) and its composite uniforms, all before any pass opens; then it renders each window into its layer's target with the camera moved to the rectangle (`layerCamera`; the camera uniform is shared, so it is written back for the canvas). Composites are drawn by the composite pass's entries wherever they fall: a nested layer's in its parent's target pass, outermost ones in the canvas pass, each placed by its uniform's clip rectangle (`layerCompositePlacement`) without touching the pass's viewport. Hit testing is unchanged.
- **Layer opacity, bounded** (`src/scene/layers/`, `src/scene/segments/segment-layer-fallbacks.ts`). Each layered frame, the z-order segments ask the layer composite pass's drawer which layers fall back to the multiply form (`LayerSelection`), from the layers' bounds (`layerCandidatesOf`: the union of each layer's members' boxes and its depth, measured from scratch only when the paint order, the slots, opacity 0 or a drawing bound changed, and otherwise only for the layers holding or held by what moved, `remeasureLayers`; the plan reuses them). A still frame chooses nothing again (the same candidates, camera and held targets give the same choice); each layer's form is kept by its index while the candidates keep their order, and a choice names only the layers whose form changed, so a board of tens of thousands of layers costs a typed-array pass per camera change and work only for what changed. **Small**: a layer whose content is under 64 device pixels on its longer edge falls back, with a band remembered per layer (the level-of-detail band's 20% on both sides: a composited layer falls back under 51.2 px, a fallen-back one composites again from 80 px), so a slow zoom never alternates. **Limit**: of the rest on the canvas, at most 16 composite, the outermost first, then the larger content area in device pixels, then the lower id, with a band (`limitOrder`): a layer that composited last frame keeps its slot while it stays on the canvas, or within the view's own size of it, and within the budget; a newcomer takes a free slot, or the weakest one's when it is outer or at least a quarter larger (`LAYER_LIMIT_MARGIN`), so a pan or zoom that wobbles layers across the canvas's edge swaps none, and a cold start chooses by the order alone. **Budget**: within the limit, one whose targets (its bucketed tiles, or the larger targets it keeps) would take the layers past their share (`budgetForDevice`'s `layers`, 48 MiB on a desktop; the scratch counted first) falls back, and composites again only with a fifth of the targets' share to spare (`LAYER_BUDGET_BAND`); a smaller one after it may still fit. A layer off the canvas keeps its last form, so a pan changes nothing for it. Each fallen-back layer counts once, under the first reason (`FrameStats.layersFallbackSmall`, `…Limit`, `…Budget`; `layersDrawn` and `layerBytes` beside them). **Fallback is the multiply form**: `Scene.layerOpacity` marks the layers, so `SceneOpacity` no longer stops at them, and rewrites only the trailing transparency of each changed layer's records and its descendants' (from the hierarchy and the opacities kept of translucent objects, no document read); those records upload before any pass opens. Small and over-limit fallbacks leave the plan: the frame plans in full without them, so their content joins their parent's window or the canvas and batches with it (their form changes rarely). Budget fallbacks, which follow every zoom near the budget's edge, stay planned: their windows draw in place of their composites, into whichever pass draws the composite (`LayerDraw.isInline`), so a budget decision never costs a re-plan, and there are at most 16. A composite multiplies its opacity by its ancestors' drawn in the multiply form up to the nearest layer that composites. Nothing disappears, and a layer composites again the same way. A board with nothing translucent never asks. **Tiles**: a layer wider or taller than a tile (`layerTileEdge`: 1024 px, halved while its scratch would take more than three quarters of the budget, so 512 px on a phone) is cut along the canvas's grid of tiles; each tile renders the layer's window with its own translated camera into a target of at most a tile and composites on its own, edge to edge on whole pixels with its neighbours, and a nested layer composites into each tile of its parent it overlaps, so the backends' shared scratch never exceeds a tile. **Pooling**: targets are tile rectangles rounded up to 64 px buckets (`LayerTargetPool`); a tile keeps the target it drew into last while that holds its bucket within four times its area (so a zoom out, or back in, makes nothing), else takes any free one of its bucket, else a new one; a target or uniform no frame used for two seconds is freed, idle ones first when the pool is over budget. A composite uniform is written only when its values change, so a still frame uploads nothing. **Memory**: `layers` holds the targets' resolved colour, the uniforms and, while any target lives, the scratch at its actual size: the pooled targets' extent (`LayerTargetPool.extent`, as `RenderTargetExtent` sizes it) at the backend's bytes per texel (`layerScratchBytesPerTexel`: on WebGPU colour and `stencil8` per sample plus a resolve, 24 at 4× MSAA; on WebGL2 colour and depth-stencil per sample, 32), so a large layer is not pushed into the budget fallback by bytes the backend never allocates. The selection charges the scratch the same way, at the chosen targets' extent (and any larger target a layer keeps); the tile edge is still chosen at the worst rate.
- **Frame clipping**. A frame with `clip: true` clips its descendants, never its own fill, stroke, shadow or title; nested clipping frames intersect, groups pass clips through, and overlays (selection, handles, guides, presence) are not scene passes and are never clipped. Clipping is analytic per fragment rather than stencil or scissor: scissor cannot turn with a frame and splits batches, and the stencil is the even-odd path fill's. Every scene record ends with its clip index (`resolveSceneInstanceLayout`), the slot of its nearest clipping ancestor in the scene's `ClipTable`, worked out with `clipChainOf` (innermost 8, the shaders' cap) once per `Scene.apply`; the table holds each clipping frame's world box and a float64 map into its clipping ancestor's frame. Batching is unchanged, and moving a frame, which already rewrites its descendants' records, adds only that frame's four texels to the upload. **Rounded clips**: a frame's `cornerRadius` rounds its clip; its record carries a rounded flag and four capped radii, and the shaders' `clipBoxDistance` level becomes the exact rounded-box distance (`clipRoundedDistance`, each corner its own radius) only for rounded clips, so sharp clips compute exactly what they did; nested rounded clips intersect as boxes do. `isInsideClipChain` and `clipCoverageAt` mirror it on the CPU; `clipPolygon`, `clipSegment` and `clipBounds` still cut by the box, which errs large by the corners for culling and the marquee. Component instances and the worker's mirror resolve clips by the same ancestor walk (their virtual frames carry `clip`). CPU culling and hit testing read the same chains: `SceneSpatialIndex` indexes each object's box cut by its chain (`clipBounds`, the turned box of a turned object; label and title drawing bounds alike) and leaves out an object nothing is left of, which `SpatialCuller` then never draws (the whole-buffer shortcut waits until there are none) and a moved one never breaks a segment plan (`isClippedAway`); `hitPoint` hits a candidate only where `isInsideClipChain` holds, and `hitRect` tests the clipped polygon and centre-line pieces, so hidden overflow is never hit or marquee-selected and `contain` needs only the visible part inside; the select tool's frame title bands follow the same chains. The clip table texture counts towards `textures` in the memory ledger (`CLIP_TABLE_OWNER`). `clipCoverageAt` is the coverage the GPU applies.
- **Hostile stored values**. Commands refuse NaN, infinities and places past the board's bound, but a client with an editor token can write raw values the codec accepts by type. The engine judges each object once when it changes, never per frame: the `SceneRenderer` passes every change set through a `DrawableGate` (`undrawableReasonOf`), so the scene, every pass (shapes, images, paths, text), level of detail, the culler's index and the z-order segments see an undrawable object as deleted; the app's hit-test feed does the same, so hit testing, marquees, snapping and zoom to fit never meet it. Its children are undrawable too, since their place on the board cannot be worked out. Each is reported once per change in `EngineFrameReport.undrawable` (a host may show it; the app shows nothing yet). Nothing in the document is repaired or removed: the object stays selectable by id (select all, the layers panel) and deletable. The rule is float32's, not JavaScript's: a colour of 1e39 is finite in JavaScript and infinite in an instance buffer, so colours, opacity and crop are held to [0, 1], `sides` to 3-64 (the CPU walks that many vertices per hit test and label fit), strokes to 64, font sizes to the schema's 4-400, natural sizes to whole numbers from 1 (a fraction lets the image fit's aspect underflow to NaN), runs to at least one covering the text (the layout walks them and throws without one), and every other number to float32's range (fix rounds 1 and 2). A select-all drag previews every moved frame each frame: the gate re-judges the moved frames only, answering for their unchanged subtrees with a kept hull, so a preview frame costs O(moved objects) (fix round 2; measured below). Any future export of the board as an image (PNG, SVG or PDF, not built yet) must read the document through a `DrawableGate` as the renderer does. The index also refuses any box that is not finite, a last line of defence. Judging costs about 0.4 µs an object (a 50k-object board's first change set about 65 ms per gate, the subtree hulls included: building them adds about 7 ms at 10k objects and 15-20 ms at 50k per gate, and there are two gates, the renderer's and the app's hit index; accepted, fix round 3). Measured with `bench:ci`'s normal repeats on the 10k select-all drag (`drag-selection`, one warm-up and three 10 s repeats, Apple M1 Max, webgpu), against main at `586c683c`: frame CPU p50 76.05 ms against 77.78 (p95 80.56 against 82.19), the gate's stage (`applyChanges`) 0.38 ms against 0.13, so +0.25 ms a frame, a preview frame moving 500 frames over 50k objects about 0.4 ms, and nothing on a frame without document changes.
- **Gradient fills and theme-aware ink**. Solid fills keep their passes, records and shaders: a gradient-filled shape, path or frame background is drawn instead by the gradient variant listed right after its solid pass (`SDF_SHAPE_GRADIENT_PASS`, `createGradientPathPass`, `RECT_GRADIENT_PASS`), each its own scene pass, so the z-order segments order it against every other pass by z (an interleaving costs a segment boundary, never a per-object draw); a board without a gradient gives the variants no record and allocates no paint table. A variant's record is its solid pass's plus one float, the object's record in the renderer's `PaintTable` (11 texels each, written when the paint changes, uploaded by dirty records before `uploadDirtyRanges`; a camera-only frame uploads nothing); its fragment shader evaluates `paintColorAt` (premultiplied, padded, at equal offsets the later stop) at the fragment's point of the object's unit box (`paintBoxOf`: a shape's or frame's `(0, 0)–(width, height)`, a path's network bounds, an axis of zero extent at 0.5). Below 8 device px (`GRADIENT_LEVEL_OF_DETAIL`; a path in its chord form) a gradient draws its average colour (`paintAverageColor`) through record 0, without reading the table. `isPaintedShape` counts a gradient fill as painted when any stop's alpha is above 0 and an `'ink'` outline as alpha 1; a frame background's gradient is flagged when any stop is visible. The engine has no separate opaque-occluder optimisation beyond these flags, so `isPaintOpaque` has nothing to gate yet. **Ink** is resolved on the CPU: the scene hands every pass the viewer's ink colour with each object (`SceneObject.ink`, from `SceneRenderer`'s `theme` and `inkColors`), and passes write it for `'ink'` wherever a colour enters a record (shape outlines, path, line and connector strokes, glyph runs, greek bars, shape, connector and sticky labels); the layout keeps the token, so it is theme-free. The scene keeps the last applied target of each object drawn in ink (`usesInk`); `setTheme` rewrites only those objects' records from them, in one dirty-range pass, with no document read, text layout or path mesh (about 6 ms of CPU for 10k ink strokes, `paint.bench.ts`). **Reader tolerance**: the drawable gate judges a tuple's channels as before but never refuses an object for its paint or an inkable colour; a gradient the schema refuses (`paintReason`) draws as no fill (the outline and label still draw), and a stroke or text colour that is neither a tuple nor exactly `'ink'` draws in the base colour (`readFill`, `readInkable`).
- **Colour tokens and colour modes**. Tokens are resolved on the CPU, as ink is, and no shader or record layout changed. A `ColorPalette` is one colour mode's values of the board's token table with the host's ink colours (an edited `ink` entry wins over `inkColors`; a token the board lacks draws as ink); the scene builds one per mode for each table and theme and hands every pass the object's palette (`SceneObject.palette`), and every colour read resolves through it: `readFill` and `readSolid` (shape, path and sticky fills, frame backgrounds), `drawnColor` (outlines, path, line and connector strokes), `glyphColorOf` (glyph runs and greek bars; the layout keeps `'ink'` and `{ token }` as given, so it is mode-free). Whether there is a fill never depends on a token's value (`isPaintedShape`, the path layers, hit geometry: a token fill is a fill). **Modes**: `ColorTargets` keeps each object whose colours name `'ink'` or a token (`colorTokensOf`), with its fixed mode: the nearest ancestor-or-self frame, main or instance with a `colorMode`, walked through the scene's source (virtual content walks its virtual parents to its instance), else `colorModeFallback`, else none (the viewer's theme). An instance that sets none is shown by `InstanceExpansion` with its main's mode (`withMainColorMode`; the main may be on another page, or unreadable in a worker), and `mainKey` includes the main's `colorMode`, so a main's mode change re-resolves its instances. A theme switch rewrites the kept objects in the viewer's mode; a token edit (`setColorTokens`) those naming a token whose light or dark value changed; an ancestor's `colorMode` change needs nothing more, since the scene refreshes descendants. **The table reaches the engine** by its own call, not in the change set: `EngineHost.setColorTokens(table)` (the main-thread host to its runtime; the worker host as a `tokens` command with the whole table, `serializeColorTokens`), kept by `RuntimeView` for an assembly rebuilt after a lost device. The app's `DocumentSceneFeed` sends the board's table (`readTokens` of the whole-board store) on attach and after every change set naming `tokens`. A fallback hook is a function, so it cannot cross to the worker: it is a `SceneRendererOptions`/`SceneOptions` option for a renderer built on its own thread. **The frame-fill rule** is therefore a built-in chosen by name, `colorModeFallback: 'frame-fill-luminance'`, which `EngineHostOptions` carries to the worker (`RuntimeView` keeps it for a rebuilt assembly) and which the app's host and the snapshot service's render page both select. `ColorTargets` collects the fills of the ancestors it walks for an explicit mode and asks the schema's `frameFillModeOf`; a frame's fill edit, or a reparent, refreshes its descendants through the scene as any ancestor change does. When a fill behind the object is a token, its fills are kept (`FrameFillBackdrop`) with the tokens it named and whether it resolved one in the viewer's theme, so a token edit, a theme switch or an ink change (`setInk`, new `inkColors`) works the mode out again without reading the document and rewrites the objects whose mode moved. A token fill is judged in the colour the frame is drawn in: the scene's token table, its ink colours for an unedited `ink` token and for a token the board lacks, and the frame's own mode. An opaque fixed fill nearer hides the fills above it, so content under one keeps no backdrop; only the kept objects with a backdrop are visited. Cost (`color-mode-fallback.bench.ts`, 50k ink shapes in 50 nested filled frames, against the same board without the rule, through a fake backend): a frame's fill edit re-resolving its 1,000 descendants costs what it costs without the rule (about 5 ms), a theme switch costs less (content in fixed-fill frames keeps its records), and an edit of the token half the frames are filled with rewrites only the 12,500 records whose mode moves (about 30 ms, once per edit); `color-tokens.bench.ts` is unchanged within noise. Cost (`color-tokens.bench.ts`, 50k shapes, 45k naming tokens, through a fake backend): a token edit nothing names rewrites nothing (about 3 ms to check the kept objects); an edit of a token 15k records name, or a theme switch rewriting 30k, costs what rewriting that many records costs, as an ink theme switch does (tens of ms on a laptop, once per edit), and no frame after it uploads anything.
- **The dot grid** is the `draw` stage's background (`GridBackground`), not a scene pass: it has no objects and its cost must be the camera's alone. One quad covers the canvas and the fragment shader lights the pixels within a dot's radius (1 CSS px, times the dpr) of the lattice, antialiased over the last pixel. Everything is in device pixels: the CPU reduces the camera to the lattice's phase (the world origin's position modulo the spacing, in world units first, so a pan to a billion units keeps full precision) and passes it with the canvas size and the spacing; the pixel position reaches the fragment shader as an interpolated varying, since `@builtin(position)` and `gl_FragCoord` run y opposite ways on the two backends. The spacing is `gridSpacingAt(zoom)`, a power of two, so dots stay 16–32 CSS px apart and every coarser grid's dots are a subset of a finer one's. A frame with the same camera writes nothing; a hidden grid writes and draws nothing. **Zoom fade:** the dots are fully visible at and above 25% zoom (`GRID_FADE_FULL_ZOOM`), fade over one octave down to 12.5% (`GRID_FADE_HIDDEN_ZOOM`, one doubling of the spacing) along a smoothstep (`gridOpacityAt`, slope zero at both ends, so a zoom sweep never pops; half at 18.75%), which scales only the uniform's alpha, and at and below 12.5% the grid writes no uniform and issues no draw call while it stays shown. Snapping does not read the fade: it uses `gridSpacingAt` and the person's grid preference at any zoom. The engine host shows it with `setGridVisible` (a `grid` command to the worker); the golden scenes `grid-background`, `-zoomed-in` and `-zoomed-out` render it at 100%, 300% and 25% on a 2× display, and `-light` over the light canvas; `-fading` at 18.75%, inside the fade band (half-strength dots), and `-faded-out` at 10%, below it (no dots). The dots are one fixed grey at half strength (`GRID_DOT_COLOR`): the engine holds no theme tokens, and the host clears to transparent over the theme's background, so the same grey reads on the light and the dark canvas. The uniform is rewritten in one kept array only when the camera changes, so a still frame allocates nothing.

The entry, `src/index.ts`, holds only re-exports; the text, workers and engine host areas keep theirs in `src/text/text-api.ts`, `src/workers/workers-api.ts` and `src/host/host-api.ts`, which it re-exports whole, so the entry stays under the 400-line limit as the areas grow.

The engine core compiles without the DOM lib. Only `src/gpu/` may use browser GPU APIs: it is a separate TypeScript project (`src/gpu/tsconfig.json`) that adds the DOM lib and `@webgpu/types`, so a DOM global anywhere else fails `pnpm typecheck` (Global Constraint 2). The `GpuBackend` interface files themselves use no DOM types (only `GpuCanvas` and `createGpuBackend` do), so renderers outside `gpu/` can be written against them. Likewise `src/workers/web-worker/` is its own project with the WebWorker lib, and is the only place that touches `Worker`, `postMessage` and `Transferable`. And `src/host/web/` is its own project with the DOM lib: the engine host's browser platform (animation frames, `performance.timeOrigin`, `transferControlToOffscreen`, `createGpuBackend` for either canvas).

**Scene graph** (most frames upload nothing; replaces the prototype's per-frame rebuild in `webgl-whiteboard/src/render/renderer.ts` and `src/app/controller.ts`). The `Scene` mirrors the document through `SceneSource`, never importing `@canvas/document`:

- Each pass owns one persistent `InstanceBuffer` (a `Float32Array` with the pass's fixed record stride) and one GPU vertex buffer of the same size. An object holds zero or more slots per pass; slots come from a free list before the buffer grows, and grow by doubling (the GPU buffer is then replaced and its used range written once). A released slot is zeroed, which draws a zero-size instance, so the draw range `[0, recordCount)` may have holes.
- `Scene.apply(changes)` reads every listed id through `changes.get`: present means create or update, absent means remove, so a coalesced change set is correct whatever happened in between. It then rewrites the descendants of every changed object, found through a child index, because an object's world transform composes its ancestors' (the schema's frame convention: translate by `x`, `y`, then rotate about that point). A record is marked dirty only when its values change, so an edit a pass does not draw (a `z` key, a lock) uploads nothing.
- Dirty slots are coalesced per frame into ascending `[start, end)` byte ranges, merging adjacent records and bridging gaps of up to 256 bytes (one `writeBuffer` costs more than re-sending a few clean records). Uploading writes exactly those ranges; a frame with no change and the same camera writes nothing, and a camera-only frame writes the 32-byte camera uniform alone (the tests count backend calls).
- The camera is a value (`x`, `y` are the world point at the viewport's top-left corner; `zoom` is CSS px per world unit). Shaders get `clip = world × scale + offset`, so large world coordinates lose some float32 precision far from the origin; a camera-relative origin can come with the zoom sweep work.
- Draw order is z order, through `ZOrderSegments` (below); culling is the R-tree's (`SpatialCuller`, below).
- Measured (`pnpm bench`, Apple M1 Max, fake backend): a camera-only frame at 10k objects takes about 0.5 µs of CPU (budget 1 ms); applying and uploading a 100-object change takes about 0.05 ms (adjacent slots) to 0.12 ms (scattered).

Settled path draws retain only the last frame's resolved layers and exact entry/range snapshots.
They replay through the same path encoder with identical stencil and backend commands. Document,
instance, mesh, LOD, bucket, viewport or entry-boundary changes clear that cache, as do late dirty
writes, buffer replacement and an invalidation after preparation captured its reuse decision.
Pending/stand-in work keeps the original resolution loop; mesh drop and renderer destruction
release every retained layer reference. This removes repeated owner/mesh/alpha lookups, not draw
calls, and still allocates frame cursors, snapshots when changed and per-entry encoders.

**Z-order segments** (draw calls are bounded by passes times atlas pages times opaque segments; from the prototype's `webgl-whiteboard/src/render/segments.ts`, `renderer.ts` `beginSegment`). Passes draw in registered order, so without segments all text would draw over all notes. `ZOrderSegments` (`src/scene/segments/`) is a stage after `cull`:

Interval bookkeeping is lazy: a full plan retains copied delta cursors and its move-check tables;
only a validated coverage delta builds the interval graph. Each interval counts unique owned
slots (excluding free bridges), but creates its removal maps and per-rank arrays only when a
record leaves that interval. Passes absent from its retained entries keep revision cursors but
allocate no removal map or rank-count array. Passes with at least 256 slots and averaging more than eight slots per draw
range index first ownership as sorted intervals plus sparse departures; fragmented passes retain
the slot map. Both representations require the same stable ownership tables, and table changes
force full planning before reuse. `windowCounts` distinguishes graph/window construction and local
removal initialization from patch work. The first eligible patch still pays interval discovery;
unchanged frames and invalid cursors avoid that work. This does not imply zero allocations:
full-plan inputs, cached plan objects, cursor snapshots and diagnostic snapshots still allocate.
Routing coalesces adjacent changed slots within each pass and interval without crossing free or
hidden slots. A run inside the current paint-rank interval reuses its routing destination;
a different interval triggers a fresh lookup, including backward slot/rank order. Broad-change
fallback still counts records, independent of range compression.
A patch is refused when it would cost more than the full plan (`segment-patch-guard.ts`),
on boards with at least 1024 live records (`SegmentWindowOptions.minGuardedRecords`). Before the
first patch builds the interval graph, the delta's eligible slots are counted without routing:
an entering half of the live records is a wide fallback, and a delta touching a quarter of them is
a `costFallbacks` refusal, since the whole-board graph costs about as much as the plan. Once the
graph exists, a removal that would build removal state for half the live records is refused too.
Under zoom churn, each patch otherwise followed a fresh full plan and paid the graph again.
Page, drawing-box and level-of-detail changes patch too (`segment-touches.ts`): a paged
pass's slots whose page changed (its page table diffed against the last plan's), the slots of the
objects whose drawing boxes changed (`DrawingChangeLog`) and those of text shown again are routed to
their intervals as leaving and entering, so each is planned again from current tables. A retained
move's begin and end, and hiding, still plan in full: hiding lets the segments around merge, which
keeps a far view of many notes a few draws.

- **Paint order.** The board paints depth-first: a parent before its children (a frame's background under its contents), siblings by `z` compared by UTF-16 code units, ties by id (`compareStacking`, `paintOrderOf`). The engine may not import `@canvas/document`, so the rule lives in `@canvas/schema` (`compareSiblings`, `compareKeys`) and both packages use it from there; `sibling-order-agreement.test.ts` feeds one fixture of keys and ids through the schema's comparator, `paintOrderOf` and the pick order (`sortTopmostFirst`) and checks they agree. Objects whose parent is missing paint at the root; parent cycles paint last.
- **Segments.** Walking the visible objects in paint order, each visible flagged object (`ScenePass.isOccluder`: notes, painted shapes at any alpha, frame backgrounds, images; not text or lines) starts a segment; within a segment passes draw in registered order, so an occluder covers everything before it whatever pass drew it, and everything after it in its segment draws over it (a note's own text included). This is the prototype's semantics: within a segment, objects of different passes are not z-ordered against each other (text over a later outline-only shape, say). Adjacent segments merge when splitting changes nothing: when every pass of the first comes no later than every pass of the second (stacked notes, or a board of filled shapes in one pass, stay one segment), and, given object boxes, when no object of the second meets an object of the first that draws in a later pass than its own lowest (drawing both segments pass by pass differs from drawing their union only where a record of the second meets a later-pass record of the first). `SceneRenderer` gives the stage its `SpatialCuller`'s index (`ZOrderSegmentsOptions.spatial`), so a note with text that covers no text before it shares its segment rather than starting one; `assignSegments` buckets the segment's boxes on a uniform grid (`SegmentOverlapGrid`, about √n cells a side, filled only once a query needs it) and tests each object of a split against the cells its box covers, errs large (boxes as the index holds them, a note's dropped shadow included; touching edges count; an object without a box meets everything), and so never changes what is drawn, only how many segments draw it. A plan that merged by boxes holds only while its objects stay apart, so each frame's moved objects (with everything under a moved frame) are looked up in the index at their new boxes (`checkMovedObjects`), and the plan is re-made only when one now meets content a merge relied on missing: twenty collaborators moving rectangles through a zoom sweep cost an index search each, not a re-plan (a re-plan at 0.05× on the 50k board is about 20 ms through a fake backend, with or without boxes). Past `MAX_CHECKED_MOVES` (256) moved objects in a frame, a whole selection dragged, the stage plans by passes only, which no move can break, and plans by boxes again in the first frame where nothing moves. The output is one `{ passName, ranges }` entry per segment and pass with visible records (per segment, pass and page for a paged pass), so draw calls are at most segments × passes × pages when slots are in paint order.
- **Level of detail** (generalised by; below). Records a pass leaves out at this level of detail (the `hidden` form, `LevelOfDetail.hiddenIn`: a note's, a text object's or a shape label's text whose lines would be under 2.5 device pixels) are left out of the culler's ranges and of the plan (`PlannedPass.isHiddenByRank`), so they neither draw nor split segments: at far zoom a board of notes with text is a few segments, not one per note. The stage re-plans when an object is hidden or shown (`LevelOfDetail.hiddenRevision`), which with each object's 20% band is not on every frame of a pinch near a threshold.
- **Known limit.** Within one segment the text pass draws after the path pass, so a pen stroke drawn over a sticky note (in the note's segment, since a stroke is no occluder) falls under the note's text. Making a stroke over a note draw above its text needs the stroke to start a segment of its own, or a change of pass order.
- **Slot order.** Records live in slot order, not paint order. Within an entry records draw in paint order (rank, then record index, so a note's shadow stays under its fill), coalesced into ranges of consecutive slots; free slots between them are bridged (they are zeroed and draw nothing), culled ones are not. A board built by appending keeps each entry one range; an object reordered or re-slotted after its neighbours splits a range, up to two extra draws each. A compaction pass that re-slots buffers in paint order when fragmentation grows is future work.
- **Cached page partitions.** The cull stage keeps one page partition per pass and scene. It compares an independent snapshot of range values, so custom cullers may reuse mutable arrays, and invalidates on page-table identity or revision changes. An unchanged camera frame checks ranges rather than every paged record; asynchronous glyph/image page changes still invalidate the partition.
- **Caching.** A `ZOrderMirror` sees every change set (the stage wraps `collectChanges`) and marks what went stale: a `z` key, a parent or a create/delete rebuilds the paint order, except objects created above every other (a stroke committed, a sticky placed: childless roots without closing ranks at the end of the root list, on an order last walked from its roots), which are appended to the paint order, the occluder and rank tables and the slot owners (patched) at the cost of what was created (`refreshOrder`, `paint-order-tables.ts`), and leaf objects created, deleted, reparented or restacked anywhere (a sticky placed or a stroke committed in a section; `ZOrderMirror.editedIds`, at most `MAX_ORDER_EDITS` a frame, none with children or a closing rank), which are spliced into the order in one pass of typed arrays (`editedOrder`, `order-edits.ts`), every table indexed by rank moved through the same shift (`RankShift`: the rank indexes, which key each object to a handle so a shift writes an `Int32Array`, not a map, `RankIndex`; the hidden tables; the slot owners, then patched for the edited objects), at about 4 ms instead of a 22 ms walk on a 50k board with one pass (`PaintOrderState`); a record-count change rebuilds only the slot owners (O(objects × passes)); an occluder flip only the occluder table; any of them, a change to an object's minimum scale, the camera crossing a minimum scale, or different visible ranges from the culler, re-plans (O(v) table reads over the visible records and O(s log s) over their spans, an object's consecutive records on one page, with no sort when slots are already in paint order: per span, not per record, since a zoomed-out ratio-2 screen keeps about four times the greek glyph records of a ratio-1 one). A camera move with the same visible set re-plans nothing, nor does a drag unless it breaks a merge made by boxes (`counts`, asserted in the tests; `segmentCount` is the last plan's segments). The stage refuses to draw if it was installed after the scene applied changes, since objects it never saw would have no rank.
- **Incremental sibling order.** The mirror keeps every parent's children sorted (`SiblingLists`, `sibling-lists.ts`): each created, moved, reparented or deleted object is placed by binary search with the schema's `compareSiblings` and one splice, so a paint-order rebuild is a walk of already sorted lists (`paintOrderOfSiblings`, O(n)), with no sort; objects under a missing parent or in a parent cycle are sorted when found, as `paintOrderOf` does. A test checks that 20 seeded runs of 200 random creates, moves, reparents (to missing parents too) and deletes give the same order as `paintOrderOf` after every step. Bringing one of 50k root siblings to front (`paint-order.bench.ts`, Apple M1 Max): 1.2 ms for the move and the walk, against 7.8 ms for the full rebuild (which sorts nearly sorted siblings; a sort from scratch is the 27 ms of the document's `sortedSiblings`). The slot owners and occluder table are still rebuilt over every object after a reorder, because every rank above the moved object shifts. A change set of 64 objects or more (`SIBLING_BATCH_THRESHOLD`; a page switch takes 10,000 root objects off and puts 10,000 on) goes through `replaceAll`: each touched parent's list is filtered once for what left and merged once with what arrived, sorted, instead of a splice per object, which on one parent is O(n²) (330 ms for a 10k-object page switch, 3 ms batched). Likewise the spatial index clears its R-tree and packs the arrivals (`bulkLoad`) when a change set removes everything it held, rather than removing and inserting one by one.
- Measured (Apple M1 Max, fake backend, 10k visible objects in about 1000 segments, fastest runs on a machine shared with other builds, so treat as rough): `planSegments` alone about 0.8 ms (Node, 19k visible records); through the frame (`z-order-segments.bench.ts`), a camera-only frame on the cached plan about 0.07 ms including 2000 fake draws, a re-plan after the visible set changes 0.8–2 ms, a bring-to-front (new paint order, slot owners and plan) about 5 ms; made the sibling order incremental, which took it from 7.0 ms to 4.7 ms (means, same machine and day). With the R-tree culler a pan that changes the visible set re-plans, which is near the 1 ms camera-only budget at 10k visible objects; the pan re-plan, and the slot-owner rebuild after a reorder, can be made incremental too if the benchmarks flag them.

**Level of detail**. Below a few screen pixels an object draws in a cheap form: text as greyed bars (under 4 device px a line) or not at all (under 2.5 px), an image as its average colour (under 8 px on its fitted longer edge), a path as a straight chord per segment (a box under 6 px). A line under 6 px is not reduced to a chord between its endpoints: it keeps its route (an elbow line's bends) and heads, meshed at the chord form's coarse tolerance (a quarter pixel at 7.2 px), so its arcs take the fewest triangles; the brief says paths, and a line's route is already straight pieces. The thresholds are `lod-thresholds.ts`; each has a 20% band remembered per object (`lodFormOf`: cheaper as soon as the size falls under the threshold, back only at the threshold × 1.2), so a pinch hovering at a threshold does not flip forms or re-plan every frame.

- **State in the scene.** A pass declares a rule and the size it measures (`ScenePass.levelOfDetail`: the text pass the tallest line of any text `textPlacementOf` places, so shape labels adopt it by registering their placement; the image pass the longer edge; the path pass the box's longer side). The scene tracks every object a pass with a rule draws (`Scene.levelOfDetail`), bucketed by size with the sizes kept sorted (`LodSizeIndex`). The `levelOfDetail` stage, right after `collectChanges` and before the passes rewrite records, evaluates only the objects the culler draws this frame (`SpatialCuller.visibilityFor`): those that entered the visible set, and, on a zoom from one scale to another, only the objects whose size on screen crossed an edge of their rule (`lodEdgesOf`: each threshold and the tops of its bands): for each edge the sizes between edge / new scale and edge / old scale, found by binary search and merged across edges, so a zoom frame costs O(passes × edges × log sizes) plus the objects that cross, whatever the spread of sizes (fix round 1: the first version walked every distinct size on every scale change, 229 µs a zoom frame at 50k with 4,000 images and 6,000 freehand paths of distinct sizes). `lod.bench.ts` at 50k objects with 2,000 distinct text line heights, 4,000 image sizes and 6,000 path sizes (Apple M1 Max, load 70 to 210, so rough): a zoom frame that crosses nothing about 1 µs mean, 0.3 µs p75 (before: 190 µs mean, 67 µs p75); a far zoom step taking a few sizes across an edge 50 to 90 µs mean (before 210 µs); a new visible set of 50k 1.6 to 2.1 ms at best (unchanged); a frame that flips every text between greek and full, 18,500 of them, about 10 ms at best against 4 to 5 ms before (walking entries in size order touches memory out of order: the first version, forced into size order, was as slow; with the few font sizes of a real board both walk the same order).
- **No measuring on a move.** The scene tracks an object again on every change (`Scene.upsert`); a rule may say, without measuring, that the size cannot have changed (`PassLevelOfDetail.isSameSize`: the text rule compares the largest font size of a text object's or note's runs, the image rule box/crop dimensions and natural size, the path rule the mesh input, `isSameDrawnMesh`), so a drag neither places text nor recomputes path bounds (fix round 1: `lod.bench.ts`, re-tracking 1,000 moved texts and 1,000 moved 100-point paths, 8.4 ms before, 2.9 ms after). A rule without it measures on every change. The stage and its callers allocate nothing per frame: the image stage's and the text pass's rewrite sets and the tier checks' hand-out are reused.
- **The cheap forms.** Text rewrites its records as bars from the cached layout (`greekQuads`), requesting no glyph; the shader antialiases a bar's top and bottom edges (its quad grows a device pixel above and below, and each fragment covers the share of its pixel's height the bar overlaps, from the camera uniform's pixel size), so a bar of 1 to 1.6 device px neither drops rows nor shimmers while zooming and one thinner than a pixel draws a pixel at proportionally lower alpha (fix round 1); hidden text keeps its bars and is left out of the culler's ranges and the plan, so it costs nothing and splits no segment. An image writes its average colour with a texture weight of 0 on its level's page, so a form change moves no record between pages; the texture manager is not told and keeps its smallest level resident, so it counts as drawn, never blank. A path draws a chord mesh (`chordMeshRequestOf`: its segments straightened, flattened at a quarter pixel of the largest scale the form is drawn at), one per path version for every zoom below the threshold, where a zoom bucket's mesh would be rebuilt every 41% of zoom.
- **No thrash, measured.** Each frame counts the objects whose form changed (`FrameStats.lodTransitions`) and those that have now changed form across a threshold more often than their size on screen traversed its whole 20% band (from under the threshold to at or above it × 1.2, or back: `bandSideOf`), plus one for an object first seen inside the band (`lodThrashes`, `LodBand`, per object and threshold). The band is the brief's, not the rule's own `LodRule.hysteresis`, so a rule without memory, which changes form at every crossing of the threshold itself, is caught as soon as a pinch wobbles across it (a unit test runs one with `hysteresis: 0`; the bench's wobble phase does it on the 50k board); the glyph atlas and the path mesh cache remember what they evicted in the last 8 s (`EvictionMemory`) and count anything made again within it (`atlasRegenerations`, `meshRegenerations`). The benchmark's zoom sweeps fail on any of them (`tooling/bench`, `lodChecks`).
- **Tier checks follow the frame.** A zoom used to queue a tier check for every text entry on every scale change and walk the off-screen ones every frame; tier checks are now queued only when a zoom takes a font size across a tier edge and taken when the text is drawn (`TextTierChecks`). After a hand-out nothing queued is visible, so a change of the visible set looks up only the objects that entered it (`LevelOfDetail.enteredIds`), not the whole queue (fix round 1): with 18,000 texts queued off screen and ten entering, 0.2 µs against 0.4 ms before (`text-tier-checks.bench.ts`).

- **Thresholds are in screen pixels.** At zoom 1 on a 1× display an image under 8 world units on its fitted longer edge draws its average colour, a path whose box is under 6 units draws chords, and text whose tallest line is under 4 units (a font under 3.2 units, lines being 1.25 em) draws bars, under 2.5 units (a font under 2) nothing; on a 2× display each halves. Such objects are rare at zoom 1, but a board of very small type shows bars until the reader zooms in.
- **Cropped images.** The average colour is the whole asset's (`ImageAssetInfo.averageColor`), also for a cropped image, whose visible region may differ. The cropped region's colour needs the smallest level's pixels, which are uploaded and not kept in the worker: it needs a new field (a small grid of region colours from the decode job, or the smallest level's pixels kept on the CPU), so it is left for a follow-up.
- **Recorded exceptions and follow-ups** (the controller's rulings, fix round 1). The camera-only budget (CPU p95 under 1 ms at 50k in the quiet zoom sweep) is not met: 2.1 to 3.7 ms on this branch against 4.8 to 7.2 ms on main. It is accepted as a recorded exception for this task, because main already misses it by more and this task improves it two to three times; a follow-up covers incremental re-planning and range patching when the padded region changes, and a diff-based visible set. The costs this task added to those frames (a zoom frame walking every distinct size, tier checks walking the whole queue) are fixed here. Mid-zoom draw calls (824 at 0.2× on the 50k board) and page runs that interleave in slot order (each a range whatever the segments) are follow-ups too. The owner has since relaxed the benchmark gate's camera-only limit to 6 ms, interim until (incremental re-planning and a diff-based visible set, the follow-up above) lands and the 1 ms target is restored (`CAMERA_ONLY_INTERIM_LIMIT_MS` in `tooling/bench/src/compare/budgets.ts`): measured 2026-09-28 on a quiet machine, desktop 50k CPU p95 4.36 ms and the mobile profile's 10k 3.20 ms, both under the interim limit.

**Adopting level of detail in a new kind** (written for the shapes branch, which merged first, and any later pass):

- A pass declares `levelOfDetail: { rule, sizeOf }` (`PassLevelOfDetail`) and, to skip measuring on a move or a recolour, `isSameSize`; the scene then tracks every object the pass draws. The rule is a `LodRule` (its cheap forms, thresholds descending, and optionally its own `hysteresis`; the no-thrash counter holds every rule to the 20% band whatever it says). `sizeOf` is world units in the object's own frame and must be a pure function of the object.
- When it writes records the pass reads `scene.levelOfDetail.formOf(passName, id)`, and in a stage after `collectChanges` rewrites `scene.levelOfDetail.changedIn(passName)` (`Scene.rewriteRecords`); the z-order segments leave a `hidden` form's records out by themselves (`hiddenIn`).
- Text placed by `textPlacementOf` adopts `TEXT_LEVEL_OF_DETAIL` with no further code: greek bars, the hidden form and tier checks come with the text pass. Shape labels did so when the shapes branch merged: a label greys under 4 device px a line and is left out under 2.5, as a note's text is ('s provisional rule left it out under 3 px), and `isSameTextSize` compares its runs so a move measures nothing. A later kind extends `isSameTextSize` to its runs, or a move measures it again (correct, only slower).
- Gone with: `note-text-detail.ts`, `ScenePass.minimumScaleOf`, `DetailScales`, `noteTextMinimumScale` and `MIN_NOTE_TEXT_LINE_PX`; a rebase that still uses them moves to the rule above.

**Spatial index, culling and hit testing** (an R-tree spatial index over object bounds drives culling, hit testing and marquee selection, so only visible objects cost anything). Pure, no DOM and no clock:

- `RTree` packs a first load with Sort-Tile-Recursive (cutting slices and runs evenly, so every node is at least 40% full), inserts by least enlargement with Guttman's quadratic split (node capacity 16), and on removal dissolves underfull nodes, putting their child subtrees back at their own level and their items into leaves. `update` with an unchanged box is a map lookup. `updateMany` refits existing leaves and tight ancestor boxes once for batches of at least 64 entries covering half the tree; sparse batches and inserted keys use ordinary updates. It repacks with STR when summed non-root node areas plus edge lengths exceed twice the reference cost (edge lengths also protect zero-area geometry), and ordinary structural edits reset that reference. This heuristic affects grouping cost only: queries always use the exact current boxes, including after distant moves. Tests check every query against brute force over seeded random boxes and `validate()` the invariants (tight boxes, balanced height, fill) after bulk loads, inserts, and interleaved moves and removals.
- `SceneSpatialIndex` stores each object's world AABB (`worldBoundsOf`): the geometry the schema's `localBounds` uses for every type but groups (boxes, line points, path vertices and Bézier control points) through `worldTransformOf`, so a rotated object is bounded by its rotated corners, grown by what the renderer draws past it (half a shape's stroke; twice a stroke's width for miter joins, four times with line caps; a sticky's shadow reach). Groups contribute no box: their children are indexed individually in world space, and a change to a group or frame re-indexes every descendant. Connectors and comments are not indexed yet (their geometry follows other objects); a pass that draws them will need their bounds, since `SpatialCuller` draws only indexed objects unless the whole board is visible. `objectGeometry` keeps its own per-type rules because the schema's `localBounds` needs a whole board and child index (for groups, which the engine does not index); `object-geometry.test.ts` pins that its hull box equals `localBounds` for every non-group type. Points are mapped with the schema's `applyTransform` and `invertTransform`.
- Shape labels keep their centered overflow. The text pass reports the exact transformed glyph/greek quad union through `ScenePassEnvironment.setTextBounds`, including layouts prepared before a shape ever becomes visible. `SceneRenderer` composes this hook with `SpatialCuller.setDrawingBounds`; `SceneSpatialIndex.setDrawingBounds` unions it with geometry and removes it when the label is removed or the pass destroyed. Async bounds changes invalidate cached visibility and segment planning through `drawingBoundsRevision`; ordinary document moves keep the incremental segment-move checks. Camera-only frames do not relayout labels. A custom non-spatial culler owns its own drawing-bounds policy and may consume the environment hook.
- `SpatialCuller` searches the index for the viewport padded by 25% of its size per side and keeps that region and the ranges built from it. A frame whose viewport stays inside the region (and has not zoomed in more than twofold) searches nothing. A document change that moves a box into or out of the region re-searches the same region (the visible set is exactly the indexed boxes that meet it, so it is not stored). An object that changes but stays inside keeps its slots unless its record count changed, so the ranges are rebuilt only when it holds a slot they do not draw: a still frame, a small pan and an in-view drag return the same ranges. Visible slots are coalesced into ranges, bridging runs of up to 16 hidden records (`maxGapRecords`; a clipped quad costs less than a draw call); when every indexed object is visible each pass draws `[0, recordCount)`. `SceneRenderer` feeds a `SpatialCuller` (default or given) every change set by wrapping `collectChanges`; pass your own to share its `index` with hit testing.
- `hitPoint` and `hitRect` refine the index's candidates by exact geometry: for `hitPoint`, a shape by the signed distance of the kind the shape pass draws (`spatial/shape-hit.ts`, `isPointOnShape`, over `shapeDistance`): a shape with a painted fill is hit inside its outline, one without on its outline band (its stroke's width, placed about the edge by its `strokeAlign`) within the tolerance, or inside its label's box when it has a label, so an ellipse's box corner is not the ellipse and a click inside an unfilled shape reaches what shows through it (the marquee keeps boxes); otherwise a box rotated with its object (point containment in the object's frame; separating axes against a marquee), and for lines and paths the centre line with curves flattened by the path pass's `flattenCubic` (for `hitPoint`, at the tolerance of the bucket of zoom × `dpr`, keeping the caller's previous `flattenBucket` by the same hysteresis, as the select tool does across picks; the drawing's own hysteresis state is per frame, so the two can differ by a bucket, so the pick's flattening tolerance is at most the coarser bucket's, about 0.35 device px; for `hitRect`, at zoom 1), so picking agrees with drawing (a point within half the stroke plus `tolerancePx / zoom`; the even-odd fill of a filled path's closed loops, the regions the path pass fills). A line is picked on its route (`lineRouteOf`: an elbow line through `elbowRoute`, the route the path pass draws) and its heads (an open arrow's barbs as strokes, filled caps as fill polygons, `capShapeOf`), and its world bounds take the heads' points, so a head is picked and culled where it is drawn. Results are topmost first by stacking path (the z keys from the root ancestor down, a child above its parent); each step compares siblings with the z-order segments stage's `compareStacking` (z by UTF-16 code units, then id), so pick order is the reverse of the order `paintOrderOf` draws in (a test pins this).
- Measured (`pnpm bench`, Apple M1 Max, while other work loaded the machine, so upper bounds): bulk-loading 50k boxes about 43 ms (inserting them one by one about 140 ms); 1k incremental updates about 5 ms to random places and 3.5 ms for small drags; a padded 1600 × 1000 viewport query at 50k about 15 µs, a point query about 2 µs. Culling a 50k-object board: a camera move inside the padded region about 0.1 µs; a pan past it (one search, 9k visible) about 0.55 ms; a zoom out to the whole board about 0.4 ms; a one-object drag in view about 0.06 ms.

**Paths** (CPU flattening with stencil even-odd fills; flatten buckets change with hysteresis and meshing stays off the frame; meshes are cached per zoom bucket under the GPU memory budget; ported from the prototype's `src/render/pathRenderer.ts`, `src/vector/bezier.ts`, `network.ts` and `stroke.ts`):

- **Geometry.** A path is the schema's vector network. `indexNetwork` builds its vertex and edge lookups once, so chains and loops are linear (the prototype searched the segment list per step). Strokes follow `strokeChains`, maximal runs through degree-2 vertices, so joins are continuous; a chain that starts at an end or a branch has caps there. Fills cover `closedLoops` only: components whose vertices all have two segments; a theta graph or a loop with a tail is stroked, never filled. A lone vertex is a dot.
- **Flattening by zoom bucket.** `flattenCubic` subdivides until both handles lie within the tolerance of the chord (the curve lies in its control points' hull, so the polyline stays within the tolerance). The tolerance is a quarter of a device pixel at the bucket's zoom: bucket `b` stands for `2^(b/2)` device pixels per world unit (zoom × dpr), so meshes are rebuilt only when the zoom moves by about 41%, never on a pan, and the bucket changes only after the zoom crosses the boundary by an eighth of an octave (`FLATTEN_BUCKET_HYSTERESIS`), so a zoom wobbling about a boundary does not rebuild.'s thrash counters found no mesh rebuilt after its eviction in the zoom sweeps, so the margin stays; a path under 6 device px draws its chord form instead (`PATH_LEVEL_OF_DETAIL`), one mesh per path version for every zoom below it, so a far zoom re-meshes nothing per bucket. Hit testing flattens with the same function, but its bucket keeps its own hysteresis and may differ from the drawn one by one bucket, so its tolerance is at most the coarser bucket's, about 0.35 device px at the drawn zoom (a quarter pixel times √2); picks agree with pixels to within that.
- **Round joins.** The prototype mitred every turn under 60° and put a whole disc on sharper ones. Here a join is mitred only where the mitre stays within the tolerance of the round join (the gentle turns between a flattened curve's pieces); elsewhere the outer side of the turn gets a sector of the half-width. Arcs are divided so their chords stay within the tolerance (8 to 64 sides per circle, the prototype's bounds), with an even count so a cap's tip and a join's bisector are vertices and the bounds exact. Caps are a hook: `round` and `butt` today, arrowheads with lines.
- **Lines and arrows**. The path pass draws `line` objects too: one stroke layer each (`pathLayersOf`), meshed by `buildLineMesh` through the same `mesh` job (a request carrying a `line` shape and an empty network), cache and budget (a line counts as one segment). A line's centre line is its two points, or for an elbow line `elbowRoute`: horizontal, vertical, horizontal through the middle x when the points are further apart across than down, else vertical, horizontal, vertical through the middle y, so the long pieces run along the longer axis and a head points the way the line mostly travels; the route stays inside the box of the two points, the line's stored bounds. Caps are geometry through `writeStroke`'s `capStyle` hook (`caps.ts`): `capLength(width) = 8 + 3 × width`, so heads scale with the stroke and a hairline still shows one, and each head is at most half the route's length (`capLengthOn`), so on a short line the heads never reach past the far end (fix round 1); a line whose ends coincide (two people moved its ends onto one point at once; each command saw a length) has no heads and draws as a round dot the size of its stroke, whatever its caps, so it stays visible and pickable; an open arrow is two barbs stroked back from the tip (half as wide as long), a triangle is filled with its point on the end point and the shaft pulled back half its length under it (butt), a circle (radius 0.35 of the length) and a diamond (0.3 across) are centred on the end point over a butt shaft end, and a plain end is round. Heads are drawn in the stroke layer, so a translucent arrow covers each pixel once. Hit testing and bounds read the same shapes (`objectGeometry`: barbs as polylines, filled heads as fill polygons, a disc as a 16-gon with its exact axis extremes in the hull), so rendering and picking agree; `lineLocalBounds` grows the points' box by the farther cap's reach for the pass's off-screen skip. Measured (`elbow-route.bench.ts`, the 50k board's 2,500 lines): routing all of them about 0.07 ms, their geometry 4 ms, meshing them at one bucket about 10 ms.
- **Dashes, joins and caps**. A path's, line's or connector's `strokeDash`, `strokeJoin`, `strokeMiterLimit` and `strokeCap` are read by `strokeOutlineOf` (tolerantly: a refused value is absent) into a `StrokeOutline`, which a `mesh` job carries as plain data; an object without them sends no outline and builds exactly the mesh earlier builds did, so existing goldens are unchanged. Joins: a gentle turn shares one mitre whatever the style (every join is within the tolerance of it there); a sharper one keeps each segment's own normal and fills the outer side with a sector (round, and absent), a triangle (bevel), or the miter's two triangles, bevelled when `1 / cos(turn / 2)` passes the miter limit, as SVG. A path's join applies at its vertices only (`flattenChainCorners`); the points inside a flattened curve, and along a curved connector, join round. Dashes are cut along arc length (`dashIntervals`, then pieces across segments and joins), each piece stroked open with the outline's cap; a piece that starts or ends at the stroke's own open end keeps that end's cap; on a closed chain the dash over the closing point is one piece joined there; a dash of length 0 is a dot. Past `MAX_DASHES` dashes the stroke draws solid, which bounds the mesh. A line's or connector's `strokeCap` ends only an end without a decoration; its heads stay solid with round joins. The dash pieces overlap where the stroke crosses itself or at joins, and are all in the one stroke range, so the `strokeOnce` stencil pipeline still covers each pixel of a translucent dashed stroke once. A square cap or a miter join reaches further than half the width: `strokeOutlineReach` grows the path pass's local bounds and the spatial index's. No shader or instance record changed.
- **Meshes.** `buildPathMesh` writes one vertex list per path and bucket, in the path's own frame: the fill's fans (one per closed loop, from its first point), a cover quad over everything padded by two tolerances, then the stroke's triangles. A move or a recolour changes the path's records and never its mesh; the path pass keys meshes by a version it bumps only when the network, stroke width or fill flag changes (`isSameMeshInput`).
- **Freehand strokes**. A freehand stroke is one stroke layer of the path pass. `buildFreehandMesh` flattens its curve (`freehandCurve`) at the bucket's tolerance and writes a quad per segment, at a half-width that follows a marker's pressure (`freehandHalfWidth`, from 30% of the width at no pressure), with round joins (`writeJoin`), round ends (a highlighter's flat) and a disc for one point. It reuses the path shader unchanged. A highlighter is translucent by its layer opacity, so it takes the `strokeOnce` stencil and a stroke crossing itself is blended once; separate strokes stack. The mesh's version bumps only for new points, pressures (a marker's), width or tool ends (`isSameFreehandMesh`).
- **Records and drawing.** A path draws up to two layers, fill then stroke, each a record of its rotation, origin and colour (`float32x4` twice). The pass is a custom-draw pass: its drawer draws each layer record in draw-list order, selecting the record with `firstInstance` (no writes inside the pass). A fill is the fans with colour writes off and the stencil inverted (the loops' even-odd count), then the cover quad where the stencil is set, zeroing it for the next path. An opaque stroke is its triangles; a translucent one draws where the stencil is clear and sets it, so overlapping triangles at joins paint each pixel once, then the cover quad with colour off clears it. Every path or line with a drawable layer is flagged for z-order segmentation, including stroke-only paths and translucent strokes, so it paints over later-pass content below it. Draw calls are per path (two or three), as in the prototype; batching non-overlapping fills is future work.
- **Building and caching.** Before `draw`, the `preparePathMeshes` stage picks the frame's bucket and, for each visible path record (paths whose box, placed by their record, misses the viewport are skipped, since the culler's ranges bridge short runs of hidden records), takes the mesh from the cache or sends a `mesh` job (`meshJobRequestOf`) to the mesh builder: through the engine host's job pool at `visible` priority (`createPooledMeshBuilder`; `INLINE_MESH_BUILDER` meshes at once on the rendering thread, for tests, benchmarks and golden scenes). A build the pool rejects, or leaves unanswered for `MESH_BUILD_TIMEOUT_FRAMES` (300) frames, is made inline once at the start of the next frame (`MeshBuilds`), so a lost job never keeps `hasPendingWork` true; a timed-out build also retires the worker running it (`PathMeshBuilder.abandon`, a hung worker), and each frame's timeouts and failures reach `onFault` as one fault, not one per path; a network whose inline build throws too is not tried again until it changes, and what is kept per path is dropped with the path. A frame sends at most `maxMeshSegmentsPerFrame` path segments (1024 by default, at least one path), so a bucket change over many paths spreads over frames; until a path's mesh lands it draws the nearest cached bucket, or its previous version during an edit, and `hasPendingWork` keeps the frame loop drawing. The `MeshCache` holds meshes under `meshByteBudget` (in the engine hosts the `meshes` share of `budgetForDevice`, 64 MiB on a desktop and 12 MiB on a phone; 32 MiB for a path pass built without one): least recently drawn first, never a mesh drawn this frame, so off-screen paths and abandoned buckets go first; a mesh of a newer version drops the older. The cache's bytes are the `meshes` ledger row.
- Measured (`pnpm bench`, Apple M1 Max, on a machine running many other builds at a load average above 300, so these are upper bounds to re-measure on a quiet runner): meshing a six-vertex pen path about 25 µs, a 1k-segment curved path about 4 ms; a camera-only frame over 1k paths (300 visible, cached meshes) about 0.1 ms of CPU.

**Engine in a worker** (React and the document store on the main thread cannot jank a frame; pointer events are forwarded with timestamps; a main-thread fallback behind the same interface). `EngineHost` is the interface the page drives; two implementations sit behind it and share `EngineRuntime`, the engine on the rendering thread:

- **The runtime** queues each arriving change set and applies it in the frame's first stage, `applyChanges` (before `collectChanges`): it checks the change set's shape (`isSerializableChangeSet`, which the protocol guard leaves to it) and mirrors it, so that work is timed with the frame. The same stage hands the overlay layer the latest model that arrived (`SceneArrivals`), so a drag's preview and its selection overlay land in one frame. It owns the `SceneRenderer`, a `SceneSourceMirror` (the worker's copy of the document: a change set's `get` is a closure over the page's document and cannot cross threads, so the page sends `serializeChangeSet` output, the touched objects plus the ancestors their world transforms compose), the camera and its animation, the pointer inputs of the coming frame and the pixel reads that wait for it. It asks for an animation frame only when something arrives or an animation runs, and draws one frame for everything that arrived since the last. `readPixels` is answered inside the frame it asked for, since a GPU canvas can be read only before it is presented. `animateCamera` (zoom geometric, centre linear, for zoom to fit) runs on the runtime's own frames, so a camera keeps moving while the page is busy.
- **`WorkerEngineHost`**: `createEngineHost` spawns the worker first and then hands over the canvas (`transferControlToOffscreen`), so a worker that cannot start leaves the canvas to the main-thread fallback; after the hand-over the canvas belongs to the worker and a failure rejects. The page posts `engine-init` with the transferred `OffscreenCanvas`; the calls of one task are then posted together as one `engine-commands` message (a microtask flush), so they reach the worker together and land in one frame. The worker posts `engine-frame` reports (times converted to the page's clock with the two threads' `performance.timeOrigin`), `engine-pixels` with the buffer transferred, `engine-frame-stats` answering a `read-frame-stats`, and `engine-failure`s. The protocol (`host-protocol.ts`) follows the job protocol's conventions: `type`-discriminated plain messages, transfer lists, cloneable failures, and guards on both sides.
- **`MainThreadEngineHost`** runs the same runtime on the page's animation frames: the fallback where `OffscreenCanvas`, `transferControlToOffscreen` or an `OffscreenCanvas` WebGL2 context (the worker's fallback backend) is missing, and the control case of the jank benchmark.
- **Pointer input** keeps the DOM event's `timeStamp` (page clock) and is coalesced per frame (`coalescePointerInputs`): a pointer's run of moves keeps its last, presses, releases, cancels and button transitions are never dropped. Each frame's report carries its coalesced inputs; hit testing and tools (later tasks) consume them there.
- **Faults** (a frame that throws, a crashed worker, a malformed message) go to `onFault` listeners, or are thrown when there are none, so they are never silent. The frame's pixel reads reject with the fault; its pointer inputs are reported with the next frame.
- Passes are not cloneable, so a host renders the engine's standard passes (`createStandardScenePasses`: solid rectangles, SDF shapes, images, paths, then text) on its own thread, with the runtime's frame request and clock as their environment, the fonts its owner creates (`createTextResources`) and its one job pool (`EngineJobs`): the job workers `EngineJobWorkers` describes (`createEngineWorkerEntry`'s extensions for the worker host, `createEngineHost`'s option for the main-thread host), or, without them, a queue it runs for 4 ms after each frame (`EngineJobs.runQueued`, the pool's only drain; its fallback handlers are the kinds the engine submits, `mesh`, `layout` and `msdf`, and `decode` only where `EngineImageSupport.decodeFallback` is given, never `echo`; the `msdf` one is imported on its first job, so its code is a chunk of its own rather than part of the page or the engine worker), stopped with the runtime. Path meshes are `mesh` jobs on it, images `decode` jobs, and the text pass's `layout` and `msdf` jobs go to it too (the pass only submits); while any is pending the host asks for another frame, and each frame's report says so (`hasPendingWork`, false once everything sent so far is drawn), and whether the pool still has live job workers (`isUsingJobWorkers`, false without them or once every one has failed, a script that did not load included); a mesh fault reaches `onFault` after the frame. The path mesh cache and the texture manager take their caps from one device budget (`budgetForDevice`: `meshes` and `textures`), so an image-heavy board cannot starve path meshes, nor the reverse. Options that cross to the worker are data (`backend`, `sampleCount`, `clearColor`, `fontFaces`, `device`).
- **Overlays**: the tools stay on the page, so what they show over the scene reaches the engine as data. `setOverlay(model)` sends a structured-cloneable model (the last of a task: a busy pointer costs one per frame at most), and an `EngineOverlay` layer, created on the rendering thread when the host starts (a function cannot cross to a worker: the main-thread host takes `createOverlay` in `createEngineHost`'s options, and the worker's script passes it to `createEngineWorkerEntry`), installs its stages before any statistics and draws the model at each frame's zoom, so screen-sized outlines stay right through a camera glide the page never sees. The engine does not know the model's shape; the layer refuses one it cannot use, which is reported as a fault, as is a model sent to a host without a layer. The select tool's layer is `createSelectionOverlayLayer` of `@canvas/tools`.
- **The drawing buffer** is sized where the engine runs: after the page hands the canvas to a worker, the page cannot size it. Each frame report carries the buffer's size (`drawingBuffer`), which the app's test harness reports as the canvas's.

**Workers** (expensive work, image decoding included, runs off the frame). Two layers, both DOM-free:

- `WorkQueue` runs synchronous jobs on the calling thread, most urgent first, until the frame's budget is spent; a started job always finishes, so jobs must be small.
- `WorkerPool` sends jobs to N workers (`chooseWorkerCount`: cores − 1, at most 4), round-robin, at most `maxInFlightPerWorker` (default 2) each. Submissions made in one tick are ordered before any is sent. Responses come back with their buffers transferred. Without workers, or once every worker has failed, it runs the same handlers on the main thread through its `WorkQueue`, when the frame loop calls `drainMainThread(budgetMs, now)`. A crashed worker is retired and its running jobs fail with `worker-failed` (not retried: a job that crashed one worker would crash the next); `retireWorkerOf(id, reason)` retires a hung one the same way. The main-thread fallback runs only the `fallbackHandlers` its owner passes (the hosts pass the mesh job alone): the pool imports no handler, so a bundle carries only the handlers its code names.

The protocol (`src/workers/protocol.ts`) is one request and exactly one reply per job, correlated by id, with structured failures (a result that cannot be posted becomes a `handler-failed` reply; a request the worker cannot deserialise becomes a `worker-fault`, which retires the worker); it is the contract the MSDF text port and the engine-in-a-worker task build on. A new kind of job is an entry in `JobPayloads` plus a handler in `createDefaultJobHandlers`. Handlers must not mutate their request (on the main-thread fallback it is the caller's object) and, if they keep per-worker state such as a loaded font, must tolerate several of their jobs in flight at once (the prototype's msdfgen worker serialised calls for this reason: `webgl-whiteboard/src/atlas/msdfSource.ts`).

The app owns the bundler, so it starts the workers: its job-worker script is `serveWorkerEntry(self, createWorkerEntry())`, and the pool is `new WorkerPool({ workerCount, createTransport: () => createWebWorkerTransport(new Worker(url, { type: 'module' })) })`.

**GPU backends** (WebGPU first, with a WebGL2 peer). `GpuBackend` is the smallest surface the prototype's renderers (`src/render/*.ts` in the prototype) need: persistent buffers written by dirty byte range; `rgba8unorm`/`r8unorm` textures with sub-region upload from a larger source (atlas pages); pipelines with per-vertex and per-instance attributes, premultiplied blending, a colour-write switch and the stencil states of an even-odd fill; one bind group (WGSL group 0); passes that clear, set a viewport and draw instanced triangles from an instance range (the prototype's `drawInstanceRange`); pixel readback; GPU pass timings. Semantics that differ between the APIs are pinned down in the interface:

- **Call order.** Commands take effect in call order on both backends. WebGPU queue writes would otherwise overtake passes already recorded, so the WebGPU backend submits recorded passes before a write.
- **No writes inside a pass.** `writeBuffer` and `writeTexture` throw while a pass is open, on both backends (one shared guard). Per-draw values, such as the prototype path renderer's per-path colour and offset uniforms, go in per-instance attributes selected with `firstInstance`, or in one small uniform buffer and bind group per draw, all written before the pass begins.
- **Lifetime.** Buffers, textures, samplers and pipelines have `destroy()`. `GpuBackend.destroy()` frees everything the backend created that the caller did not: WebGL2 tracks its live programs, vertex arrays, samplers, buffers and textures; WebGPU destroys its device. Bind groups own no GPU memory.
- **Render targets.** `createRenderTarget({ width, height })` makes an offscreen target in the canvas's colour format and sample count, so every canvas pipeline draws into it; a pass with `target` always starts cleared (transparent unless `clearColor` says otherwise) and loads nothing. Both backends share one scratch per backend, sized to the widest and tallest live target (`RenderTargetExtent`), reallocated when that extent changes and freed with the last target. WebGPU needs a pass's attachments and resolve target to be one size, so a target pass draws into the scratch's top-left corner (multisampled colour and `stencil8`, stored with `discard`), resolves into a single-sample scratch and copies the target's part into its texture (`copyTextureToTexture`); replaced scratch textures are destroyed only after the next submit. WebGL2 draws into the bottom-left corner of a framebuffer with multisampled `RGBA8` and `DEPTH24_STENCIL8` renderbuffers, `blitFramebuffer`s that corner into the target's texture framebuffer and invalidates the scratch. GL counts rows from the bottom, so a WebGL2 target's texture holds the image upside down: the composite (`layer-composite.wgsl`) flips the interpolated `v` when its uniform says so (`isRenderTargetBottomUp`). A lost device or context destroys every target, as `GpuBackend.destroy()` does. `drawLayerComposite` sets the pass's viewport to the layer's rectangle, so it must be whole device pixels on the canvas, the target's size.
- **Device loss**. `onDeviceLost` fires once when the GPU is reset or the browser reclaims it: WebGPU's `device.lost`, WebGL2's `webglcontextlost` (cancelled, so the browser restores the context; the loss's `restored` settles at `webglcontextrestored`). A deliberate `destroy()` is no loss. `EngineRuntime` then waits for `restored`, builds a new backend for the same canvas (`recreateBackend`, from the host), a new renderer, change stage and overlay (`EngineAssembly`), replays the whole document mirror and the last overlay model, moves the frame statistics across, and draws; the image catalogue outlives the device, so images restart at once from the CPU copies of their smallest levels.
- **Shared programs**. Pipelines drawn with the same shader share one program on WebGL2, as one shader module on WebGPU: the backend links a shader's program on its first pipeline and deletes it with its last (`WebGl2ProgramCache`), so passes that share `sdf-shape` or `path` compile it once at engine start.
- **Base instance.** WebGL2 has none; its backend re-aims per-instance attribute pointers at the range's first record on every draw.
- **Bindings.** GLSL ES 3.0 has no `layout(binding)` and only combined samplers. The WebGL2 backend reads the naga-generated names (`<Struct>_block_<n><Stage>`, `_group_0_binding_<b>_<vs|fs>`) and ties each uniform block to binding point = WGSL binding and each sampler to texture unit = the texture's WGSL binding; a texture's layout entry names its sampler binding.
- **Coordinates.** Viewports and texture rows count from the top on both. naga's `adjustCoordinateSpace` is turned off because WebGL2 draws straight to the canvas, where clip space already matches WebGPU's. Readback rows are returned top-down (WebGL2's are flipped; WebGPU's `bgra8unorm` is swizzled).
- **Stencil.** Every canvas pass has a stencil attachment (WebGPU `stencil8`; WebGL2 `stencil: true`), cleared to 0 with the colour; tests compare against reference 0.
- **Multisampling.** `sampleCount` 4 (default) renders with 4× MSAA (WebGPU resolves into the canvas texture; WebGL2 uses an antialiased drawing buffer). WebGL2's default framebuffer is stored bottom-up, so its sample pattern is mirrored and slanted edges can differ from WebGPU by one sample; interiors are identical.
- **Timings.** Passes with a `timingLabel` are timed with WebGPU `timestamp-query` or `EXT_disjoint_timer_query_webgl2`; `collectPassTimings` resolves them later. At most four frames (WebGPU) or 128 passes (WebGL2) wait uncollected; later ones go untimed.
- **Sample count.** `capabilities.sampleCount` is the real count: the requested one on WebGPU, the drawing buffer's `SAMPLES` on WebGL2 (1 when not multisampled).

**SDF shapes** (shapes are SDF quads, as the prototype's sticky notes were). Ported from the prototype's `src/render/shapeRenderer.ts`. Each instance is a unit quad grown by `softness` plus one device pixel (the camera uniform's `pixel`) so a blur is never clipped, turned about its top-left corner by the record's axis. The fragment shader evaluates both distance functions and selects one by the instance's `kind`: the exact rounded-box distance (radius clamped to half the shorter side), or an ellipse's implicit function divided by its gradient length (exact on the outline; the centre, where the gradient vanishes, counts as a semi-minor axis inside). Coverage is `1 − smoothstep(−edge, edge, d)` with `edge = max(softness, 0.5 × pixel)`, `pixel` the camera's device pixel in world units (a flat varying from the vertex stage): softness 0 is a crisp edge whose coverage ramps over one device pixel centred on the edge at any zoom and turn (the distances have a gradient of length 1), so a pixel centre half a pixel inside an edge is fully covered and one half a pixel outside untouched, and a rectangle on pixel boundaries draws exactly its pixels, as a flat quad does (until then `0.75 × fwidth(d)`, which bled about 7% into the pixel outside and doubles across a box's corner diagonal); a larger softness is a blur of that half-width in world units. Output is premultiplied. A sharp-cornered soft box shows mitred diagonals inside its corners (the box distance is `max(q.x, q.y)` there), as in the prototype; the note shadow's 6-unit radius rounds them away.

The instance record is 19 `float32`s, 76 bytes: `x, y, width, height` (world, `@location(1)`; `x, y` is the top-left corner the shape turns about), the fill's straight-alpha `red, green, blue, alpha` (`@location(2)`), `radius, softness, kind` (`@location(3)`), the turn as `cos, sin` (`@location(4)`; `ShapeInstance.rotation`), then (appended so writers of the first 13 by index keep their meaning) the outline's straight-alpha colour (`@location(5)`) and its width and the sides (`@location(6)`). A sticky note is `noteInstances(rect, colour)`: the shadow (inset 4, from 10 below the top to 8 below the bottom, radius 6, softness 14, 28% black) then the fill (radius 3, crisp), values tuned in the prototype (`src/board/note.ts`). A note is opaque, so it starts a z-order segment.

**The shape pass** (`src/shapes/shape-pass.ts`). `SDF_SHAPE_PASS` is the shape shader as a stateless scene pass, second in `createStandardScenePasses`: a sticky note has two records, its shadow and its fill as `noteInstances` makes them, each box placed in the note's own frame and turned with it (a note in a turned frame, or rotated by the select tool, turns its paper and its shadow with its text), and it is an occluder, so a note hides the objects under it, their text included. The shader adopts the engine's camera uniform rather than its own viewport-and-zoom block, so the pass binds the scene's `CameraUniform` like every pass; the uniform grew from 16 to 32 bytes to carry the world size of a device pixel, which the shader needs to pad its quads for antialiasing and which the clip map alone cannot give. `ShapeRenderer` still draws outside a scene, its camera packed into the same layout by `packShapeCamera`. **Shape objects** (`src/shapes/shape-object-record.ts`, `src/shapes/shape-distance.ts`). The pass draws every shape object as one record (`writeShapeRecord`), filled rectangles included, which left the solid-rect pass (frame backgrounds stay there), so a rectangle draws once with its corners and outline. The kinds are distance functions in `sdf-shape.wgsl`: a rectangle is the rounded box (its `cornerRadius`, clamped to half the shorter side), an ellipse as before, and a diamond, a regular polygon or a star (`sides` points; the inner vertices at half the outer polygon's apothem, `STAR_INNER_SCALE`) walk their vertices with an exact polygon distance (Inigo Quilez's `sdPolygon`), the polygon's vertex bounds stretched onto the box (`polygonFitOf`, per instance in the vertex stage), so a triangle's apex touches the top and its base the bottom. The shader walks only the edges that can lie within the outline's width plus a device pixel of the fragment (`bandedPolygonDistance` on the CPU, tested equal to the full walk wherever it is under the band): the point's angular sector in the unit polygon's space names one edge, whose side gives the sign, and an edge m sectors away is at least ρ·sin((m − 1)·step) times the smaller stretch away, so a fragment walks its sector's edge and a few neighbours, all edges only near the centre of a small or thin shape, and a point deep inside the largest centred circle none (fix round 1: the full walk of a screen-filling 64-point star cost about 4 ms of GPU time a frame on an M1 Max, the banded one 0.4 ms; 1,000 polygons of 3 to 64 sides 1.5 ms, now 0.5 ms). The walk runs only for those kinds. The outline is the band of its width inside the edge, laid over the fill (`stroke` over `fill` with the fill's alpha under it), so a shape never grows past its box, and a width of 0 draws exactly the fill. Both edges ramp over one device pixel at any zoom, exact on pixel boundaries (the `sdf-shapes` scene checks both, and its baselines still match; the sticky-note baselines were regenerated for their crisper edges). `src/shapes/shape-distance.ts` mirrors every distance on the CPU, tested against analytic values. Every painted shape is flagged to the z-order segments (`isPaintedShapeObject`), translucent and outline-only ones too: the flag means "paints, so it must be ordered against later-pass content below it", not "hides", so a half-transparent highlight over text, or an unfilled outline over an image, draws over it (`shapes-over-content` golden). The planner merges a split whose box meets no later-pass content below it, so boards of shapes stay few segments. **Drop shadows** (`src/shapes/shape-shadow.ts`, `src/scene/frame-shadow-pass.ts`). A shape's or frame's `shadow` is drawn as the sticky note's is: one soft record of the object's silhouette in the shape pass's layout, moved by `x`, `y`, grown by `spread` on every side (a rounded corner's radius with it, a sharp corner stays sharp; a polygon's or star's box grows, which stretches it slightly), with a soft edge of 1.04 × `blur` (Figma's and CSS's blur radius is a Gaussian of σ = blur / 2, and the shader's smoothstep edge over ±2.08σ is within 2.3% of its CDF). What casts it is what the object paints: a filled shape's area, an outline-only shape's band (a ring), a frame's box when its background paints; an object that paints nothing casts nothing. **Order.** A shape's shadow is the shape's first record in the shape pass, so within the pass it lands over every shape below and under every shape above, at no extra segment; a gradient-filled shape's shadow is there too, its body in the gradient pass after it. A frame's shadow cannot be: the frame's background is drawn by an earlier pass (`SOLID_RECT_PASS`, `RECT_GRADIENT_PASS`), and passes draw in registered order within a segment, so it would land over its own background. It is drawn by `FRAME_SHADOW_PASS`, registered first and flagged to the z-order segments, so a shadowed frame starts a segment wherever its box meets content of the segment below it in any later pass, and everything above it (its background, its children, later siblings) draws over its shadow. Bounds take the shadow in (`worldBoundsOf`: offset length + positive spread + soft edge), so culling keeps an object whose shadow alone is on screen and the segments see what the shadow covers; hit testing reads exact geometry and never the shadow. The shader's banded polygon walk is exact within the outline, the soft edge and a pixel (`outline.x + softness + pixel`), so a polygon's or star's blurred shadow is exact; shapes have softness 0, so their pixels are unchanged. Clipping follows: a child's shadow carries the child's clip index and is cut by its ancestors' clips; a frame's own clip never cuts its own shadow. Out of scope: pen paths, lines and connectors (an offscreen blur pass), inner and multiple shadows. **Stroke alignment and frame outlines** (`sdf-shape.wgsl`, `src/scene/frame-stroke-pass.ts`). A shape's `strokeAlign` puts its outline inside the edge (absent: every outline before it), centred on it or outside it: float 19 of the record (`outline.z`) is the fraction of the width outside the edge, and the vertex stage pads the quad by that part. The fragment stage keeps the inside formula byte for byte when nothing lies outside (the band's coverage composed over the fill's), so absent alignments draw identically; with a part outside, the band past the edge covers no fill, so there the band's and the fill's coverages add rather than compose (no seam at the edge), and the fill shows under the band inside the edge as before. The band's outer edge is the distance offset by the outside part, except for a rounded box, whose box is grown instead: a rounded corner's radius grows with it and a sharp corner stays sharp (a mitre, as in the design tools); a polygon's or star's points, and an ellipse, round by the outside part (by design; mitred outer corners for those kinds are). The banded polygon walk is exact within `outline.x + softness + pixel` of the edge on either side (`bandedPolygonDistance`, tested outside the edge too), which covers any alignment, so it needs no widening. A shape's shadow follows its alignment: a filled silhouette grows by the outline's outside part, a hollow one's band sits where the outline does. **A frame's outline** is drawn by `FRAME_STROKE_PASS`: one stroke-only record of the frame's box with the same shader, registered right after the frame backgrounds and drawn after the frame's descendants, as Figma draws a frame's stroke above its contents (): the pass sets `isDrawnAfterDescendants`, so the z-order segments give each stroked frame a second, **closing paint rank** right after its last descendant and before its next sibling (`paintRanksOfSiblings`), map the pass's slots to it (`slotOwnersOf`) and take its occluder flag there, while the frame's other passes (shadow, background, title) keep its own rank. The outline then lands over its own subtree whatever pass drew it (a later-pass child meets the flagged closing rank and a segment splits there), a nested frame's outline closes inside its parent's, so the outer outline is over the inner one, and later siblings land over it (a frame's background or shadow, flagged, splits; shapes, images, paths and text draw in later passes). A board without a stroked frame has no closing rank, so its ranks, plans and pixels are exactly as before; giving or taking a frame's stroke re-ranks (`ZOrderMirror.hasClosingRank`), the mirror compares occluder flags per rank (`occluderState`: own and closing apart, so a background or shadow given to a stroked frame re-flags its own rank), and a moved stroked frame is checked at both ranks (`checkMovedObjects`). A frame's own clip never cuts its outline. Bounds grow by the outline's outside part (and a shadow's margin by it); hit testing counts it as part of the object where the shader draws it (`outlineOuterDistance`: a rectangle's box grown, its sharp corner mitred and a rounded one's radius grown; other kinds offset), a frame's box grown by it, an unfilled shape's band where it lies. **Frame corner radius** (`src/scene/frame-shape-record.ts`). A frame's `cornerRadius`, one radius or four (top-left clockwise), each capped at half the shorter side, rounds everything the frame draws: the shape shader takes four corner radii at `@location(15)` (`corners`), passed to the fragment stage in the `fit` varying a rounded box never used, and a rounded box with any of them above 0 takes the radius of the fragment's quadrant (`cornerRadiusAt`; `drawnFrameCornerRadii` caps them on the CPU), so `roundedBoxDistance` and the outline's outer edge are exact per corner; all 0 (every shape, and every sharp frame) keeps `shape.x`, the old arithmetic. Shapes feed the zeros from their per-vertex buffer (`SHAPE_QUAD_VERTICES`, `SHAPE_QUAD_VERTEX_LAYOUT`), so a shape record keeps its 20 floats; the frame passes' records carry the radii (`FRAME_SHAPE_INSTANCE_LAYOUT`, floats 20–23, before the clip index). A frame's outline and shadow (radii grown by the spread, sharp corners kept sharp) and an image background are rounded so; a rounded frame's solid or gradient background moves from the flat-quad passes to `ROUNDED_RECT_PASS` and `ROUNDED_RECT_GRADIENT_PASS`, SDF rounded boxes antialiased as a shape is, while a sharp frame keeps the flat quad, so its pixels are unchanged. Its clip is rounded (see frame clipping), never cutting its own fill, outline, shadow or title. A turned rounded frame's bounds are its corner circles' (tighter than its box), and `hitPoint` misses its empty corners (`isInsideFrameShape`, the outline's outside part counted).

`ShapeRenderer` does not depend on the scene graph. Registering it as a scene pass is a few lines: the pass's pipeline is `SHAPE_PIPELINE_DESCRIPTOR`, its record size `SHAPE_INSTANCE_BYTES`, its packer `packShapeInstances`, its per-vertex buffer `SHAPE_QUAD_CORNERS`, and its draw `pass.draw(SHAPE_QUAD_VERTEX_COUNT, count, 0, first)` with the camera bind group. The camera block (`packShapeCamera`) is the prototype's `(x, y, zoom)` plus the viewport size, in device pixels; when the scene graph defines the engine-wide camera uniform, the shape shader's `Camera` struct adopts it.

**Text** (MSDF text; layout and MSDF generation run in a worker pool; glyph atlas pages count against the GPU memory budget; ported from the prototype's `src/text/`, `src/atlas/` and `src/render/textRenderer.ts`). Five areas, each usable alone; none depends on `scene/`:

- **`font/`** reads fonts from their bytes, DOM-free, because layout runs in job workers and the raster fallback needs outlines (the prototype measured with Canvas2D and rasterised with tiny-sdf). It reads the Unicode `cmap`, `hhea`/`hmtx`, the `kern` table (GPOS is not read: GPOS-only fonts lay out unkerned; msdfgen's stb_truetype prefers GPOS, and for the bundled faces both give the same values) and TrueType outlines. `FontLibrary` holds the loaded faces; a style resolves to its exact face, then the family's nearest weight in its slant, then upright (as CSS matches fonts), then the default (first) face, so text always renders.
- **`layout/`** is the prototype's pure layout over plain `text` + `StyleRun[]` (the Y.Text mapping is's): greedy wrapping at the last space (the space hangs past the width), per-run advances, kerning only between neighbours of one face and size, each line as tall as its tallest run with one baseline, centring (and now right alignment) on the visible width. A `layout` job carries the text, runs, width, alignment and each used face's metrics cut to the characters it sets, the default face first so a worker resolves fallbacks as the library does; the reply packs glyphs and lines into two float64 buffers that transfer back. `layoutTextNow` is the same work on the calling thread. Measured (`pnpm bench`, Apple M1 Max): about 65 µs per 330-character paragraph for `layoutText`, about 98 µs for the whole job on one thread (request, layout, pack, unpack).
- **`atlas/`** holds glyph fields per face, codepoint and tier: MSDF glyphs in RGBA8 pages, fallback glyphs in R8 pages (a quarter of the memory), square pages of 2048 texels created on demand within a byte budget; `singleChannelPageSize` gives R8 pages a larger side (the scene text atlas's are twice its page side, an RGBA page's bytes, within the backend's largest texture), so CJK text in single-channel fields spreads over fewer pages. A glyph that does not fit evicts the least recently used glyphs not used this frame, one at a time, and releases a page left empty; `memory()` reports the `glyph-atlas` category's resident bytes, budget and eviction and rejection counts. The atlas owns no GPU objects: each new glyph's cell (bitmap plus a cleared one-texel gutter) is queued as a sub-region upload. Every insert and eviction bumps `revision`; whoever caches glyph quads rebuilds them when it changes, so a quad never samples an evicted glyph's space. Eviction can cascade: it frees the least recently used glyph and retries, and a freed cell only helps a glyph that fits it (or its merged neighbours), so fitting one larger glyph (a higher tier, a bigger character) can evict many smaller ones, up to emptying a whole page, which is then released and reopened. Only glyphs not used in the current frame are evicted, so the cascade never removes anything the frame draws; when nothing evictable is left, the glyph is rejected and `GlyphSource` backs off re-requesting it. Tiers are 64, 256 and 512 texels per em, each serving up to 2× magnification, picked from the on-screen em size with 10% hysteresis; a glyph missing at its tier draws from the highest lower tier that has it.
- **`msdf/`** is the prototype's msdfgen worker on the pool's protocol: an `msdf` job generates a batch of glyphs of one face at one tier. Each glyph's bounds are snapped outwards to whole texels and the shape is translated onto them, so quads are placed with no sub-texel error. The field encodes `0.5 + d / 16` (d in texels, positive inside) with 8 texels of padding, as in the prototype. The raster fallback computes a single-channel true distance field from the font's outline with the same encoding, so one shader draws both; it serves every job when there is no msdfgen loader, the module fails to load, or msdfgen cannot read the font. `GlyphSource` coalesces the glyph requests of one tick per face and tier into batches (the prototype's 50 ms debounce needed timers the core does not have), retries a failed batch once with the fallback, and gives up on glyphs whose fallback fails too, so a bad font cannot loop. A glyph the atlas rejects for lack of budget is not requested again for the next 2, 4, 8, … up to 64 ticks that ask for it (about a second of frames), counted once per tick however many occurrences ask, so an over-full atlas does not regenerate it every frame.
- **`renderer/`** draws glyph quads through `GpuBackend` with one WGSL source (`msdf-text.wgsl`): instanced unit quads, the median of three channels for MSDF pages or the red channel for R8 pages (a page uniform says which), msdfgen's screen-space antialiasing (the field's range in screen pixels from `fwidth` of the texture coordinates: sharper under zoom than the prototype's `fwidth` of the field, which also blurred where channels disagree), premultiplied output. `TextRenderer.prepare()` mirrors atlas pages onto textures and applies queued uploads before any pass (writes are rejected inside one); `draw(pass, cameraUniform, range)` records one instanced draw by `firstInstance` range. `TEXT_PIPELINE_DESCRIPTOR` and the instance layout are plain data for the scene graph to register the pass; its camera block is the engine's (`clip = world × scale + offset` at binding 0), so `draw` takes the scene's `CameraUniform.buffer` as it is; registering it will need a bind group per atlas page, which `ScenePipelineSpec` does not describe yet.

**The scene's text pass** (`src/text/scene/`) puts text on the board through the scene graph, so text is z-ordered with everything else and drawn by both backends in the worker host. `TEXT_PASS` is a `ScenePassFactory` in `createStandardScenePasses`, built per renderer with the host's `TextPassResources`: the fonts `EngineRuntimeExtensions.createTextResources` makes and the runtime pool's `submit` (without fonts it draws nothing). Each text object gets one record per character that is neither a space nor a newline (a pure function of the object, as the z-order segments need); `TextRecordCounts` retains an exact-text count per ID with allocated records, avoiding placement allocation and repeated Unicode scans during translation, and releases it with pass slots or renderer destruction; `prepare` fills record `i` from glyph `i` of the object's `orderedGlyphQuads`, in the object's frame, and the record carries the object's world origin and rotation, so `scene-text.wgsl` turns text with its object (the msdf-text shader's fragment stage, with rotation in the vertex stage). `pageOf` is the page group of the glyph's atlas page: `TextAtlasPages` gives each live page the lowest free slot, eight slots make a group bound together, and the record carries the page's index in the group, so the draw list splits by group, not page, and texts whose glyphs scatter over up to eight pages draw in one draw per z-segment (the frame titles keep a page per group). A group whose pages fill only its first 1, 2 or 4 slots (`TextAtlasPages.slotsOf`) draws with a generated variant of the shader whose page switch covers just those (`scene-text-pages-N`, `scripts/text-page-shader.ts`). Standard hosts resolve the glyph inputs once for each synchronous object rewrite (`record-batches`, `text-record-batch`), then preserve each zeroed record, exact float32 placement, slot and page write. The capability is private to `EngineAssembly`; direct/custom renderers and replaced `prepare`/`pageOf` callbacks keep the ordinary per-record path. The temporary writer never survives its rewrite, so layout, glyph and LOD invalidation still use the existing resource lifecycle. Layouts come from a per-object cache (`TextLayoutCache`) keyed by the text, runs, wrapping width, alignment, a sticky note's fit height and the loaded faces. Identical pending and completed layouts share work within that renderer (`SharedTextLayouts`), bounded to 512 entries and 256 Ki source/key code units; font-library revisions invalidate reuse, oversized labels bypass it, and failures retry. Forgetting one object does not cancel another object's shared job. Low-zoom bars also share immutable quads for the same layout and local origin (`SharedGreekQuads`), with only the latest origin retained per weakly held layout; atlas-backed glyphs retain their ordinary readiness and eviction checks. Layouts are asked of the pool at `visible` priority; the previous layout draws until the new one lands, which names the object for a rewrite (`Scene.rewriteRecords`). Two stages bracket `collectChanges`: `textBegin` starts the atlas frame (glyphs used from then on are safe from eviction), takes the frame's scale (zoom × dpr) and notices new faces; `textRefresh` rewrites the text whose layout landed, whose glyphs landed (only text still waiting for one) or were evicted (all text), and the drawn text whose tier changes with the zoom: a zoom queues tier checks only when it takes a font size in use across a tier edge (`mayChangeTier`, `TextTierChecks`), and queued text is checked when the frame draws it (the level of detail's visible set), so a zoom frame costs O(font sizes), not O(text objects) (the walk over every text entry cost about 3.5 ms a zoom frame on the 50k board); then it mirrors the atlas onto page textures (`TextAtlasPages`, a blank page for records whose glyph is not in yet). The atlas's resident bytes go to the frame statistics' ledger through `ScenePass.reportMemory`. `textPlacementOf` is the per-type hook: text objects lay out from their local origin, wrapping at their width unless auto-width, placed vertically in their stored height; a sticky note's text (`noteTextPlacement`) lays out inside the note's 16-unit padding (`NOTE_PADDING`), wrapping at its width less the padding (`noteWrapWidth`), in the note's alignment, and short text sits in the padded box where its `verticalAlign` puts it (the sticky tool makes notes centred both ways); its text is fitted to the note (`fitNoteText` in the layout job), and the note grows (`noteHeightFor`, measured by the page's editor) only when its text overflows at the 8 px floor. `textOriginOf` is where the laid-out text starts in the object's frame, shared by the pass and the page's editor. A shape's label (`shapeLabelPlacement`) lays out centred both ways in the rectangle inscribed in its kind (`shapeLabelBox`): a rectangle's box less what its rounded corners cut off, the largest rectangle in an ellipse (1/√2 of each axis), and for a diamond, polygon or star the 2:1 rectangle in its inscribed circle, stretched as the shape is, less a padding of 8 units (at most 15% of the box's shorter side); a label taller than its box runs on below it. A label has no size of its own, so the shape never grows with it. The page's text tool lays text out with the same faces through `layoutTextNow`, so the caret the page draws and the glyphs the worker draws agree.

A job-worker script that ships msdfgen registers it alongside the handlers: `serveWorkerEntry(self, createWorkerEntry({ ...createProductionJobHandlers(), msdf: createMsdfJobHandler({ loadMsdfgen: () => createMsdfgenModule({ locateFile: () => wasmUrl }) }) }))`, with the loader and wasm from `@zappar/msdf-generator`'s `dist/` (as `tooling/golden/harness/vite.config.ts` aliases them).

Level of detail (`TEXT_LEVEL_OF_DETAIL`): text whose tallest line is under 4 device pixels draws as greek bars (`greekQuads`: its records rewritten from the cached layout, no glyph requested), and under 2.5 pixels it is left out; bars stay written while text is hidden, so it shows again without a rewrite. Not yet: there is no complex-script shaping or bidi (one glyph per codepoint, as in the prototype); a character a face does not map advances by its `.notdef` width and draws nothing; CFF-flavoured fonts get MSDF glyphs but no raster fallback (the fallback reads TrueType outlines only); the editing operations on runs (`spliceRuns`, `applyStyle`, …) belong to the text tool in `@canvas/tools`, not the engine.

**Images and the texture manager** (the prototype had no images). The image pass's `images` stage runs after `collectChanges` and before the upload: the `TextureManager` finds the frame's candidates in an R-tree of its own (`ImageIndex`: `visible` on screen, `near` in the padded viewport the culler draws, `prefetch` in the padded viewport moved along the pan), plans (`ImagePlanner`: each image's smallest level, its level from the on-screen size × DPR with hysteresis (`LevelPicks`), lowered where the chosen levels would not fit 80% of the `textures` budget together, and, for a visible image zoomed past its largest level, its visible tiles, with the same hysteresis on the tile level and its largest level wanted only until those tiles are resident), requests what is missing through `LevelLoader` (fetch through the `AssetSource`, then a `decode` job on the pool, at most six at once, most urgent first, re-prioritised and cancelled as the view moves: a cancelled fetch is aborted and its slot given to the next load at once, and a re-request joins or replaces a fetch, never duplicates it; client levels of one asset share one fetch and one decode of the original, and a client level asked for while that original is still being fetched joins the fetch, also when the batch it started with was partly cancelled; the fetch is aborted only when no level of it is wanted any more, and once its bytes are handed to the decode job a later request fetches again; a client fetch left with no level is kept until the next pump, so cancelling one level and asking for another of the asset in the same frame, as a zoom does, joins the fetch), uploads what arrived (`LevelUploads` over `UploadQueue`: 16 MiB a frame, smallest first; `TextureResidency`: large levels get textures of their own, levels and tiles of at most 256 px go onto 2048 px atlas pages; an upload past the budget evicts idle levels larger-first then least recently used, or waits, and evicts nothing when even every idle level would not make room; a new version of a resident key, the server's for the client's, replaces the old one only once placed: a level that fits the rectangle the old atlas entry holds is written into it in place, evicting and refusing nothing; any other replaces it after room is made only when the upload is certain to fit (the old entry's own texture stops counting against the budget, its atlas page is never counted as freeable), and a refused one evicts nothing and leaves the resident level, its texture and the byte accounting as they were, and is dropped from the upload queue rather than retried each frame. Replacing an own texture holds the new texture beside the old one for one synchronous call, so the GPU can hold the budget plus the replaced texture, at most one 4096 px level, about 64 MiB, then; `FrameStats` memory samples are taken at frame ends and never see it, but the ledger is reported while both exist), and rebinds the images whose plan or asset changed (`BindingTable`), rewriting their records (`Scene.rewriteRecords`). A still camera with no event plans nothing, and neither does a pan at an unchanged zoom while the view stays inside the padded search, the index is unchanged, the images ahead of the pan are the same (`CandidateFinder.pan`) and no candidate may show tiles (a tiled image needed past its largest level, at any priority: `ImagePlanner.hasTileCandidates`, since a near one gets its tiles only from a plan that sees it on screen): priorities change in place and the visible images are counted again (`ImageDrawTally`); loads keep the priority of the last plan until the camera rests, and the first still frame after such a pan plans once, so a rest ends in the picks of settling at that camera directly (a seeded property test). The images ahead of the pan stay the same while a drag's speed varies: the prefetch region's reach has hysteresis (`prefetchReach`: the lookahead, velocity × 400 ms, rounded up to 1/16 of the padded view times a power of two, at most two views, and kept until the lookahead passes it, falls below a quarter of it or turns; a pan slower than the shortest reach prefetches nothing, the padding already covers it), and a pan whose reach is unchanged searches nothing. Over a board four views wide, a drag of 2 to 6 world units a frame plans on 7 of 400 frames (304 before the reach had hysteresis): when the view leaves the padded search or the reach moves. The planner, the candidate finder and the tally keep their objects and scratch arrays between frames, so a frame allocates nothing per image (fitting an over-budget plan allocates per asset). Image objects `use` and `release` their assets in the catalogue; one no object uses stops being followed at the next sweep. Its smallest CPU copy and metadata remain within the existing 64 MiB copy cap, so undo can reuse a ready image immediately; reuse describes it again and resumes following it. Once that cached copy is evicted, the unused metadata goes with it. A `failed` active asset is described again when an object using it is seen again. The texture manager tells the source which assets the visible images drawn from their placeholder wait for, and which the near and prefetch ones wait for (`VisiblePendingReport`, only when either set changes), and which pending asset's object changed (`AssetCatalogue.revive`), so the app's follower polls the visible ones first, its record reads describe the visible then the near ones before the rest of the board, and it follows again what it gave up on.

- **Never blank.** The smallest level of every visible or near image is always wanted and never evicted, and its pixels are kept on the CPU once decoded (`AssetCatalogue`): an image that scrolls back in uploads it in the same frame, and a renderer rebuilt after a lost device uploads them all under the per-frame byte cap, images on screen first (a board with more than 16 MiB of smallest levels takes a few frames, and its images show their colour meanwhile). Levels are premultiplied in the job worker (`premultiplyAlpha`), so filtering never darkens transparent edges; the image shader mixes premultiplied colours. Until an asset's smallest level exists its images draw their average colour (grey before the description); after that a visible image drawn without a texture counts in `FrameStats.blankImages`, which the benchmark and the scenario test require to be 0. "Ready" is sticky (`CatalogueEntry.hasBeenReady`), so a CPU copy dropped by the 64 MiB copy cap cannot hide a blank. Visible images drawn from their placeholder because nothing of their asset ever loaded (not described, failed, or no level yet) count apart, in `FrameStats.placeholderImages`, beside `FrameStats.visibleImages`; the memory benchmark's floor bounds their share once loads settle.
- **Records and pages.** An image has one record, or, when its original is over 4096 px (the tile pyramid's threshold, a pure function of the object as the z-order segments need), 512 tile records. The binding (`ImageBinding`) lists non-overlapping parts: the whole crop from the shown level, or one part per visible tile, drawn from the tile once resident and from the shown level until then, so a translucent image blends once and nothing overlaps. Samples are clamped half a texel inside a part's page rectangle, so atlas neighbours never bleed and entries need no gutter. Records past the parts take the last part's page, so empty tile records add no draw.
- **Z order across pages.** A z-order segment draws a paged pass page by page, which would put a later image on a lower page (an atlas page made early) under an earlier one on a higher page. The image pass sets `isPaintOrderedAcrossPages`, so an object whose pages come before a page already used in its segment starts a new split (`assignSegments`), and a new segment only where its box meets a record on a higher page (`SegmentPageOrder`; without boxes, always); otherwise the split joins its segment by the usual overlap rule and the plan rests on boxes, which the moved-object check then covers (a moved image landing on an earlier one on a higher page breaks it). 1,000 opaque images on pages uncorrelated with paint order plan 3 draw entries on 3 pages (684 before) and 8 on 8 (872) when apart on a grid, 64 and 183 when scattered and overlapping. Text keeps drawing page by page. Images at any opacity above 0 are flagged (a faded image still paints over the text or line below it). Images are boxes in the culler's index like any object, so with sticky notes (the SDF shape pass draws before the image pass) a note over an image starts a segment of its own where it covers one, and an image over a note draws after it in the note's segment; with lines (the path pass draws after the image pass) a line over an image draws after it in its segment, and an opaque image over a line starts a segment where it covers one (`image-note-order.test.ts`).
- **Budget and failures.** `budgetForDevice` sets the caps (the host describes the device: `EngineHostOptions.device`), worked out again with the catalogue's levels for a backend rebuilt after a lost device (`EngineFoundation.adoptBackend`), whose texture limit may differ. An allocation that throws lowers the manager's budget by a quarter (down to a quarter of the cap) and evicts every idle level, so every image drops to lower levels and rebuilds. The ledger's `textures` bytes are whole textures and atlas pages, so `memory.textures.peakBytes` is the most the GPU held at the end of a frame (a replacement's momentary second texture, above, is inside one call and is never sampled).
- **Internal image preview evidence.** `AssetSource.immutableContentIdentity?` is an explicit trusted adapter attestation: its token must never identify different original content or changed rendition bytes for the same source selector/decoder format. Original SHA alone is insufficient. Missing, withdrawn, empty or throwing capabilities refuse proof; successful descriptions and hexadecimal IDs alone prove nothing. The current app HTTP/linked adapters and worker channel supply no such attestation; image preview activation remains disabled. Unique admission objects reject stale completion generations. Strong provenance retains only tracked assets and active requests/queued uploads; completion, cancellation, last-object removal and destruction release it, while live resident proofs use weak ownership. Built-in image evidence records the actual target frame's object, crop, transform, selected level/tile plan, binding and renderer-local resident allocation identities. Placeholders, lower-resolution fallback, pending work, unproven cached pixels, failed uploads and changed source identities refuse. This internal contributor still requires the host's successful full-frame and scene/camera barriers; a host certificate requires every installed contributor, a reusable exact image-plan key, unchanged scene/camera and no pending arrivals. Only image-free persistence and warm startup are connected; source boards containing images refuse publication.
- **Decoding off the rendering thread.** The `decode` job decodes with `createImageBitmap` in a job worker of the engine's pool (the app's `job-worker.ts` passes `createBrowserBitmapFactory(self)`), resizes to each long edge there and transfers the pixels. Without job workers the pool decodes nothing unless given `EngineImageSupport.decodeFallback` (tests and golden scenes pass `createDecodeJobHandler()`; the runtime drains its shared pool after the frame through `EngineJobs.runQueued`, while standalone renderers may expose `drainMainThread` for the image stage's 4 ms slice); images then keep their placeholder or the levels they have, `TextureManagerStats.decoderMissingFailures` counts the loads, and the engine reports one fault (`onFault`). A main-thread decode fallback for browsers without job workers is owed.
- **Animated GIFs.** A GIF image (`image/gif`, not tiled) on screen at 64 CSS px or more plays, per client, writing nothing to the document (`GifPlayback`, owned by the texture manager): its original is fetched (`AssetSource.fetchOriginal`) and a `frames` job decodes its frames in a job worker with the engine's own GIF decoder (`decodeGifFrames`, chosen over WebCodecs' `ImageDecoder` so every browser composes, times and scales frames alike and golden scenes are deterministic), at most 512 px on the long edge and 16 MiB (8 MiB on a mobile profile) per GIF. The decoded frames are counted under `textures` (`IMAGE_ANIMATION_OWNER`) and held back from the residency's budget (`LevelUploads.reserve`, which evicts idle levels, larger and older first, to make the room, never needed ones), at most a quarter of it; a needed level that does not fit makes the playback give its frames back (`onPressure`), paused GIFs first. Only the current frame is uploaded, into a slot texture (`<asset>|A`, in the atlas up to 256 px, else a texture of its own rewritten in place) that the GIF's images on screen at 64 px or more draw in place of their level (`BindingTable` through `GifPlayback.shownFor`, decided per image: one decode and one slot serve every such image of the asset, and its smaller or off-screen images keep the still level), and only while that level is resident: a GIF off screen, under 64 px, still loading, or whose frames were dropped draws its still level, the server's first frame, and decodes nothing. Frames follow the file's delays (10 ms or less shows for 100 ms) and loop count (n plays n + 1 times, 0 forever, none once) on the frame clock (`animationMomentAt`); a one-shot timer (`FrameDeadline`, injectable as `TextureManagerOptions.frameTimer`) calls `requestFrame` when the next frame is due, so the runtime needed no change and frames that advance no GIF upload nothing. At most two GIFs (decoded assets, not images) play on a mobile profile, the ones playing first. No play/pause, reduced motion, or other animated formats.
- **The original as the top level.** For an untiled image the original is its top level (`showableLevels`): when the on-screen need exceeds the largest server level, the original is fetched (`fetchOriginal`) and decoded at its own size in a job worker, never on the rendering thread, so the image shows full resolution. Only for an original whose long edge is at most the device's `maxTextureSize` and 4096 px (`ORIGINAL_LEVEL_MAX_LONG_EDGE_PX`); it is an ordinary level under the budget, evicted when idle and refused when it does not fit, and then the largest server level stays shown (an upload evicts nothing when even evicting every idle level would not make room). While any level an image wants is not resident (loading, or a refused original waiting in the upload queue), the fallback level stays wanted and needed, so another asset's upload cannot evict it; the upload of the wanted level itself may (`LevelUploads`: to an upload, its own asset's levels below it, other than the smallest, are idle), inside the same upload that makes it resident, so a level upgrade under budget pressure still happens and the image is never blank. When the wanted level cannot fit even without them, nothing is evicted and the lower level stays shown. The fallback normally uses the largest resident level below the target. When only the smallest is below, it prefers the smallest resident level above, up to 4× the target, so a small copy can reuse a larger copy's texture without excessive minification shimmer. If no lower level exists, it draws the resident level above regardless of ratio; the cap never makes an image blank. A tiled image never decodes its original: it shows only the levels the server made, then its tiles, and its placeholder until the server lists a level. The client also decodes the original of an untiled image in a job worker to make the levels the server has not made yet.
- **Failures.** A description or level that fails (a 404 while an upload's asset is not linked to the board yet, a network error, a decode that fails) is retried after 0.5, 1, 2 and 4 s (`RetrySchedule`), never once per frame, and then left: the image keeps its placeholder or the level it shows until the asset's description changes. Nothing is logged per failure. Fixture images (`encodeFixtureImage`) are a few dozen bytes the job renders at any size, so the fixture source costs the rendering thread nothing.
- **Review rulings.** Accepted: after a device loss, a board with more than 16 MiB of smallest levels shows some images' colour for a few frames while the smallest levels are re-uploaded under the per-frame byte cap, and those frames count in `FrameStats.blankImages`: the metric stays honest rather than exempting them. Undo-after-delete reuse is covered by below. Deferred to follow-ups, not done here: mipmaps (minifying up to about 5× between levels shows moiré; a mip chain costs about a third more memory); detecting GPU out-of-memory (`pushErrorScope('out-of-memory')`, `gl.getError()`), where today only a throwing `createTexture` counts.

### Undo thumbnails and board possession

`AssetCatalogue` retains smallest decoded copies after the last image releases an asset, under
its existing shared 64 MiB CPU-copy budget. Unused copies are evicted before referenced copies,
with least-recently-used order within each group; restoring a copy updates that order. A newest
referenced copy retains the prior single-copy exception for a configured cap smaller than that
copy; unused insertions cannot displace it. Normal
undo reuses resident levels without a fetch, while GPU-loss undo starts with the CPU thumbnail
and fetches the requested larger level. Both re-describe the restored asset once. On the first
failed restored description, the catalogue drops the copy and its old metadata/readiness and
notifies bindings immediately: the image becomes a placeholder, not a blank image, throughout
remaining retries. This also handles transient failures conservatively.

The cache key is the asset ID **within one catalogue**, not a global asset-ID cache. A catalogue
belongs to an engine and its fixed `AssetSource`; it survives GPU recovery, not a board change.
The site keys `BoardPage` by `boardId` (`site/site-app.tsx`), so another board gets another canvas
and host. `holdEngineHost` only leases the same canvas across React Strict Mode remounts; the
old canvas release destroys its host, and `EngineFoundation.destroy` clears its catalogue and
closes image support. An embedding application must likewise create a new host/catalogue when
switching board or possession scope; changing a source's board underneath an existing catalogue
is unsupported. A separate catalogue cannot restore an asset from the first catalogue's cache.
Cross-board paste still requires the destination's link/possession check before creating images.

Focused evidence lives in `texture-manager-undo.test.ts` (settled fetch/describe counts and first
revalidation failure, with and without GPU loss) and `asset-catalogue-cache.test.ts` (eviction,
restore recency, cross-catalogue isolation, callback identity and destruction).

The default culler updates membership by querying the old/new padded rectangle difference
strips, deduplicating candidates and checking their full current bounds. Indexed box changes
update their IDs directly. Both views containing the board need no new search.
`queryCount` counts logical visibility refreshes, which may use several strip searches or
none. `visibilityFor` retains one change record: source identity, revision, previous revision,
entered/left IDs and borrowed current membership. Repeated reads share it; consumers missing
a revision reset from membership. The membership set is valid only at its current revision.
LOD owns a separate membership set, applies consecutive deltas and evaluates entering IDs.
Entering, pending and crossed-size paths share the last evaluated pixel size, so duplicate
evaluation cannot repeat the same form and band-history work;
its `visibleCount` lets text-tier checks avoid materializing the legacy ID array. Custom
all-visible and legacy-array paths remain supported. Partial-view slot ranges retain independent old ownership and patch only changed IDs in
sparse ordered intervals. Consecutive slots within an object update as one interval, while
old ownership is removed before any replacement is inserted. Local predecessor/successor
checks preserve the 16-record gap
bridge rule. `rangeChangeOf(passName)` exposes actual added/removed drawn slots, including
offscreen bridge slots; a missed revision or changed source requires a reset. Page partitions
read only added slots; removed intervals are subtracted from each page without page reads.
Existing partial-view slot caches stay current through a whole-board view, avoiding their full
reconstruction on return. Initial whole-board drawing does not construct them; whole-board output
still uses the pure reference and exposes no precise range delta.
Page-table identity/revision changes still rebuild the affected pass safely.
Image candidate pans retain the same inclusive/strict viewport intersection proof used by path
preparation. Only successful same-candidate pans with unchanged priority classification skip
image recounting; index/query changes clear the proof and resource changes still reassess bindings.

LOD's `updateRevision` detects missed changed-ID sets. Missed updates, whole-board mode
transitions and broad whole-board hidden changes use the safe reference rebuild. Interval
array movement and output materialization still cost the number of affected/output runs;
this is not a worst-case O(delta) claim. Segment planning remains unchanged at this stage.

Settled path preparation copies eight visibility thresholds for its fixed candidates. Visible
boxes retain inclusive intersections; hidden boxes retain a strict separating axis. This allows
clipped candidates to remain cached during camera motion. Changed ranges, invalid bounds and
all document, instance, LOD, bucket, mesh and pending-work guards still force preparation.

Camera-only path preparation retains the exact candidate boxes when document records, draw ranges,
LOD forms and the flatten bucket are unchanged. A viewport crossing updates only the entering and
leaving meshes; `PathPreparationCache.reuseCandidates` checks those guards and `MeshCache.unpin`
releases departed objects without touching the active meshes. The drawer compares its commands
with forced full preparation across viewport boundaries. This optimization does not establish the
1 ms target without the hosted camera benchmark.

Image zooms can reuse a residency plan while `LevelPicks.canReuseScale` proves every image stays
strictly within its level's hysteresis band, with a conservative floating-point margin. The
intersection also stops before tiled images require tiles. `ImagePlanner.canReuseScale` exposes
that proof to `TextureManager`; candidate changes, asset events, record changes, existing tile
candidates and the first resting frame still force planning. Tests compare the interval with the
original level-picking oracle across zooms, pixel ratios and cropped images. The internal
`residentLevelBelow` helper reads the largest resident fallback below a requested level.

The page host view coalesces source changes once per animation frame before encoding. Its
`TranslationChangeEncoder` keeps the last sent immutable values and emits a compact local
translation only when every other field is unchanged and floating-point addition reconstructs
the new coordinates exactly. The receiving mirror applies messages in order, retaining intermediate numeric positions and
cloning each translated object once after the batch. It evaluates each addition separately to
preserve rounding; full-object replacements and deletion discard pending positions. Drawable
checks see the final combined state once per frame. Commit metadata,
restyles, reparenting, unequal movement and newly created objects retain full object payloads.

Retained root-leaf moves (`scene/retained-scene-move.ts`) keep ordinary geometry records and bind
absolute float32 placements through a load-only texture plus one table index per instance.
`ScenePass.pipelineSpec.moveShader` opts in; custom passes without a proof use full preparation,
even when they initially draw zero records. `movePlacement` preserves record-specific CPU
origin arithmetic (notably sticky shadows). Pending text/image resource work follows current
targets; ordinary changes and session boundaries restore all retained objects before clearing
indices. `host/retained-move-command.ts` validates ordered session messages, and the mirror keeps
exact absolute doubles for fallback, replay and read barriers. The retained-move golden probe
compares pixels against ordinary rendering on both GPU backends without baseline replacement.
Path preparation also tracks `TransformTable.revision`: placement-only changes invalidate its
visibility witness and prepared meshes even when ordinary instance bytes remain unchanged.
Inactive session cleanup leaves camera-only path preparation reusable.

Retained host updates carry an engine-owned root-placement proof (`scene/root-move-changes.ts`).
Only accepted update commands receive it; session boundaries, ordinary edits, filtered gate
wrappers and mixed coalescing use ordinary checks. Passes declaring `isRootMoveOrderStable`
prove that x/y cannot change `recordCount` or `isOccluder`; a custom pass that changes either
function must reconsider that opt-in. Z-order still mirrors objects and updated IDs; unproven
passes retain their normal comparisons.

The retained host mirror selects canonical literal copiers once per begin command, only for exact
ordered own enumerable data fields on `Object.prototype` objects. Unknown, new or accessor
fields use generic copying, preserving immutable object snapshots.

During host-owned root movement, `install-root-move-batches.ts` shares one current object array
only inside synchronous collection. It is installed before external overlay wrappers; custom
`SceneRenderer` instances do not opt in. Ordinary live source reads remain unchanged. Scene
and spatial consumers preflight every member's identity, root parent and absence of children
before skipping repeated hierarchy walks. Mixed changes and failed preflight use the ordinary
path. Image passes also refuse snapshots while an asset is unknown, pending or failed, so
synchronous asset callbacks retain ordinary live-source behavior. The scope is cleared even
when collection throws. Exact placement, drawing-bound unions,
spatial event snapshots and post-update observer ordering remain unchanged.

During an engine-owned root-move collection, `PathRegistry` reuses mesh metadata only while the path’s current record slots match its saved slots. It still replaces the tracked path and each owner with fresh snapshots containing the current object. A refused member resumes ordinary live reads for the remainder of the batch, preserving removal-hook effects; ordinary and custom collections keep their existing reads.

`ImageIndex` publishes tracked objects and its version immediately. It copies changed bounds into a pending batch and flushes that batch through `RTree.updateMany` before every synchronous search. Forgetting an image removes both pending and indexed bounds; invalid bounds still throw during `track`. Returned tracked bounds cannot mutate the queued tree update.

### internal resource lease groundwork

`memory/resource-lease.ts` is an internal GPU reservation primitive, not a package-root
export or an activated preview path. One admission authority must own the leases for a backend.
It checks a complete preview/live overlap plan against unchanged device categories and total,
keeps outstanding reservations separate from actual ledger allocations, and rechecks unrelated
ledger growth before allocation. Each lease owns unique allocation accounts; adopting a handle
adds a holder without another allocation or ledger charge. Dropping its last holder waits for
GPU completion before destruction and returning capacity. Release and live rollback are
idempotent and cannot release another attempt's resources.

This groundwork allocates only buffers. It does not enforce immutable writes through exposed
backend handles, allocate textures or a hidden live output, validate adoption identities, provide
bounded scene residency, or implement CPU admission. Those remain integration contracts in
the bounded resource design. In particular,
a rejected or throwing completion fence conservatively retains the buffer and its reservation
indefinitely; device-loss retirement integration is still required. It is not safe to infer
successful destruction from a failed fence. None of this activates compiled replay or establishes
the 500 ms first-paint criterion.
